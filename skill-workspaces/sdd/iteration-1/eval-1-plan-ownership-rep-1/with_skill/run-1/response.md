# План реализации

Основание: `specs/orders/spec.md`, `design.md`, согласование `USER-documents` и команда `USER-plan` из `review/decisions.md`. Актуальное документное ревью завершено без находок.

Каждый из двух AC закреплен за одной задачей. Тестовая инфраструктура отсутствует; ее подготовка включена в задачи. Указанные места тестов — планируемые каталоги относительно корня проекта.

### Возвращать прежний заказ при повторе ключа

```yaml
sdd_record: task
id: TASK-reuse-order
number: 1
covers: [AC-reuse-order]
depends_on: []
cannot_parallel_with: []
status: pending
verification:
  - criteria: [AC-reuse-order]
    test_description: >-
      Выполнить POST /orders, сохранить полученный order_id и убедиться,
      что связь с Idempotency-Key сохранена. Повторить запрос с тем же
      ключом и тем же содержимым через HTTP-маршрут. Проверить, что
      возвращен прежний order_id, а число сохраненных заказов не увеличилось.
    location: tests/orders/idempotency/
    run:
      setup_required: >-
        Внутри этой задачи настроить тестовый раннер согласно стеку проекта,
        зависимости, HTTP-клиент и изолированное хранилище с очисткой между
        тестами. Создать тест в указанном каталоге, определить и записать
        в tests/README.md точную команду локального запуска и необходимые
        настройки окружения. Выполнить тест и зафиксировать результат.
```

Реализовать сохранение связи `Idempotency-Key` с `order_id` согласно `DEC-preserve-key-map`. При повторном запросе возвращать существующий заказ, не проходя ветку создания нового.

В рамках этой же задачи подготовить общие фикстуры приложения, клиента и хранилища. Проверка должна проходить через маршрут и обработчик до хранилища, чтобы подтверждать отсутствие нового заказа. Подготовку окружения, реализацию и успешное выполнение проверки завершить до перевода задачи в `done`.

### Заменить retry на ответ HTTP 410

```yaml
sdd_record: task
id: TASK-remove-retry
number: 2
covers: [AC-retry-gone]
depends_on: [TASK-reuse-order]
cannot_parallel_with: []
status: pending
verification:
  - criteria: [AC-retry-gone]
    test_description: >-
      Подготовить существующий заказ и вызвать POST /orders/{id}/retry
      через HTTP-маршрут. Проверить ответ HTTP 410 и отсутствие вызова
      механизма повторного исполнения заказа, включая постановку задания
      на исполнение, если она используется.
    location: tests/orders/retry-gone/
    run:
      setup_required: >-
        Внутри этой задачи подключить тест к раннеру и общим фикстурам
        из TASK-reuse-order. Добавить наблюдение за вызовами механизма
        исполнения и необходимые фикстуры заказа. Записать в tests/README.md
        точную команду запуска этого теста и общего набора orders.
        Выполнить проверку HTTP 410, отсутствия повторного исполнения
        и регрессионный запуск теста повторного ключа; зафиксировать результаты.
```

Заменить обработчик `POST /orders/{id}/retry` на tombstone, возвращающий HTTP 410. Удалить из этого пути запуск повторного исполнения заказа. Сохранить регистрацию маршрута, необходимую для ответа 410.

Зависимость от `TASK-reuse-order` нужна для использования подготовленного тестового окружения. Обработчики и общие тестовые файлы изменяются последовательно; дополнительное ограничение параллельности не требуется. Регрессионный запуск использует уже созданный тест и не переносит владение `AC-reuse-order`.
