## TASK-1 — Подготовить локальный запуск проверок

- [ ] Подготовить минимальную тестовую инфраструктуру для `AC-reuse-order` и `AC-retry-gone`: запуск приложения, изолированное хранилище заказов и очистку данных между проверками.
- [ ] Обеспечить наблюдаемость числа созданных заказов и вызовов повторного исполнения, чтобы проверять отсутствие побочных эффектов.
- [ ] Зафиксировать необходимые зависимости, подготовку окружения и точные команды запуска обеих проверок по отдельности и вместе.

**Зависимости:** нет.  
**Результат:** воспроизводимый локальный запуск; проверки обращаются к обработчикам HTTP и позволяют проверить состояние хранилища и вызовы исполнения. Отсутствующая тестовая инфраструктура создается в рамках этой задачи.

## TASK-2 — Возвращать существующий заказ при повторе ключа

**Трассировка:** `REQ-reuse-order` → `AC-reuse-order`; решение `DEC-preserve-key-map`.  
**Зависимости:** TASK-1.

- [ ] Добавить проверку: выполнить `POST /orders`, сохранить полученный `order_id`, затем повторить тот же запрос с тем же `Idempotency-Key`.
- [ ] Проверить, что повтор возвращает прежний `order_id`, а число заказов после повторного запроса не увеличивается.
- [ ] Реализовать сохранение связи `Idempotency-Key` с `order_id` и возврат существующей записи при повторе согласно `design.md`.
- [ ] Запустить проверку `AC-reuse-order` подготовленной командой и зафиксировать результат.

**Критерий завершения:** повтор уже сохраненного ключа с тем же запросом возвращает прежний заказ без создания нового; проверка проходит.

## TASK-3 — Заменить retry на ответ HTTP 410

**Трассировка:** `REQ-remove-retry` → `AC-retry-gone`; удаляемое поведение — `docs/orders.md`, раздел `Retry endpoint`.  
**Зависимости:** TASK-1.

- [ ] Добавить проверку вызова `POST /orders/{id}/retry` для подготовленного заказа.
- [ ] Проверить ответ HTTP 410 и отсутствие вызова повторного исполнения заказа.
- [ ] Заменить прежнюю логику retry обработчиком `410 tombstone` согласно `design.md`, исключив запуск повторного исполнения.
- [ ] Запустить проверку `AC-retry-gone` подготовленной командой и зафиксировать результат.

**Критерий завершения:** endpoint отвечает HTTP 410 и не запускает повторное исполнение; проверка проходит.
