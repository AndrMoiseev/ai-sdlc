# Контрольный запуск до написания скилла

Исполнитель: чистый native-субагент `/root/baseline_sdd`, fork_turns=none.
Каталог скиллов унаследован от среды, но кандидата sdd в нем нет; исполнитель подтвердил это. Файловые инструменты не требовались: вход полностью передан в задании. Это проверка формата на синтетическом сценарии, не прогон процесса в проекте.

## Задание

Составить краткий машинно-проверяемый Markdown-план идемпотентного создания заказа: повтор ключа возвращает прежний заказ, удаляемый retry endpoint возвращает 410. Указать критерии с условиями и результатом, дизайн, стабильные ID задач, зависимости, тесты и команды. Формат извне не задавался.

## Наблюдаемый результат

Исполнитель выбрал REQ-001, AC-001, AC-002, AC-003, DES-001, DES-002, TASK-001..003. Метаданные записаны списками Markdown, без YAML/frontmatter. TASK-001 покрывает AC-001/002; TASK-002 покрывает AC-003; TASK-003 «Проверить совместную работу» повторно покрывает AC-001/002/003. Добавлены предположения о Python, маршрутах и ответе 409.

Дословные фрагменты ответа:

> Навыки с именами `sdd` или `sdd-*` в каталоге отсутствуют. Другие навыки не использовались.

> ### TASK-003 — Проверить совместную работу
> - **depends_on:** `[TASK-001, TASK-002]`
> - **work:** Добавить интеграционный сценарий через HTTP с настоящим тестовым хранилищем.
> - **acceptance:** `[AC-001, AC-002, AC-003]`

## Вывод для реализации

Обычный агент способен составить содержательный план, но не воспроизводит специфический контракт sdd: смысловые ID, YAML-записи и ровно одного владельца AC. Пакет нужен для этого контракта. Наблюдение не доказывает, что агент всегда допускает ошибку, и не служит основанием для запрета интеграционных тестов: они входят в задачу владельца критерия.

Полный tool transcript и счетчик токенов native-среда не предоставила; не оценивались по длине текста. Эта запись не является сравнительным benchmark.
