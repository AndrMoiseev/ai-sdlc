# Дизайн независимой части CSV

## Контекст, цели и исключения

См. [proposal](proposal.md) и [контракт CSV](specs/delivery-csv/spec.md). Исходники, тесты и конфигурация продукта не предоставлены. Документ описывает границу черновика, а не существующую архитектуру.

## Модули и контракты

Предлагаемая граница: формирование CSV принимает данные отчёта и выдаёт три согласованные колонки. Источник записей и механизм назначения остаются за этой границей до выбора поведения. Генерация CSV сама по себе не должна становиться основанием для включения автоматического назначения.

Конкретные компоненты, API, хранение, расписание запуска и обработка ошибок пока не выбраны. Поля не дополняются вымышленными данными.

## Термины

`delivery_id`, `overdue_minutes`, `responsible` — имена колонок из исходного описания. Точные типы, правила вычисления и представление исполнителя требуют уточнения.

## Альтернативы и последствия

Менеджер предлагает автоматическое назначение либо принятие риска; оба варианта остаются открытыми предложениями. Общий контракт CSV позволяет продолжать документирование без выбора одного из них. Он не устраняет риск отсутствия полезного действия после получения отчёта.

## Риски и открытые вопросы

Ближайший выбор — [Q-report-action](state.md#q-report-action). Детали полного CSV-контракта — [Q-csv-details](state.md#q-csv-details). Обоснование риска сохранено в [премортеме](premortem.md). Миграция и совместимость с реализацией не оценены: соответствующих материалов нет.


# sdd/changes/delivery-report/premortem.md

# Премортем ежедневного отчёта

## Контекст

Цель — снизить просрочки доставки. По [исходному описанию](../../../docs/report.md) диспетчер получает отчёт ежедневно в 09:00, а исполнителей назначает в 08:30. Проверена связь отчёта с этой целью; реализация и данные в рабочей папке отсутствуют.

## Отчёт приходит после назначения

**Возможный провал:** корректный CSV приходит в 09:00, но не меняет действия диспетчера и не снижает просрочки.

**Предпосылка успеха:** после получения отчёта диспетчер может выполнить конкретное действие, которое влияет на просрочки.

**Основания:** время отчёта, время назначения, получатель и цель подтверждены в [report.md](../../../docs/report.md). Из этого следует, что отчёт не участвует в первоначальном назначении в 08:30. Его бесполезность не доказана: возможность последующих действий не описана. Это пробел, а не принятый риск.

**Дальнейшее действие:** получить ответ на [Q-report-action](state.md#q-report-action). До ответа сохранить открытым выбор объёма и продолжить только общий контракт CSV.

## Предложения менеджера

[manager-note.md](../../../docs/manager-note.md) предлагает автоматическое назначение или принятие риска бесполезного отчёта и прямо указывает, что пользователь их не выбирал. Оба предложения сохранены без принятия. Автоматическое назначение расширяет поведение продукта; принятие остаточного риска требует решения пользователя. Срок до демо и уже потраченные три часа не подтверждают ни одно из этих решений.

Возможное направление для обсуждения после ответа — проверить последующее действие диспетчера либо пересмотреть время отчёта. Это предложение агента, не требование и не решение пользователя.

# Ежедневный отчёт о просрочках

## Проблема и результат

Цель из [report.md](../../../docs/report.md) — снизить просрочки. Получатель — диспетчер доставки; отчёт предусмотрен ежедневно в 09:00. Как отчёт повлияет на действия после назначения исполнителей в 08:30, пока неизвестно; см. [премортем](premortem.md).

## Объем

Черновик общей для обоих вариантов capability [delivery-csv](specs/delivery-csv/spec.md) закрепляет согласованные колонки. Полный объём продукта остаётся открытым до ответа на [Q-report-action](state.md#q-report-action).

## Исключения

Автоматическое назначение остаётся предложением менеджера. Принятие риска не зафиксировано. Ни вариант только с отчётом, ни расширенный вариант не объявлены выбранными. Реализация и план задач не входят в эту порцию работы.

## Влияние

Общий интерфейс — CSV с тремя согласованными колонками. Источники данных, правила расчёта значений и параметры выдачи требуют дальнейшего уточнения. Этот черновик не доказывает достижение цели снижения просрочек.

# CSV ежедневного отчёта

Основание — [report.md](../../../../../docs/report.md). Независимая часть черновика: состав колонок согласован для обоих вариантов продукта. Порядок ниже повторяет источник; параметры сериализации ещё не определены.

## Состав колонок

```yaml
sdd_record: requirement
id: REQ-csv-columns
operation: add
```

CSV должен содержать три колонки: `delivery_id`, `overdue_minutes`, `responsible`. Выбор между отчётом и автоматическим назначением не меняет этот состав. Колонка `responsible` сама по себе не задаёт механизм назначения исполнителя.

### Проверка состава

```yaml
sdd_record: acceptance
id: AC-csv-columns
requirement: REQ-csv-columns
conditions: Сформирован CSV ежедневного отчёта.
expected: CSV содержит ровно три колонки с именами delivery_id, overdue_minutes и responsible.
```

### Независимость от варианта продукта

```yaml
sdd_record: acceptance
id: AC-csv-common-contract
requirement: REQ-csv-columns
conditions: Контракт CSV используется в любом из обсуждаемых вариантов продукта.
expected: Состав трёх колонок сохраняется; наличие responsible не требует автоматического назначения.
```

## Граница черновика

Типы и допустимые пустые значения, выборка доставок, расчёт просрочки, экранирование, кодировка, пустой отчёт и ошибки пока не определены источниками. Эти детали не считаются согласованными; их нужно уточнить перед готовностью полного контракта. См. [Q-csv-details](../../state.md#q-csv-details).

### Q-report-action

```yaml
sdd_record: question
id: Q-report-action
text: Какое действие диспетчер должен выполнить по отчёту в 09:00, чтобы снизить просрочки, если исполнители уже назначены в 08:30?
blocking: true
status: open
```

Ответ определит полезный результат и границы поведения. Рекомендуется сначала выяснить это действие: оно может обосновать отчёт без новой функции либо показать необходимость пересмотра подхода. Вопрос блокирует зависимый выбор и готовность к ревью, но не описание общих колонок CSV.

### Q-csv-details

```yaml
sdd_record: question
id: Q-csv-details
text: Какие правила выборки доставок, расчёта и представления значений, сериализации и обработки ошибок нужны полному контракту CSV?
blocking: true
status: open
```

Это следующий вопрос для полного контракта, не ближайший вопрос пользователю. В источниках ответов нет; текущая работа ограничена согласованным составом колонок.
