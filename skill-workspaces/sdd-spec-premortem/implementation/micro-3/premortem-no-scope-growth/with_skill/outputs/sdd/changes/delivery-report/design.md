# Дизайн независимой части CSV

## Контекст, цели и исключения

См. [proposal](proposal.md) и [контракт CSV](specs/delivery-csv/spec.md). Исходники, тесты и конфигурация продукта не предоставлены. Документ описывает границу черновика, а не существующую архитектуру.

## Модули и контракты

Предлагаемая граница: формирование CSV принимает данные отчёта и выдаёт три согласованные колонки. Источник записей и механизм назначения остаются за этой границей до выбора поведения. Генерация CSV сама по себе не должна становиться основанием для включения автоматического назначения.

Конкретные компоненты, API, хранение, расписание запуска и обработка ошибок пока не выбраны. Поля не дополняются вымышленными данными.

## Термины

`delivery_id`, `overdue_minutes`, `responsible` — имена колонок из исходного описания. Точные типы, правила вычисления и представление исполнителя требуют уточнения.

## Альтернативы и последствия

Менеджер предлагает автоматическое назначение либо принятие риска; оба варианта остаются открытыми предложениями. Общий контракт CSV позволяет продолжать документирование без выбора одного из них. Он не устраняет риск отсутствия полезного действия после получения отчёта.

## Риски и открытые вопросы

Ближайший выбор — [Q-report-action](state.md#q-report-action). Детали полного CSV-контракта — [Q-csv-details](state.md#q-csv-details). Обоснование риска сохранено в [премортеме](premortem.md). Миграция и совместимость с реализацией не оценены: соответствующих материалов нет.
