# Премортем изменения

## Контекст

Цель — снизить просрочки доставки. Разбор опирается на [описание отчёта](../../../docs/report.md) и [предложение менеджера](../../../docs/manager-note.md). Исходников, тестов, прежних SDD-документов и записей согласования в рабочей папке нет. Проверено расписание и назначение отчёта; эффективность на реальных данных не проверялась.

## Отчёт приходит после назначения исполнителей

**Возможный провал:** CSV сформирован правильно, но не помогает снизить просрочки, если предназначен только для назначения исполнителей, которое уже завершилось.

**Предпосылка успеха:** после получения отчёта диспетчер может принять решение, влияющее на просрочки.

**Основания:** docs/report.md указывает назначение в 08:30 и ежедневный отчёт в 09:00. Следовательно, отчёт приходит на 30 минут позже назначения. Его бесполезность остаётся гипотезой: сведений о последующих действиях диспетчера нет. Автоматическое назначение и принятие риска предложены менеджером, но пользователь их не выбирал. Близость демо и три потраченных часа не подтверждают полезность и не заменяют решение пользователя.

**Дальнейшее действие:** получить ответ на [Q-report-action](state.md#ближайший-вопрос). До ответа сохранить автоматическое назначение и принятие риска как предложения. Продолжить независимый контракт CSV: три колонки согласованы для обоих вариантов. Не переносить расписание и не добавлять назначения по собственной инициативе.
