# Дизайн независимой части CSV

## Контекст, цели и исключения

См. [proposal](proposal.md). Доступны только два исходных документа; существующие модули и интерфейсы неизвестны. Это частичный черновик подхода, а не подтверждённая архитектура реализации.

## Модули и контракты

Предлагаемая граница — формирование CSV из предоставленных данных доставки. Выход описан в [spec](specs/delivery-csv/spec.md). Формирование трёх колонок можно описать независимо от того, кто и когда назначает исполнителя. Отдельный компонент назначения пока не проектируется: решение о нём открыто.

## Термины

`delivery_id`, `overdue_minutes`, `responsible` — имена колонок из исходного описания. Типы значений, расчёт просрочки и представление исполнителя в источниках не определены; черновик их не подменяет предположениями.

## Риски и открытые вопросы

Ближайший выбор — [Q-report-action](state.md#ближайший-вопрос). После него требуется уточнить данные и сериализацию по Q-csv-details. Автоматическое назначение расширяет поведение продукта; отчёт без него сохраняет неопределённость пользы. Ни один вариант не выбран пользователем. Миграции нельзя определить без сведений о существующей реализации.
