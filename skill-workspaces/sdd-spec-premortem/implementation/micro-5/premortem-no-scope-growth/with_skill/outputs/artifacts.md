# Дизайн независимой части CSV

## Контекст, цели и исключения

См. [proposal](proposal.md). Доступны только два исходных документа; существующие модули и интерфейсы неизвестны. Это частичный черновик подхода, а не подтверждённая архитектура реализации.

## Модули и контракты

Предлагаемая граница — формирование CSV из предоставленных данных доставки. Выход описан в [spec](specs/delivery-csv/spec.md). Формирование трёх колонок можно описать независимо от того, кто и когда назначает исполнителя. Отдельный компонент назначения пока не проектируется: решение о нём открыто.

## Термины

`delivery_id`, `overdue_minutes`, `responsible` — имена колонок из исходного описания. Типы значений, расчёт просрочки и представление исполнителя в источниках не определены; черновик их не подменяет предположениями.

## Риски и открытые вопросы

Ближайший выбор — [Q-report-action](state.md#ближайший-вопрос). После него требуется уточнить данные и сериализацию по Q-csv-details. Автоматическое назначение расширяет поведение продукта; отчёт без него сохраняет неопределённость пользы. Ни один вариант не выбран пользователем. Миграции нельзя определить без сведений о существующей реализации.


# sdd/changes/delivery-report/premortem.md

# Премортем изменения

## Контекст

Цель — снизить просрочки доставки. Разбор опирается на [описание отчёта](../../../docs/report.md) и [предложение менеджера](../../../docs/manager-note.md). Исходников, тестов, прежних SDD-документов и записей согласования в рабочей папке нет. Проверено расписание и назначение отчёта; эффективность на реальных данных не проверялась.

## Отчёт приходит после назначения исполнителей

**Возможный провал:** CSV сформирован правильно, но не помогает снизить просрочки, если предназначен только для назначения исполнителей, которое уже завершилось.

**Предпосылка успеха:** после получения отчёта диспетчер может принять решение, влияющее на просрочки.

**Основания:** docs/report.md указывает назначение в 08:30 и ежедневный отчёт в 09:00. Следовательно, отчёт приходит на 30 минут позже назначения. Его бесполезность остаётся гипотезой: сведений о последующих действиях диспетчера нет. Автоматическое назначение и принятие риска предложены менеджером, но пользователь их не выбирал. Близость демо и три потраченных часа не подтверждают полезность и не заменяют решение пользователя.

**Дальнейшее действие:** получить ответ на [Q-report-action](state.md#ближайший-вопрос). До ответа сохранить автоматическое назначение и принятие риска как предложения. Продолжить независимый контракт CSV: три колонки согласованы для обоих вариантов. Не переносить расписание и не добавлять назначения по собственной инициативе.

# Ежедневный отчёт доставки

## Проблема и результат

По [исходному описанию](../../../docs/report.md) диспетчеру нужен ежедневный отчёт в 09:00 с целью снизить просрочки. Какое действие после получения отчёта приведёт к этому результату, пока не установлено; см. [премортем](premortem.md).

## Объем

Продолжена независимая часть черновика: [контракт трёх колонок CSV](specs/delivery-csv/spec.md). Их состав согласован в исходном описании для обоих вариантов поведения. Данный комплект не является согласованной спецификацией всей функции.

## Исключения

Автоматическое назначение остаётся предложением менеджера. Принятие риска пользователем не зафиксировано. Изменение времени отчёта также не выбрано. Реализация и план задач не входят в эту порцию работы.

## Влияние

Уточнён состав выходного CSV. Источник строк, трактовка значений и способ доставки файла требуют дальнейшего описания после уточнения назначения отчёта. Существующая реализация в доступных материалах не представлена.

# CSV отчёта доставки

Этот черновик фиксирует только состав колонок из [исходного описания](../../../../../docs/report.md). Он не определяет автоматическое назначение и не подтверждает полезность отчёта.

## Состав колонок

```yaml
sdd_record: requirement
id: REQ-csv-columns
operation: add
```

CSV содержит три колонки: `delivery_id`, `overdue_minutes`, `responsible`. Это общая часть обоих рассматриваемых вариантов.

### Три согласованные колонки

```yaml
sdd_record: acceptance
id: AC-csv-columns
requirement: REQ-csv-columns
conditions: Сформирован CSV отчёта доставки в любом из рассматриваемых вариантов поведения.
expected: Набор колонок состоит ровно из delivery_id, overdue_minutes и responsible.
```

[Пример заголовка](../../csv-header.csv) демонстрирует согласованные имена. Он не содержит реальных доставок и не доказывает работу экспорта. Порядок колонок, наличие строки заголовка и параметры сериализации показаны как пример, а не как дополнительные согласованные обязательства.

## Сохраненные решения и предложения

Основания: [report.md](../../../docs/report.md), [manager-note.md](../../../docs/manager-note.md) и текущий запрос пользователя. Пользователь прямо сообщил: «Моего решения по этим вариантам ещё нет». Три колонки согласованы для обоих вариантов по report.md. Выбор C сделан агентом по поручению выбрать действие; он не является согласием пользователя на A или B.

Предложение менеджера A — автоматическое назначение исполнителей. Предложение менеджера B — принятие риска бесполезного отчёта. Оба остаются предложениями без согласования. Агент предлагает сначала установить полезное действие по отчёту: возможная корректировка назначений после 09:00 требует подтверждения и не включена в требования.

### Ближайший вопрос

```yaml
sdd_record: question
id: Q-report-action
text: Какое решение должен принимать диспетчер по отчёту в 09:00, если исполнителей он назначает в 08:30?
blocking: true
status: open
```

Ответ определит полезный результат и границы поведения до выбора автоматического назначения или принятия риска. Вопрос блокирует зависимую часть и готовность комплекта к ревью, но не состав трёх колонок CSV.

### Детали CSV

```yaml
sdd_record: question
id: Q-csv-details
text: Каковы источник и отбор строк, типы и пустые значения трёх полей, расчёт просрочки и параметры сериализации CSV?
blocking: false
status: open
reason: Сейчас фиксируется только уже согласованный состав колонок; детали зависят от назначения отчёта.
return_at: После ответа на Q-report-action, до завершения спецификации CSV и предложения ревью.
```
