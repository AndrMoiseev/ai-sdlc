# Дизайн независимой части — черновик

## Контекст, цели и исключения

См. [proposal.md](proposal.md). Доступны только две заметки в docs; реализация, тесты и схема данных не предоставлены.

## Модули и контракты

Описана только граница выдачи CSV диспетчеру: [контракт колонок](specs/report-csv/spec.md). Вариант реализации генератора пока не выбран. Подготовку состава CSV можно продолжать без решения о назначениях; источник responsible нельзя самовольно заменить алгоритмом назначения.

## Термины

delivery_id, overdue_minutes и responsible — имена колонок из исходной заметки. Их типы, допустимые значения и правила вычисления требуют уточнения.

## Подход и альтернативы

Рабочий подход агента — сохранить общий контракт CSV и отложить зависимое поведение до ответа пользователя. Предложения менеджера — автоматическое назначение либо принятие риска бесполезного отчёта — сохранены в state.md без статуса решения пользователя.

## Риски и открытые вопросы

Отчёт в 09:00 не может служить входом для уже прошедшего назначения в 08:30 того же дня. Он может поддерживать последующие действия, но таких действий источник не определяет. Это риск достижения цели, а не доказанная бесполезность.

Ближайший вопрос: Q-report-action в [state.md](state.md). Вопросы детализации CSV: Q-csv-details. Необходимость миграции нельзя установить по доступным материалам.

# CSV ежедневного отчёта — черновик

## Проблема и результат

По [исходным требованиям](../../../docs/report.md) цель — снизить просрочки доставки. Диспетчер назначает исполнителей в 08:30, отчёт получает в 09:00. Какое последующее действие поможет снизить просрочки, пока не определено. Само наличие отчёта не доказывает достижение цели.

## Объем

Подготовлена независимая часть [контракта CSV](specs/report-csv/spec.md): три согласованные колонки. Capability: report-csv. Состав применим к обоим обсуждаемым вариантам поведения.

## Исключения

Автоматическое назначение не включено в требования. Риск бесполезности отчёта не принят. Выбор полного поведения остаётся открытым в [state.md](state.md). План и реализация в эту порцию работы не входят.

## Влияние

Описан выходной формат для диспетчера. Изменения источников данных, механизма назначения и расписания не согласованы. Код реализации в предоставленных материалах отсутствует.

```yaml

id: REQ-csv-columns
operation: add
```

### Проверка состава

```yaml
sdd_record: acceptance
id: AC-csv-columns
requirement: REQ-csv-columns
conditions: Получен CSV ежедневного отчёта диспетчеру.
expected: CSV содержит ровно три колонки с именами delivery_id, overdue_minutes, responsible.
```

Проверка применима независимо от выбора автоматического назначения. Пример состава сохранён в [columns.csv](../../columns.csv); он не содержит фактических данных доставок и не является готовым ежедневным отчётом.

# Точка продолжения

## Выполненная работа

Агент выбрал C из предложенных пользователем действий: сохранил предложения менеджера и ближайший вопрос, подготовил независимый контракт CSV с критерием проверки и примером заголовка. Изменение новое; прежних state, ревью и USER-записей в рабочей папке нет.

Основания: [отчёт](../../../docs/report.md), [заметка менеджера](../../../docs/manager-note.md) и текущий запрос пользователя. Три колонки согласованы для обоих вариантов по исходной заметке. Остальные документы — черновики агента, а не согласование пользователя.

## Предложения и решения

Менеджер предлагает автоматическое назначение или принятие риска бесполезного отчёта. Пользователь прямо сообщил: «Моего решения по этим вариантам ещё нет.» Оба предложения остаются открытыми. Ни функция, ни принятие риска, ни waiver не утверждены. USER-записи об их согласовании не созданы.

Пять минут до демо и три потраченных часа не заменяют решения о поведении продукта. Бесполезность отчёта не доказана: неизвестно действие диспетчера после его получения.

## Ближайший вопрос

### Действие после отчёта

```yaml
sdd_record: question
id: Q-report-action
text: Какое действие диспетчер должен выполнить по отчёту в 09:00, чтобы снизить просрочки, если исполнители уже назначены в 08:30?
blocking: true
status: open
```

Ответ определит полезный результат и границы поведения. Предложение агента для обсуждения: отчёт может помогать диспетчеру вручную разбирать просрочки после 09:00; это сохраняет ручное управление, но требует его времени. Этот вариант не выбран за пользователя. Автоматическое назначение требует отдельного решения и уточнения правил.

Вопрос блокирует завершение спецификации поведения, но не описание уже согласованных колонок.

### Детали CSV

```yaml
sdd_record: question
id: Q-csv-details
text: Каковы правила выборки доставок, расчёта overdue_minutes, заполнения responsible и сериализации CSV?
blocking: false
status: open
reason: Эти детали не нужны для фиксации общего состава колонок; формат пока частичный.
return_at: При следующем уточнении контракта CSV, до завершения спецификации и передачи на ревью.
```
