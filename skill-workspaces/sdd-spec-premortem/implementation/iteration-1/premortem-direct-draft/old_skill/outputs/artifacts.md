# Дизайн отчёта

Черновик. Технология и архитектура не выбраны.

## Контекст, цели и исключения

Основания и объём: [proposal](proposal.md); известный контракт: [spec](specs/delivery-report/spec.md). Доступны docs/report.md и пакет sdd-spec. Подтверждённых сведений о модулях, хранилище и планировщике продукта нет.

Ранний выбор — действие диспетчера после получения отчёта. Без него нельзя обосновать достаточность времени и полей для снижения просрочек.

## Модули и контракты

Предложение агента: запуск по расписанию → чтение среза → выборка просроченных → CSV → передача диспетчеру. Это логические обязанности, а не решение создавать отдельные сервисы.

| Граница | Ответственность | Неопределённость |
|---|---|---|
| Запуск | Ежедневное формирование | Часовой пояс, смысл 09:00, пропущенный запуск |
| Данные | Сведения о доставке, сроке и ответственном | Источник, полнота, свежесть, момент среза |
| Выборка | Определить просрочку и её длительность | Статусы, сроки, округление минут |
| CSV | Представить три запрошенных поля | Кодировка, разделитель, пустые значения |
| Передача | Предоставить результат диспетчеру | Канал, адрес, повторы и ошибки |

## Термины

Получатель — диспетчер доставки; роль известна, адрес и канал неизвестны. Значение responsible не позволяет пока установить, идёт ли речь об исполнителе или иной роли. Формула overdue_minutes не определена. Срез — момент, к которому относятся данные; он не обязательно совпадает с получением CSV.

## Подход и альтернативы

Время 09:00 сохраняется по запросу. Эскалация просроченных доставок или пересмотр назначений после 09:00 — возможные действия, предложенные агентом, а не решения пользователя.

Отчёт до 08:30 мог бы поддерживать первоначальное назначение, но меняет явное расписание. Отчёт в 09:00 только для наблюдения сохраняет расписание, но не объясняет, как снижать просрочки. Выбор зависит от Q-report-action.

API, база данных и готовая выгрузка — возможные источники; ни один не подтверждён. Выбор зависит от доступных полей и свежести. Формальные DEC не записаны: оснований для технического решения недостаточно.

## Риски и открытые вопросы

Главный риск: отчёт приходит после назначения и не вызывает полезного действия. Для проверки нужен пример одного утра: что изменит диспетчер после чтения строки? Это Q-report-action в [state](state.md).

Неверная просрочка или устаревший ответственный приведут к ошибочному действию: Q-data-contract. Ошибка источника, представленная как пустая выборка, скроет проблему: Q-failure-contract. Без часового пояса нельзя проверить время: Q-delivery-contract.

## Миграция и проверка

Изменения хранения и миграция пока не обоснованы. После уточнения контрактов нужны контрольные данные для выборки, проверки CSV, расписания и ошибок передачи, а также проверка возможности принять выбранное решение по отчёту. План реализации не создаётся; код не изменяется.

# Ежедневный отчёт о доставках

Черновик: цель использования требует уточнения.

## Проблема и результат

Источник: [docs/report.md](../../../docs/report.md). Получатель — диспетчер доставки. Цель — снизить просрочки. Запрошен ежедневный CSV в 09:00 с полями delivery_id, overdue_minutes, responsible.

Диспетчер назначает исполнителей в 08:30. Отчёт поступает после этого решения. Неизвестно, какое действие по отчёту должно снижать просрочки. Получение CSV само по себе не подтверждает достижение цели.

## Объем

Новая capability [delivery-report](specs/delivery-report/spec.md): ежедневный отчёт о просроченных доставках и ответственных. Существующих спецификаций и исходников продукта в доступных материалах нет. [Design](design.md) содержит предварительный подход; [state](state.md) — блокирующие вопросы.

## Исключения

Автоматическое назначение исполнителей, изменение расписания 08:30, реализация и развёртывание не входят в запрос. Перенос отчёта на время до 08:30 не согласован.

## Влияние

Появляется CSV для диспетчера. Потребуются сведения о доставках, сроках и ответственных. Источник, правила расчёта, канал передачи и часовой пояс неизвестны. Оценка интеграций ограничена отсутствием материалов реализации.

# Отчёт о просроченных доставках

Черновик известной части контракта из [источника](../../../../../docs/report.md). Условные критерии не закрывают вопросы в [state](../../state.md).

## Ежедневная выдача

```yaml
sdd_record: requirement
id: REQ-daily-report
operation: add
```

Диспетчер доставки должен получать отчёт ежедневно в 09:00. Часовой пояс, канал и значение 09:00 для начала формирования либо получения требуют уточнения Q-delivery-contract.

### Отчёт за день

```yaml
sdd_record: acceptance
id: AC-daily-report
requirement: REQ-daily-report
conditions: Согласованы часовой пояс и контракт передачи; наступило время ежедневного отчёта 09:00.
expected: Отчёт за соответствующий день предоставлен диспетчеру по согласованному контракту времени и передачи.
```

## Поля отчёта

```yaml
sdd_record: requirement
id: REQ-report-fields
operation: add
```

Отчёт должен иметь формат CSV и поля delivery_id, overdue_minutes, responsible для просроченных доставок. Правила просрочки, расчёта минут, выбора ответственного и момента среза остаются открытыми в Q-data-contract.

### Представление доставки

```yaml
sdd_record: acceptance
id: AC-report-fields
requirement: REQ-report-fields
conditions: По согласованным правилам в отчёт включена просроченная доставка с известным ответственным.
expected: CSV содержит delivery_id, overdue_minutes, responsible со значениями идентификатора доставки, просрочки в минутах и ответственного по согласованному срезу.
```

### Состав выборки

```yaml
sdd_record: acceptance
id: AC-report-selection
requirement: REQ-report-fields
conditions: Подготовлен контрольный набор с ожидаемой выборкой по согласованному правилу просрочки.
expected: Набор доставок в CSV совпадает с ожидаемой выборкой.
```

## Незавершённая часть контракта

Пустая выборка, неполные данные, недоступный источник, ошибка передачи, повторный запуск и параметры CSV требуют решения Q-failure-contract. Текущие критерии не составляют полной приёмки. Действие получателя и критерий полезности отчёта не определены: Q-report-action.
