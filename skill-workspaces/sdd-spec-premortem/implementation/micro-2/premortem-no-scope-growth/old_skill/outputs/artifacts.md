# Дизайн независимой части CSV — черновик

## Контекст и границы

См. [proposal](proposal.md) и [контракт CSV](specs/report-csv/spec.md). Доступны только два исходных документа в docs; исходников, конфигурации и тестов продукта нет. Реальная архитектура не установлена.

## Предлагаемая граница

Формирование CSV принимает подготовленные данные доставки и выдаёт три согласованные колонки. Источник данных и механизм назначения исполнителя остаются за этой границей. Такое разделение позволяет уточнять CSV до выбора способа назначения. Это предложение дизайна, а не описание существующего кода или согласованное решение пользователя.

## Термины и контракты

`delivery_id`, `overdue_minutes`, `responsible` — имена колонок из исходного документа. Точное представление идентификатора доставки, просрочки и ответственного пока не определено. Правила заполнения нельзя вывести только из имён.

## Альтернативы и последствия

Менеджер предлагает автоматическое назначение либо принятие риска бесполезного отчёта. Оба предложения сохранены в state без утверждения. Возможность использовать отчёт для действий после 09:00 требует уточнения; перенос времени отчёта также не согласован.

## Риски и открытые вопросы

Отчёт в 09:00 не может служить входом для уже состоявшегося назначения в 08:30 того же дня. Однако дальнейшие действия диспетчера неизвестны, поэтому бесполезность отчёта не доказана. Ближайший вопрос: [Q-report-action](state.md#ближайший-вопрос). Риск не принят пользователем.

Миграция, ошибки формирования и эксплуатационный контракт пока не определены: нет данных о системе и согласованной границы поведения. Это неполный дизайн для продолжения обсуждения.

# Ежедневный отчёт доставки — черновик

## Проблема и результат

По [исходным требованиям](../../../docs/report.md) диспетчер получает отчёт ежедневно в 09:00; цель — снизить просрочки. Исполнителей он назначает в 08:30. Пока не установлено, какое действие после получения отчёта должно влиять на просрочки. Эффект отчёта не подтверждён и не опровергнут.

## Объем

Продолжена независимая capability [report-csv](specs/report-csv/spec.md): состав трёх согласованных колонок. Это общий контракт для обоих обсуждаемых вариантов. Документ не выбирает между отчётом и автоматическим назначением.

## Исключения

Автоматическое назначение остаётся предложением. Принятие риска пользователем не зафиксировано. Код реализации, конфигурация продукта, baseline и план задач не изменяются.

## Влияние

Контракт задаёт состав CSV для диспетчера. Полный формат значений, источник данных и способ доставки пока не определены. Перед расширением спецификации нужен ответ на ближайший вопрос в [state](state.md).

# CSV ежедневного отчёта — частичный черновик

Источник: [docs/report.md](../../../../../docs/report.md). Три колонки согласованы для обоих вариантов. Ниже описана только независимая часть контракта.

## Состав колонок

```yaml
sdd_record: requirement
id: REQ-csv-columns
operation: add
```

CSV отчёта содержит ровно три колонки: `delivery_id`, `overdue_minutes`, `responsible`.

### Проверка состава

```yaml
sdd_record: acceptance
id: AC-csv-columns
requirement: REQ-csv-columns
conditions: Сформирован CSV ежедневного отчёта доставки.
expected: CSV содержит ровно три колонки с именами delivery_id, overdue_minutes и responsible.
```

Критерий проверяет состав, а не источник назначения исполнителя. Значение `responsible` само по себе не означает автоматического назначения.

### Границы черновика

Порядок колонок, кодировка, разделитель, типы и пустые значения, правила отбора доставок и расчёта просрочки ещё не установлены. Этот документ не задаёт их по умолчанию. В проекте нет данных доставок; фактический CSV с записями не создавался.
