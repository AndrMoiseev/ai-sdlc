# Независимая часть CSV — черновик

Основание: [docs/report.md](../../../docs/report.md). Три колонки согласованы для обоих вариантов поведения. Их описание не зависит от решения об автоматическом назначении.

## Согласованная структура

```csv
delivery_id,overdue_minutes,responsible
```

[report-header.csv](report-header.csv) содержит только эту строку заголовка. Это заготовка формата, а не выгрузка реальных доставок и не свидетельство отсутствия просрочек. Исходных строк в доступных материалах нет.

| Колонка | Рабочее прочтение имени, для уточнения |
|---|---|
| delivery_id | Идентификатор доставки |
| overdue_minutes | Просрочка в минутах |
| responsible | Текущий ответственный; источник и представление значения не заданы |

Наличие responsible не означает автоматического назначения. Черновик не определяет, кто и как меняет ответственного.

## Проверки независимой части

Заголовок содержит ровно три названные колонки в порядке, указанном в источнике. Ни одна колонка для автоматического назначения не добавлена. Фиктивных записей доставок нет.

## Детали, оставленные открытыми

Для полного контракта ещё нужны правила отбора доставок, момент расчёта просрочки, формат идентификаторов, пустой responsible, экранирование значений и кодировка потребителя. Сейчас они не объявлены согласованными. UTF-8 без BOM и запятая в заготовке — технический формат этого артефакта, а не утверждение полного контракта продукта.

После ответа на Q-report-action уточнить зависимые правила и подготовить proposal, spec с критериями приёмки и design. Этот документ — независимая часть исследования, не готовая спецификация всего изменения.


# sdd/changes/delivery-report/premortem.md

# Премортем ежедневного отчёта

## Контекст

Цель — снизить просрочки доставки. Получатель — диспетчер. Основания: [описание отчёта](../../../docs/report.md), [предложение менеджера](../../../docs/manager-note.md) и текущий запрос пользователя. Код, тесты и данные доставок в проекте отсутствуют. Разбор касается пользы отчёта и границы автоматического назначения.

## Отчёт приходит после назначения исполнителей

**Возможный провал:** корректный CSV не помогает снизить просрочки, если после его получения диспетчер не принимает решений, влияющих на доставки.

**Предпосылка успеха:** после получения отчёта остаётся доступное действие, которое может снизить просрочки.

**Основания:** по docs/report.md исполнителей назначают в 08:30, отчёт приходит в 09:00. Это подтверждает порядок событий, но не бесполезность отчёта. Возможность переназначения или других действий после 09:00 неизвестна. Менеджер предлагает автоматическое назначение либо принятие риска; пользователь прямо сообщил, что ещё не выбрал эти варианты. Срок до демо и три часа работы не подтверждают ни пользу, ни согласование.

**Дальнейшее действие:** получить ответ на [Q-report-action](state.md#ближайший-вопрос). До ответа сохранить автоматическое назначение и принятие риска как предложения. Независимо продолжить согласованную структуру CSV: [черновик контракта](csv-contract.md). Находка открыта; риск не принят.

### Ближайший вопрос

~~~yaml
sdd_record: question
id: Q-report-action
text: Какое действие диспетчер должен выполнить по отчёту после 09:00, чтобы снизить просрочки, если исполнители уже назначены в 08:30?
blocking: true
status: open
~~~

Ответ определит полезный результат и объём поведения. Предложение агента: сначала уточнить действие после отчёта; если достаточно ручного действия, можно избежать расширения объёма, но его эффективность пока не подтверждена. Вопрос блокирует зависимое поведение и готовность к ревью, но не работу над общими колонками CSV.
