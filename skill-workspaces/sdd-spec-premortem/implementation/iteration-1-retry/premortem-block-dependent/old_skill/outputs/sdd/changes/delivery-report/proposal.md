# Ежедневный отчёт о доставках

## Проблема и результат

По [исходным материалам](../../../docs/report.md) цель изменения — снизить просрочки доставок. Получатель ежедневного отчёта — диспетчер доставки. Отчёт предусмотрен в 09:00, назначения диспетчер выполняет в 08:30. Связь отчёта с решением о назначениях требует уточнения: отчёт за этот день поступает после назначения. Снижение просрочек пока является целью, а не доказанным результатом.

## Объем

Общая для обоих вариантов capability — [delivery-report](specs/delivery-report/spec.md): ежедневный CSV с тремя согласованными колонками. Этот контракт можно зафиксировать до выбора режима.

Объем изменения остаётся открытым: только отчёт или отчёт вместе с автоматическим назначением исполнителей. Ни один вариант не принят по умолчанию. Зависимые требования к назначениям появятся после ответа на Q-delivery-mode в [state.md](state.md).

## Исключения

В текущем черновике не определены алгоритм назначения, права на изменение исполнителей и обработка конфликтов с ручным назначением. Это нерешённая часть объёма, а не окончательное исключение автоматизации. План реализации и изменения кода не входят в текущее поручение.

## Влияние

Выходной интерфейс — CSV для диспетчера. Автоматический режим дополнительно затронет данные назначений; конкретные системы и интеграции в материалах не указаны. Код и конфигурация продукта отсутствуют, поэтому техническая совместимость не подтверждена.
