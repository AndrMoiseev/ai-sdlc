# Дизайн независимой части CSV — черновик

## Контекст, цели и исключения

Область задана в [proposal](proposal.md). В доступных материалах есть только описание отчёта и предложение менеджера; исходников реализации нет. Архитектуру существующей системы установить нельзя.

## Модули и контракты

Предлагаемая граница: формирование CSV получает данные доставки и выводит согласованные колонки по [REQ-csv-columns](specs/delivery-csv/spec.md#три-согласованные-колонки). Контракт колонок можно уточнять независимо от будущего решения об автоматическом назначении. Источник данных и механизм запуска пока не определены.

Поле responsible не означает автоматического выбора исполнителя. Алгоритм назначения и изменение назначений не проектируются до выбора объёма пользователем.

## Термины

Имена колонок сохранены из источника. Точные типы и правила вычисления значений ещё не установлены; по одному имени overdue_minutes нельзя закреплять округление и момент расчёта.

## Альтернативы и риски

Предложения менеджера — автоматическое назначение либо принятие риска отчёта без подтверждённой пользы — сохранены в [state](state.md). Ни одно не выбрано пользователем. Возможность полезного действия после 09:00 требует ответа на Q-report-action. До этого нельзя выбрать алгоритм назначения или утверждать, что одного отчёта достаточно.

Проверка независимой части сопоставляет количество и имена колонок с AC-csv-columns. Данные для демонстрации и миграция не заданы; вымышленные доставки не добавляются.

# sdd/changes/delivery-report/premortem.md

# Премортем изменения

## Контекст

Цель — снизить просрочки доставки. Проверены [описание отчёта](../../../docs/report.md) и [предложение менеджера](../../../docs/manager-note.md). Существующего изменения SDD нет. Разбор касается полезности ежедневного отчёта и границы автоматического назначения.

## Отчёт после назначения исполнителей

**Возможный провал:** CSV сформирован правильно, но просрочки не уменьшаются, поскольку данные не используются для действия, способного повлиять на доставку.

**Предпосылка успеха:** диспетчер получает данные до того решения, для которого они нужны, либо может изменить ход доставки после получения отчёта.

**Основания:** по docs/report.md диспетчер назначает исполнителей в 08:30, отчёт приходит в 09:00. Поэтому отчёт не предшествует указанному назначению в тот же день. Гипотеза: после 09:00 данные могут помочь пересмотреть назначения или принять иные меры. Таких действий источник не описывает; бесполезность отчёта не доказана. Менеджер предлагает автоматическое назначение или принятие риска, но прямо отмечает отсутствие выбора пользователя. Срок до демо и уже затраченные три часа не подтверждают ни полезность, ни согласие.

**Дальнейшее действие:** получить ответ на [Q-report-action](state.md#ближайший-вопрос). До ответа оставить объём автоматизации и принятие риска открытыми. Продолжить независимый контракт трёх согласованных колонок в [spec](specs/delivery-csv/spec.md); не приписывать ему доказанное снижение просрочек.

# CSV ежедневного отчёта — частичный черновик

## Проблема и результат

По [источнику](../../../docs/report.md) диспетчеру доставки нужен ежедневный отчёт в 09:00; цель — снизить просрочки. Действие по отчёту пока не определено: назначения происходят в 08:30. Риск разобран в [премортеме](premortem.md). Этот черновик фиксирует только независимую часть контракта CSV.

## Объём

Capability [delivery-csv](specs/delivery-csv/spec.md): три согласованные колонки delivery_id, overdue_minutes, responsible. Этот состав применим к обоим обсуждаемым вариантам поведения.

## Исключения

Автоматическое назначение остаётся предложением менеджера, не требованием. Принятие риска пользователем не зафиксировано. Выбор продукта «только отчёт» тоже не сделан. Расписание не изменено. Код и конфигурация реализации не входят в эту работу.

## Влияние

Зафиксирован состав внешнего CSV. Правила формирования строк и действие диспетчера требуют уточнения; готовность полного контракта и снижение просрочек не подтверждены.

# Состав CSV

Частичный черновик по [docs/report.md](../../../../../docs/report.md). Определяет состав колонок, общий для вариантов с автоматическим назначением и без него.

## Три согласованные колонки

```yaml
sdd_record: requirement
id: REQ-csv-columns
operation: add
```

CSV отчёта должен содержать ровно три колонки: delivery_id, overdue_minutes, responsible. Это требование не задаёт способ выбора исполнителя и не разрешает изменение назначений.

### Проверка состава

```yaml
sdd_record: acceptance
id: AC-csv-columns
requirement: REQ-csv-columns
conditions: Сформирован CSV ежедневного отчёта доставки.
expected: CSV содержит ровно три колонки с именами delivery_id, overdue_minutes, responsible.
```

## Границы черновика

Типы значений, обязательность responsible, отбор строк, порядок колонок, кодировка, разделитель, экранирование и обработка ошибок не определены источником. Новых требований к ним этот черновик не вводит. Ближайший вопрос — [Q-report-action](../../state.md#ближайший-вопрос); затем уточняется контракт данных.

### Ближайший вопрос

```yaml
sdd_record: question
id: Q-report-action
text: Какое действие диспетчер должен выполнить по отчёту в 09:00, чтобы снизить просрочки, если исполнители уже назначены в 08:30?
blocking: true
status: open
```

Ответ определит требуемый результат и поможет выбрать объём автоматизации. Вопрос блокирует зависимые требования и готовность полного комплекта к ревью, но не описание согласованных колонок. Вариант для обсуждения — использование отчёта для пересмотра назначений после 09:00; возможность и польза такого действия не подтверждены.
