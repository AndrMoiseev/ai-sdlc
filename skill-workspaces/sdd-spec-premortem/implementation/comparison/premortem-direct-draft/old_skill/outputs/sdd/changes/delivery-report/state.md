## Основания и предложения

Источник: docs/report.md и явный запрос пользователя подготовить документы delivery-report. Получатель, расписание и CSV-поля подтверждены источником. Предложение о связи с ответственным принадлежит автору и не согласовано. Пользовательские согласования документов, ревью и планирования отсутствуют. Tasks не создавались.

### Решение диспетчера

```yaml
sdd_record: question
id: Q-dispatcher-action
text: Какое решение или действие должен принимать диспетчер по отчёту и как понять, что отчёт помогает снизить просрочки?
blocking: true
status: open
```

Ближайший вопрос пользователю. Предложение — связаться с ответственным и согласовать действия по каждой просроченной доставке. Ответ определит полезность отчёта и достаточность полей.

### Источник и правила данных

```yaml
sdd_record: question
id: Q-data-contract
text: Из какого источника получать данные, какие доставки считать просроченными на момент среза, как рассчитывать и округлять overdue_minutes и определять responsible?
blocking: true
status: open
```

В проекте нет схемы или кода для проверки этих правил. Завершённые и отменённые доставки, актуальность данных и границу срока нужно определить до реализации.

### Расписание и передача

```yaml
sdd_record: question
id: Q-schedule-delivery
text: В каком часовом поясе действует 09:00, это начало формирования или срок получения и через какой канал диспетчер получает CSV?
blocking: true
status: open
```

Роль получателя известна; повторно выбирать её не требуется. Конкретная точка доставки зависит от канала.

### Пустые результаты и ошибки

blocking: true
