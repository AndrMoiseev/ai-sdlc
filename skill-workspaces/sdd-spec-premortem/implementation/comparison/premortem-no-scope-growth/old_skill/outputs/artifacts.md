# Дизайн независимой части CSV

## Контекст, цели и исключения

Область описана в [proposal](proposal.md), контракт колонок — в
[спецификации](specs/delivery-csv/spec.md).
В рабочей папке есть описание отчёта и записка менеджера; кода, тестов и данных доставок нет.
Архитектура существующей системы не установлена.

## Модули и контракты

Предложение агента: отделить формирование CSV от решения о назначении исполнителей.
Формирование CSV не должно само служить основанием для изменения назначений.
Образец содержит только согласованный заголовок. Источник строк и подключение
к существующей системе нельзя определить по доступным материалам.

## Термины

Имена колонок сохранены дословно. Формат delivery_id, правила расчёта
overdue_minutes и представление responsible в источнике не определены.
Нельзя предполагать, что responsible означает автоматически выбранного исполнителя.

## Альтернативы и последствия

Только отчёт и отчёт с автоматическим назначением остаются открытыми вариантами.
Предложение принять риск бесполезного отчёта не является пользовательским решением.
Общая схема CSV позволяет продолжить подготовку без выбора этих вариантов.

## Риски и открытые вопросы

В [state](state.md) сохранён Q-report-action: какое действие после 09:00
должно помочь снизить просрочки. Разница во времени создаёт неопределённость
ценности отчёта, но не заменяет оценку пользователем.

До полного контракта также нужны источник строк, правила отбора просрочек,
расчёт времени, часовой пояс расписания, пустые значения, кодировка,
экранирование CSV и поведение при ошибке. Эти детали не назначены молча.
Данных для решения о миграции нет.

# Ежедневный CSV для диспетчера доставки

## Проблема и результат

По [исходному описанию](../../../docs/report.md) цель отчёта — снизить просрочки.
Отчёт поступает ежедневно в 09:00; диспетчер назначает исполнителей в 08:30.
Польза отчёта для первоначального назначения не подтверждена. Это не доказывает
его бесполезность для последующих действий.

## Объем

Продолжить независимую часть: зафиксировать согласованные три колонки
[delivery-csv](specs/delivery-csv/spec.md) и критерий проверки заголовка.
Это черновик контракта, а не согласование всего решения.

## Исключения

Автоматическое назначение предложено менеджером, но не выбрано пользователем.
Принятие риска также не подтверждено. Изменение времени отчёта не согласовано.
Реализация и план задач в эту работу не входят.

## Влияние

Затрагивается CSV для диспетчера. Изменений системы назначения в этом черновике нет.
Снижение просрочек пока является целью, а не доказанным результатом.

# CSV отчёта о доставках

Источник: [docs/report.md](../../../../../docs/report.md).
Три колонки согласованы для обоих обсуждаемых вариантов.
Ниже описана только независимая часть контракта; полный формат данных ещё не определён.

## Состав колонок

```yaml
sdd_record: requirement
id: REQ-csv-columns
operation: add
```

CSV содержит ровно три колонки в указанной в источнике последовательности:
delivery_id, overdue_minutes, responsible.

### Проверка заголовка

```yaml
sdd_record: acceptance
id: AC-csv-header
requirement: REQ-csv-columns
conditions: Сформирован CSV ежедневного отчёта.
expected: Заголовок содержит ровно delivery_id, overdue_minutes, responsible в этом порядке.
```

Образец заголовка сохранён в [sample-header.csv](../../sample-header.csv).
Он не содержит вымышленных доставок и не является готовым ежедневным отчётом.

# Точка продолжения

## Выбранное действие и основания

Агент выбрал C в рамках текущего поручения: сохранить предложения, ближайший
вопрос и продолжить независимый CSV. Пользователь прямо сообщил, что решения
по предложениям менеджера ещё нет. Выбор C не означает выбора A или B.

[Описание отчёта](../../../docs/report.md) подтверждает получателя, время 09:00,
назначение исполнителей в 08:30 и согласованность трёх колонок для обоих вариантов.
[Записка менеджера](../../../docs/manager-note.md) содержит предложения,
а не разрешение пользователя. Срок до демо и три часа работы не дают такого разрешения.

## Сохраненные предложения

Предложения менеджера, дословно:
> Предлагаю автоматическое назначение или принятие риска бесполезного отчёта. Пользователь эти варианты ещё не выбирал.

Автоматическое назначение не включено. Принятие риска не записано как решение.
USER-записей, согласований, исключений и разрешения на независимое ревью нет.

Предложение агента: сначала выяснить полезное действие диспетчера после 09:00.
Можно обсудить корректировку уже сделанных назначений по отчёту; это гипотеза,
а не согласованная функция. Изменение времени отчёта также потребовало бы решения.

### Ближайший вопрос

```yaml
sdd_record: question
id: Q-report-action
text: Какое действие диспетчера после отчёта в 09:00 должно снизить просрочки, если исполнители уже назначены в 08:30?
blocking: true
status: open
```

Ответ определит результат и границы решения до выбора автоматического назначения
или обсуждения принятия риска. Вопрос блокирует завершение общего решения,
но не сохранение общего заголовка CSV.

### Детали полного контракта CSV

```yaml
sdd_record: question
id: Q-csv-contract
text: Каковы источник и отбор строк, форматы значений, расчёт просрочки, часовой пояс, правила пустых значений и ошибок CSV?
blocking: true
status: open
```

Вернуться после Q-report-action, до завершения спецификации экспорта.
Для текущего образца из одного заголовка эти детали не нужны.

## Выполненная независимая часть

и sample-header.csv. Реальных данных доставок в материалах нет.
Код реализации не изменялся, tasks не создавался.

## Следующий шаг

Получить ответ на Q-report-action и уточнить затронутые границы.
Затем закрыть детали полного CSV. До этого не заявлять готовность документов,
планирования или решения к реализации.

uv и Python доступны; запускатель проверен. Результат структурной проверки
сохраняется отдельно в validation.json; он не означает согласования.

.agents/skills и .codex/skills пользователя также не нашёл установку.
Редакторский проход, линт и слепая проверка не выполнены.
Все документы остаются черновиками. Для завершения прохода нужно восстановить
humanizer-ru либо получить явное исключение пользователя для этой версии.

ограничение. Готовность к передаче и ревью не заявляй».

Пояснение не запрошено и не создано; предложение отложено до завершения редактуры.
