## Предложения

Рабочее имя: `sdd-apply`. Пользователь выбрал автономное выполнение всего
плана. Отдельные исполнители и независимое ревью предложены в design.
Прогресс предлагается хранить отдельно от согласованных документов, существенные изменения
возвращать в `sdd-spec`. Результат исполнения по решению пользователя:
локальные коммиты по задачам и завершение работы на этом этапе.
HTML-дашборд включён в обязательный объём. Скилл работает в паре с `sdd-spec`,
не готовит спецификации вместо него и не переписывает проектные инструкции автоматически.
Кроме этих решений, автономного выполнения и правил выбора режима, остальные предложения пользователь ещё
не согласовал. USER-записи согласований документов не создавались.

Пояснение решения ещё не создавалось. После проверки комплекта пользователю
предлагаются один документ, набор документов или отказ; отсутствие ответа
не блокирует основной процесс.

### Модель выполнения

```yaml
sdd_record: question
id: Q-execution-model

```

Варианты, отправленные пользователю: автономное выполнение всего плана;
выполнение одной задачи с остановкой после каждой; один исполнитель
и субагенты только для ревью. Рекомендуется первый вариант.
Ответ пользователя, дословно: «автономное выполнение всего плана».
Решение применено в proposal и REQ-autonomous-execution.

### Режим выполнения

Уточнение пользователя, дословно:

> Давай добавим последовательный режим выполнения и это должен быть режим по-умолчанию. Параллельное выполнение должно запускаться только если пользователь явно это запросил.

Последовательный режим принят по умолчанию. Параллельный режим требует
явного запроса для соответствующего исполнения. Автономность, независимые
задачи и доступные ресурсы не заменяют такой запрос. При продолжении
проверяется сохранённое основание выбора и поздние отмены.
Правка внесена в proposal, REQ-autonomous-execution,
DEC-controlled-concurrency, исследование и премортем. Добавлены
AC-sequential-default, AC-explicit-parallel и AC-mode-resume,
уточнён AC-isolated-work.

### Результат и границы скилла

Уточнение пользователя, дословно:

> Уточнения по proposal: новый скилл предназначен для совместной работы с sdd-spec, подготовка спецификации вместо этого не предполагается вовсе, а не только в первой версии. Автоматическое переписывание проектных инструкций также вне скоупа. По итогам выполнения плана мы должны получить набор коммитов по задачам и на этом все. Также сразу хочется иметь HTML-дашборд, т.к. по нему удобно отслеживать прогресс.

Постоянная граница ответственности внесена в proposal и REQ-approved-input.
Добавлены REQ-task-commits и REQ-progress-dashboard. Завершение плана
требует набора проверенных коммитов по задачам в локальной ветке исполнения;
последующие этапы доставки исключены. Дашборд показывает прогресс с начала
работы и сохраняет итоговый снимок. Подходы описаны в DEC-task-commits
и DEC-live-dashboard. Исследование и премортем обновлены.

## Git Worktrees и независимые проверки

Уточнение пользователя, дословно:

> Важно зафиксировать метод изоляции при параллельном выполнении. Я предлагаю использовать Git Worktrees. Также важно понять кто и в какой момент запускает тесты и линтеры, т.к. без прохождения тестов мы не можем быть уверены в том, что работа действительно завершена. При этом если тесты запускает сам исполнитель - не понятно насколько можно этому доверять.

В черновик внесены Git Worktrees с отдельной веткой на задачу,
последовательным переносом и независимой проверкой интеграции. Работа
по умолчанию остаётся последовательной. Зафиксированы роли и моменты
запуска: исходные проверки, самопроверка исполнителя, независимый запуск
на кандидате, проверка переноса и полный обязательный итоговый набор.
Рецензент проверяет достаточность тестов и отсутствие ослабления проверок.
Результаты привязаны к версии кода и отражаются в дашборде по этапам.
Непройденная обязательная проверка блокирует соответствующую приёмку.

Новые требования: REQ-worktree-isolation и REQ-independent-verification.
Технические детали остаются черновым предложением; согласование всего
комплекта и независимое consistency-ревью ещё не проводились.
