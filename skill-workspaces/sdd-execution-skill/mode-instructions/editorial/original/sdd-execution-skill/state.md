### Режим выполнения

Уточнение пользователя, дословно:

> Давай добавим последовательный режим выполнения и это должен быть режим по-умолчанию. Параллельное выполнение должно запускаться только если пользователь явно это запросил.

Последовательный режим принят по умолчанию. Параллельный режим требует
явного запроса для соответствующего исполнения. Автономность, независимые
задачи и доступные ресурсы не заменяют такой запрос. При продолжении
проверяется сохранённое основание выбора и поздние отмены.
Правка внесена в proposal, REQ-autonomous-execution,
DEC-controlled-concurrency, исследование и премортем. Добавлены
AC-sequential-default, AC-explicit-parallel и AC-mode-resume,
уточнён AC-isolated-work.

Уточнение пользователя, дословно:

по умолчанию остаётся последовательной. Зафиксированы роли и моменты
запуска: исходные проверки, самопроверка исполнителя, независимый запуск
на кандидате, проверка переноса и полный обязательный итоговый набор.
Рецензент проверяет достаточность тестов и отсутствие ослабления проверок.
Результаты привязаны к версии кода и отражаются в дашборде по этапам.

Коммит сохраняется в рабочей ветке.

Выбраны worktrees в detached HEAD, без веток задач и коммитов исполнителей.
Оркестратор сохраняет пакет незакоммиченных изменений, переносит его
в рабочую ветку исполнения и организует независимые проверки интеграции.

Прерванный перенос восстанавливается по пакету, состоянию файлов и истории
рабочей ветки без повторного применения и дублирования коммита.
