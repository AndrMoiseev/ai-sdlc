

Новый скилл работает в паре с : тот готовит и согласует спецификацию
и план, а новый скилл выполняет план. Он сохраняет основания согласования,
проверяет выполнение критериев и продолжает работу после перерыва.
Результат выполнения плана: набор локальных коммитов по задачам,
прошедших проверки и независимое ревью. На этом работа скилла заканчивается.
HTML-дашборд позволяет отслеживать прогресс во время выполнения.

Пользователь выбрал автономное выполнение всего плана в последовательном
режиме по умолчанию; параллельный режим включается только по его явному запросу.
Совместная работа с , коммиты по задачам и HTML-дашборд также
подтверждены пользователем. Остальные решения
этого комплекта пока предложены в черновике и требуют согласования.

NeoPilot сохранены в research.md.


Все операции исполнения с однозначными правилами выполняются скриптами
пакета. Это обязательный принцип: проверка переходов и запись состояния,
расчёт доступных задач, сбор результатов команд, работа с Git и worktrees,
перенос изменений, восстановление и генерация панели. Агент передаёт
структурированное намерение; скрипт проверяет условия и выполняет операцию
либо возвращает отказ без изменения прогресса. Прямое редактирование
состояния агентом не является штатным способом работы. За агентами
остаются реализация, интерпретация требований и содержательное ревью.

Добавляется capability sdd-execution:
вход по согласованному плану, исполнение отдельными агентами, независимое
ревью, исправления, коммиты по задачам, сохранение доказательств
и восстановление после перерыва. Проверка общего результата по согласованным
критериям подтверждает готовность итогового набора коммитов.

HTML-дашборд входит в обязательный объём с первой версии. Он показывает
режим выполнения, задачи и их состояния, прогресс, результаты проверок
и ревью, причины блокировок и созданные коммиты. Данные обновляются
из записи исполнения; после завершения доступен итоговый снимок.

Скилл вызывается явно для выбранного изменения. Поддерживаются Codex
и Claude Code через адаптеры среды. По умолчанию одна задача проходит
реализацию, проверки и ревью до приёмки или блокировки; затем выбирается
следующая доступная задача. Явный запрос
пользователя разрешает параллельный режим; независимость задач и доступные
слоты сами по себе его не включают. При невозможности безопасного
параллельного запуска работа продолжается последовательно с сохранением
независимости ревью.

Инструкции оркестратора разделены на последовательный и параллельный
режимы и загружаются только для выбранного режима. Общие контракты
и скрипты используются совместно, когда это не смешивает порядок работы.
При конфликте между сокращением повторов и изоляцией инструкций
приоритет имеет изоляция; допустимы необходимые локальные повторы.

Изоляция параллельных задач строится на Git Worktrees: отдельное рабочее
дерево в detached HEAD на задачу, без ветки задачи и коммитов исполнителя.
Оркестратор последовательно переносит незакоммиченные изменения,
проверяет интеграцию, создаёт коммит в рабочей ветке и удаляет worktree.
Общие ресурсы тестов также требуют разделения. Исполнитель запускает
проверки для своей работы; перед приёмкой независимый проверяющий сам
запускает обязательные тесты и линтеры. Рецензент оценивает достаточность
тестов по AC. После переноса проверяется интегрированный результат,
а перед завершением плана проводится итоговая независимая проверка.
Отчёт автора или непройденная обязательная проверка не разрешают приёмку.

На задачу допускается суммарно не более трёх раундов код-ревью, включая
первый. Если после третьего раунда остаются блокирующие замечания
или для приёмки нужен ещё один раунд,
исполнение всего плана останавливается до явного решения пользователя.
Счётчик сохраняется при смене агента и продолжении сессии. Пользователь
получает историю попыток и может разрешить ограниченное число дополнительных
раундов, направить контракт на пересмотр в  либо завершить работу
с частичным результатом. Непройденные проверки не превращаются в приёмку.

HTML открывается с диска и по таймеру обновляет элементы из соседнего
. Этот файл генерирует скрипт из состояния исполнения.
Локальный сервер нужен только как запасной вариант просмотра в среде,
которая блокирует загрузку соседнего файла.


Подготовка и согласование спецификаций и планов относятся к 
и не входят в назначение нового скилла. Это постоянная граница ответственности.
Автоматическое переписывание проектных инструкций также вне объёма:
скилл читает их как ограничения и не запускает отдельный проход актуализации.

Работа заканчивается локальными коммитами по задачам. Создание PR,
push, merge, публикация, синхронизация baseline, архивирование изменения
и доводка сверх согласованных критериев не входят в процесс.
Изменения документации, предусмотренные самим исполняемым планом,
остаются частью реализации.


Согласованные proposal, specs, design и tasks сохраняются в исходных байтах.
Материалы исполнения и HTML-дашборд записываются отдельно в каталоге изменения. Формат
 v1 и его существующие согласования не изменяются. Сводка
исполнения объясняет, где читать прогресс, если статусы в исходном плане
остаются . У каждой принятой задачи есть связь с её коммитами
в локальной ветке исполнения; чужие изменения в них не включаются.

Пакет скилла содержит инструкции, адаптеры, шаблоны и необходимые
детерминированные проверки. Временные данные и окружения находятся вне
исходного и установленного пакетов. Подключение пакета к принятому в
репозитории способу установки входит в реализацию.
