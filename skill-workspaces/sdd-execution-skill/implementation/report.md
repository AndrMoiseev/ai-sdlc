# Реализация sdd-apply

Дата проверки: 2026-10-08. Исходный пакет: `skills/sdd-apply`.

| Задача плана | Реализация | Проверки |

## Подтверждённые результаты

- `uv run --locked --script skills/sdd-apply/scripts/test.py -q`: **67 passed in 171.14s**. Это модульные, интеграционные, Git, браузерные и runtime-проверки; тестовые role attestations не выдаются за реальные запуски агентов.
- Отдельное независимое ревью обнаружило шесть дефектов. Исправлены выбор устаревшего успешного evidence, обход владения путями, финализация незакоммиченных файлов, восстановление потерянного reviewer и два дефекта очистки worktree. Семь регрессионных проверок включены в общий набор; подробности в `review.md`.
- Реальный последовательный Codex-прогон со свежими executor, verifier/reviewer и final verifier завершился `complete`. Проверены AC-add и AC-invalid; локальный коммит `2cd7a2d7c832be622167ada639df6ed9945d7ce1`. Преждевременное принятие отклонено. Логи, grading, timing и ограничения: `behavioral/report.md` и `behavioral/outputs/execution/`.
- Реальный прогон выявил ложный конфликт владения на Windows из-за CRLF. Сравнение исходного состояния учитывает Git filters; сохранены исходный отказ и успешный повтор.
- Реальный параллельный Codex-прогон завершился `complete`: два одновременно работающих автора в отдельных detached worktrees, независимые проверки/ревью до и после последовательной интеграции, свежие финальные проверяющие на общем HEAD. Коммиты: TASK-add `b4452b04d79810b7eff7d5ba2b72aa5bf8a65c95`, TASK-alternate `4252002de7f6c04dab478c8b1bc89c2071f0e702`. Все три AC подтверждены; оба worktree удалены штатной операцией. Успешное состояние сохранено в `parallel/success-execution/`.
- В параллельном fixture авторы записали Python checks с UTF-8 BOM. После обычного repair с удалением BOM и обновлением lock предупреждение о нераспознанных script metadata исчезло, тесты повторно прошли. Это исправление тестового проекта, исходный пакет скилла в ходе параллельного прогона не менялся.
- После сохранения успешного параллельного прогона выполнена контролируемая неисправность в disposable fixture: обязательный runner временно убран. Новый свежий final verifier вернул `unavailable`, ни один тест не был выполнен; `finalize` сохранил `partial/blocked`. Runner восстановлен с исходным SHA256, diff всех шести файлов задач к HEAD пуст. Отрицательный результат оставлен в состоянии как есть; успешный архив не изменён. Доказательства: `parallel/negative/`.
- Выполнены десять свежих decision microtests: пять с полными релевантными инструкциями и пять без них, под давлением срока и уже потраченных усилий. Все выбрали остановку на 5/5 без правок кода или сброса счётчика. Это проверка решений, не десять исполнений Git-процесса. Контроль также успешен, поэтому улучшение поведения от формулировки не доказано и дополнительные запреты по этим ответам не добавлялись. Ответы и анализ: `iteration-1/microtests/`.
- APM установил локальные sdd-spec и sdd-apply в отдельный потребитель `installation/` для Codex и Claude. Установленная Codex-копия прошла `tests/test_package.py`, Claude-копия выполнила `execute.py --help`. Обе копии через `validate` успешно проверили реальный fixture и автоматически нашли свою установленную соседнюю копию sdd-spec; ответы сохранены в `installation/.agents-validation.json` и `.claude-validation.json`. Основная пользовательская установка не обновлялась.
- Runtime-матрица проверяет обе точки входа из исходной и копированной установки, повторный запуск, посторонний cwd, конфликтующие зависимости потребителя, пустой кэш, его восстановление, offline и устаревший lock. Файлы потребителя и lock-файлы остаются неизменными.
- После installed validate выполнена побайтовая сверка SHA256: все 63 файла исходного пакета совпадают с обеими установленными копиями, дополнительных файлов нет. Проверка включает скрытые и игнорируемые файлы.
- Dashboard проверен установленным Chrome через headless file://. Встроенный Browser недоступен (`browsers.list=[]`); этот результат не заявлен как проверка встроенного Browser.

## Границы доказательств

Структурный валидатор conductor: 12 успешных проверок, 0 ошибок, 2 эвристических предупреждения (нет буквального `Use when` в description; дополнительное поле `disable-model-invocation`). Поле сохраняется намеренно для явного вызова в Claude Code. Discovery для explicit-only скилла неприменим и не засчитан успешным.

Claude Code CLI отсутствует: адаптер и установка проверены, реальный процесс в этом хосте не проверен. Native Codex-прогон имеет унаследованный каталог скиллов и использует зависимости из исходного репозитория; это не герметичный сравнительный эксперимент. Базовый прогон без скилла (`baseline/`) использует другой fixture; сравнивать его скорость или pass rate с `behavioral/` некорректно. Недоступная token telemetry записана как null.

Полный герметичный paired eval по всем пяти сценариям из `evals/evals.json` не выполнен. Пять повторений с контролем выполнены для одного решения о бюджете, а реальные сквозные проверки покрывают последовательный и параллельный успех, преждевременное принятие и недоступный обязательный runner. Наличие eval definitions и успешные pytest-проверки не заменяют остальные поведенческие результаты. Таблица выше описывает реализованные части, а не утверждает независимую приёмку всех 61 AC.
