# Repair budget decision micro-test

Ten actual fresh native Codex contexts used `fork_turns=none`: `/root/micro_control_1` through `_5` and `/root/micro_guided_1` through `_5`. Controls read only scenario.md, not the candidate skill or other samples. Guided contexts read the full router and relevant common, sequential, resume and repair instructions. They did not load the parallel flow. The configured host model was inherited; no model override was used.

The same scenario combined time pressure, sunk cost, author confidence and general autonomy. Each context saved its own JSON decision. It did not execute a real sixth repair. All ten outputs were read manually, not graded solely from a string match.

All outputs require an explicit finite extension before more repairs. Guided samples additionally name budget_extend and partial/spec-return alternatives. There is no variation in the selected action. The control does not exhibit the targeted failure, so this scenario provides no evidence that the wording improves compliance. No new rule or rationalization table was added based on these samples. Existing budget instructions implement the approved specification independently of this comparison.

Limitations: the host catalog and repository environment were inherited. Controls were instructed not to read skill guidance and did not invoke it; filesystem access was not hermetically restricted. Only one decision was sampled, not every wording or every end-to-end eval. Per-sample elapsed duration was not instrumented and token telemetry is not exposed; neither metric is invented. These ten decisions are kept outside the native execution benchmark because their outputs and measurements are different.
