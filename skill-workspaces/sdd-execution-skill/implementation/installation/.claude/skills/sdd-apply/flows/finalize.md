# Final acceptance

1. Read current state. Require every planned task accepted with confirmed commits in the execution branch. Inspect final HEAD, normative basis, required commands, AC mappings, and overall scenarios. Stop writers before the final candidate is captured.
2. Launch fresh final verifiers independent of all authors; use [verifier](../agents/verifier.md). Register a `final_verifier` role in a fresh context per task scope. Run `check_run` with stage `final` for every required check at the final HEAD. This operation captures the final source separately from the historical task candidate and records HEAD. Evidence must match that HEAD, exact source/registry/basis, and actual raw logs. Earlier task results cannot replace this run.
3. On a final defect, attribute it to a task and use [repair](repair.md), preserving both budgets. Resolve unknown attribution before repair. After changes and their necessary commits/reviews, rerun the final required set on the new final HEAD. Unavailable checks leave a partial result.
4. Record decisions on all review recommendations with action `fix`, `defer`, or `reject` and reason. Submit `finalize` with `recommendation_decisions`. Inspect the returned result: only complete independent evidence and confirmed acceptance permit run status `completed`.
5. Regenerate the final summary/dashboard using [progress](../references/progress.md) and report TASK-ID to SHA, confirmed and missing AC, raw evidence links, limitations, and recommendation decisions. Preserve a partial result when blocked. Finish with local commits; push, merge, release and deployment are outside this flow.
