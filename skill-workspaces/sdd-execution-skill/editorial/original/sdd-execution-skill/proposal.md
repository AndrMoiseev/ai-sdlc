# Автономное выполнение согласованного SDD-плана

## Проблема и результат

`sdd-spec` заканчивает работу на согласованном плане. После передачи этого
плана исполнителю пока нет общего процесса, который сохраняет основания
согласования, проверяет выполнение каждого критерия и продолжает работу
после перерыва. Отдельный скилл должен доводить план до проверенного
результата без запроса разрешения на каждую задачу.

Пользователь выбрал «автономное выполнение всего плана». Остальные решения
этого комплекта являются черновыми предложениями для согласования.
Рабочее имя скилла: `sdd-apply`. Разбор референса и причины отличий от
NeoPilot сохранены в [research.md](research.md).

## Объём

Добавляется capability [sdd-execution](specs/sdd-execution/spec.md):
вход по согласованному плану, исполнение отдельными агентами, независимое
ревью, исправления, сохранение доказательств и восстановление после перерыва.
Работа завершается проверкой общего результата по согласованным критериям.

Скилл вызывается явно для выбранного изменения. Поддерживаются Codex
и Claude Code через адаптеры среды. При недостатке параллельных слотов
работа продолжается последовательно с сохранением независимости ревью.

## Исключения

В первую версию не входят подготовка спецификации вместо `sdd-spec`,
публикация, push, merge, синхронизация baseline и архивирование изменения.
HTML-панель, автоматическое переписывание проектных инструкций и доводка
сверх согласованных критериев также исключены. Изменения документации,
предусмотренные самим исполняемым планом, остаются частью реализации.

## Влияние

Согласованные proposal, specs, design и tasks сохраняются в исходных байтах.
Материалы исполнения записываются отдельно в каталоге изменения. Формат
`sdd-spec` v1 и его существующие согласования не изменяются. Сводка
исполнения объясняет, где читать прогресс, если статусы в исходном плане
остаются `pending`.

Пакет скилла содержит инструкции, адаптеры, шаблоны и необходимые
детерминированные проверки. Временные данные и окружения находятся вне
исходного и установленного пакетов. Подключение пакета к принятому в
репозитории способу установки входит в реализацию.
