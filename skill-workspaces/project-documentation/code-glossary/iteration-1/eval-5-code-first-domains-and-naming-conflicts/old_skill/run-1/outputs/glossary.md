# Глоссарий

Термины проекта Service. Названия ниже взяты из README и реализации; соглашение о канонической терминологии не принято. README предшествует текущей реализации, поэтому его утверждения отмечены отдельно.

## Partner — продажи

В README так называется организация, покупающая товары.

- Контекст: описание продаж в устаревшем README.
- Источник: [README](../README.md).
- Открытый вопрос: остаётся ли Partner действующим бизнес-термином и соответствует ли ему `Sales.Customer`? [Реализация](../src/model.ts) использует `Customer`, но не устанавливает его соответствие организации-покупателю.

## Customer — Sales

Объект с идентификатором `id` и именем `legalName`, который принимает `Sales.invoice`; результат этой функции содержит его идентификатор в `customerId`.

- Контекст: имя в реализации продаж; бизнес-определение не установлено.
- Источник: [`Sales.Customer` и `Sales.invoice`](../src/model.ts).
- Открытый вопрос: обозначает ли Customer понятие Partner из [README](../README.md), и какое название следует принять в документации?

## Client — Transport

Контракт отправителя строкового содержимого: метод `send` принимает строку и возвращает `Promise<void>`.

- Контекст: транспортный интерфейс; не следует смешивать с `Sales.Customer` без подтверждения соответствия.
- Источник: [`Transport.Client`](../src/model.ts).

## Reservation — Inventory

Результат `Inventory.reserve`, содержащий идентификатор заказа `orderId` и отметку `expiresAt`. Функция делегирует создание объекта `legacyReserve`, которая устанавливает `expiresAt` равным `Date.now() + 60000`.

- Контекст: имя в реализации учёта запасов. `release` принимает Reservation и возвращает его `orderId` как `releasedOrder`; изменения состояния запасов в представленном коде нет.
- Источник: [`Inventory.Reservation`, `reserve`, `legacyReserve` и `release`](../src/model.ts).
- Открытый вопрос: являются ли Reservation и Allocation одним бизнес-понятием или разными? Совпадение полей и делегирование подтверждают связь реализации, но не устанавливают допустимые синонимы. Механизм истечения срока в доступных материалах не описан.

## Allocation — Inventory

Тип результата `Inventory.legacyReserve`: объект с идентификатором заказа и отметкой `expiresAt`, установленной на 60 секунд позже текущего времени. Этот же объект возвращает `reserve` с объявленным типом Reservation.

- Контекст: имя в реализации учёта запасов; префикс `legacy` сам по себе не устанавливает статус термина в документации.
- Источник: [`Inventory.Allocation`, `legacyReserve` и `reserve`](../src/model.ts).
- Расхождение: [устаревший README](../README.md) утверждает, что allocation длится бесконечно; реализация задаёт конечную отметку времени, но не показывает автоматическое освобождение запасов.
- Открытый вопрос: каково действующее правило срока allocation и как оно связано с Reservation?

## DispatchBatch — Fulfillment

Объект со списком `shipmentIds`, передаваемый в `Fulfillment.dispatch`. Для каждого идентификатора функция возвращает объект с этим идентификатором и `sent: true`; фактическая отправка в представленном коде не показана.

- Контекст: имя в реализации исполнения отправлений; бизнес-название и правила формирования группы не определены.
- Источник: [`Fulfillment.DispatchBatch` и `dispatch`](../src/model.ts).
