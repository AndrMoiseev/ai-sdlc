# Проверка project-documentation

Актуальная итерация по обратной связи о глоссарии Stepan:
[кодовая база и таблицы по доменам](code-glossary/validation.md).
Ниже сохранены результаты предыдущей версии с карточками.

Дата: 2026-09-28. Статус: черновик для явного вызова в Codex.

## Основание и границы

Исходное соглашение — [ADR-0001](../../docs/decisions/adr/0001-project-documentation-structure.md)
со статусом `proposed`: общий глоссарий, канонические термины, определения,
сокращения, нежелательные синонимы и ссылки на подробные доменные понятия.
Пользователь подтвердил переносимость между проектами, вынесение неоднозначных
терминов в открытые вопросы и запуск только по явному вызову.

Порядок обновления, формат карточки и проверки — предложения первой версии
скилла. ADR исключает процедуры обслуживания из своей области и не устанавливает
эти правила. Скилл автономен: для его использования ADR из этого репозитория
не требуется. Приоритет имеют соглашения целевого проекта.

Архитектура: последовательный процесс с ветками создания, обновления и
разбора неоднозначностей. Формулировки оставлены на усмотрение агента;
границы источников, статусы утверждений и сохранение ссылок заданы явно.

## Режим вызова и проверки

В `agents/openai.yaml` установлено `policy.allow_implicit_invocation: false`.
Описание скилла сокращено до его назначения. Проверки автоматического выбора
удалены; четыре сценария теперь содержат `$project-documentation`.
Для сценария обновления добавлен отдельный `repeat_prompt` для нового чата.

Порядок ручной проверки и подключения в другом проекте описан в
[manual.md](../../skills/project-documentation/evals/manual.md).
Он не требует Claude CLI или Anthropic API key. Сравнение без скилла необязательно.

## Проверки

Оценка структуры 10/10 от 2026-09-25 относится к предыдущей версии.
Текущая версия прошла `quick_validate.py` (`Skill is valid!`). YAML-парсер
подтвердил булево значение `false` в политике вызова. JSON-парсер подтвердил
четыре сценария и явный вызов в каждом запросе, включая `repeat_prompt`.
Локальные ссылки проверены, ошибок нет. На Windows используй `PYTHONUTF8=1`
для чтения русского текста штатным валидатором.

Проверки наличия триггеров в description из `eval_skill.py` не применяются:
пользователь выбрал явный вызов. Подгонять описание под автоматический выбор
для получения прежней оценки не требуется.

Ручные прогоны в Codex ещё не выполнены. Качество результатов, устойчивость
повторного обновления и польза относительно агента без скилла пока не установлены.
Синтетические сценарии не заменяют пилот на реальном проекте.
