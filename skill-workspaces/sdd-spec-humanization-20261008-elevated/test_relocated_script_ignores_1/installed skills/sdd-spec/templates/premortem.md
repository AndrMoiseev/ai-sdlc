# Премортем изменения

## Контекст

Укажите цель и границы проверяемого изменения со ссылками на доступные
документы и ответы. Создавайте этот файл только при находках.
Это материал исследования, без frontmatter и машинных записей SDD.

## Название находки

**Возможный провал:** какой ожидаемый результат не будет достигнут,
даже если реализация работает.

**Предпосылка успеха:** условие, от которого зависит результат.

**Основания:** подтверждённые факты со ссылками, отдельно гипотеза и пробелы.
Укажите недоступные источники и ограничения проверки.

**Дальнейшее действие:** доступная проверка, ссылка на заголовок Q в questions.md
с его Q-ID либо итог решения и основание. При отсрочке повторите reason
и return_at из Q без расхождений. При закрытии сохраните итог и источники;
выбранное поведение свяжите со spec и AC, подход с design, цель с proposal.

Повторите раздел для фактических находок; обязательного количества нет.
Обновляйте существующие разделы, сохраняя закрытые находки и их основания.
