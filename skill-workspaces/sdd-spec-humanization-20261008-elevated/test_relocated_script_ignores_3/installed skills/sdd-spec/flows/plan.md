# План и завершение

После завершённой правки документов предложи [гуманизацию](../references/editorial-pass.md)
и учти сохранённый выбор пользователя; выполняй её только в согласованной области.
Исходные отчёты ревью и ответы пользователя сохраняй дословно.

## Вход

Проверь происхождение существенных положений по [discussion](../references/discussion.md),
decisions.md и questions.md, включая старые Q-записи в state. Новые существенные
выборы при детализации плана также верни в обсуждение; сохранять независимую
часть уже порученного плана допустимо.

Перечитай актуальные specs, design, proposal, вопросы, отчеты и решения с диска. До создания tasks одновременно требуются: закрытые блокирующие вопросы; корректная структура documents; актуальные завершенные ревью всех линз либо отдельные применимые waiver; решения по всем находкам, завершенные выбранные исправления, причины/`return_at` отложенных; согласование текущих specs/design; явная команда создать план. Согласование документов само по себе не команда. Сохрани `planning_command` с разрешенной областью. При возобновлении уже начатой работы используй проверенное сохраненное поручение без повторного согласия.

Если ревью missing/stale/incomplete, покажи недостающее и предложи запуск. Команда «составь план» не дает waiver. Если требуется содержательный выбор, вернись к explore/revise; структурные ошибки исправь прежде дальнейшего перехода. Пока условия не соблюдены, tasks не создавай.

## Подготовка

1. Прочитай [tasks](../templates/tasks.md) и [формат](../references/document-format.md). Разбей реализацию на проверяемые задачи разумного размера с устойчивыми смысловыми `TASK-...`, отдельным номером 1..N и `status: pending`. У каждой задачи непустой `covers`; каждый AC изменения, включая результат удаления требования, назначен ровно одной задаче. Одна задача может владеть несколькими AC; DEC не заменяет критерий.
2. Включи необходимые кодовые шаги, общие фикстуры, подготовку окружения и тесты внутрь задачи, которой они нужны. Для каждого AC опиши проверку, предполагаемое место тестов и команду либо существующую процедуру. Будущему тестовому файлу не нужно существовать. Если команда пока неизвестна, явно включи подготовку запуска в задачу. Не выделяй последующую задачу «покрыть тестами» и не дублируй AC отдельной интеграционной задачей. Новое поведение интеграции сначала согласуй в specs/AC.
3. Задай `depends_on` по TASK-ID, не номеру. Номер можно менять при перестановке; идентичность и ссылки сохраняются. Проверь отсутствующие зависимости, self-reference и циклы. Граф показывает доступность, но общие файлы/контракты требуют отдельной оценки безопасного параллелизма. Прогресс определяется статусами, не последним номером.
4. Выполни check `--stage plan`. Сообщи ошибки, исправь однозначные, повтори проверку. При необходимости выбора состава задач уточни конкретный вопрос. Успех exit 0 означает только корректную структуру, не завершенность ревью и согласований.
5. Сохрани checkpoint и предложи [независимое ревью](review.md) одному новому рецензенту плана: полнота, размер, критерии, тесты, зависимости, порядок, общие файлы и возможность параллельной работы. Получи согласие на запуск; затем [рассмотри находки](user-review.md). Если правки затронули specs/design, восстанови их готовность, актуальность ревью и согласования.

## Финальный gate

До предложения финального согласования учти выбор гуманизации текущих
tasks и остальных изменённых документов; стилистические правки после ревью
требуют пересчёта его актуальности по общим правилам.

Установи `plan_approved` только когда одновременно проверены:

- Корректная структура текущего комплекта.
- Актуальное завершенное независимое ревью плана либо отдельный явный `review_waiver` для `plan_review` и текущего комплекта.
- Решения пользователя по всем находкам, выполненные выбранные исправления, причины и `return_at` отложенных.
- Явное `plan_approval` текущего комплекта; готовность документов также сохранена.

Фраза «план согласован» не создает waiver и не закрывает находки. Если условие отсутствует, сохрани ответ, сообщи конкретно недостающее и оставь план черновиком. При выполненных условиях сохрани checkpoint и сообщи пути документов и отложенные вопросы. Здесь процесс заканчивается: реализацию, baseline sync и архивирование не начинай.
