# Независимое ревью

После завершённой правки документов предложи [гуманизацию](../references/editorial-pass.md)
и учти сохранённый выбор пользователя; выполняй её только в согласованной области.
Исходные отчёты ревью и ответы пользователя сохраняй дословно.

Перед шагом 3 учти выбор гуманизации по её контракту. Если проход согласован,
заверши его либо зафиксируй ограничение до получения review_consent и snapshot.
Не редактируй уже зафиксированный комплект во время работы рецензентов.

1. Прочитай текущие документы и [формат](../references/document-format.md); запусти check для `documents` или `plan`. До ревью устрани структурные ошибки по [runtime](../references/runtime-setup.md). По [discussion](../references/discussion.md) проверь журнал, вопросы и основания существенных положений: до готовности закрой блокирующие выборы, включая обнаруженные при чтении черновика. План проверяется одним отдельным рецензентом.
2. Для документов прочитай `sdd/arch-lenses/index.md`. Отсутствие файла или `lenses: []` означает только встроенную [consistency](../references/consistency.md). Для каждой записи индекса добавь указанную линзу; случайные файлы каталога не подключай. Повтор ID, зарезервированный `consistency`, неразбираемый индекс или неразрешимый path — ошибка. Перечитывай индекс при каждом входе: новая линза означает недостающее ревью, даже при совпадении хешей.
3. Назначь уникальный run-id из UTC-времени и суффикса. Покажи пользователю стадию, полный перечень линз и предмет проверки. Получи явное согласие на конкретный запуск, сохрани `review_consent` с run-id, областью и манифестом в decisions. Уже полученное согласие на этот запуск не запрашивай повторно. Пропуск требует отдельного `review_waiver` для стадии, линз и текущего комплекта; команда планирования или молчание не заменяют его.
4. Сними `inputs` через snapshot. Все рецензенты запуска получают один неизменяемый комплект: proposal, design, все `specs/**/spec.md`; для плана добавь tasks. Хешируются исходные байты, отсортированные пути относительно изменения; добавление и удаление файлов также меняют комплект. Не редактируй его до завершения всех рецензентов.
5. Создай нового рецензента с чистым контекстом для каждой линзы; для плана — одного. Передай только задание [документов](../references/reviewer-documents.md) или [плана](../references/reviewer-plan.md), выбранную линзу, пути документов, проектные ограничения и релевантные источники. Не передавай историю, рассуждения автора или отчеты других рецензентов. Используй [адаптер Codex](../references/codex.md), [Claude Code](../references/claude-code.md) либо [произвольного агента](../references/generic.md); при лимите агентов запускай последовательно, сохраняя одинаковые входы. Рецензенты только читают и возвращают отчет, основной агент сохраняет файлы.
6. После возврата всех результатов сними `inputs_after`. Основной агент сохраняет каждый отчет по [шаблону](../templates/review-report.md) в `review/<run-id>/<lens-id>.md` либо `plan.md`, используя run-id согласованного запуска. Не перезаписывай предыдущие отчеты. Если источник критичен и недоступен, агент упал, контекст не удалось изолировать или отчет неверен, сохрани доступный результат с `incomplete` и причиной. Не додумывай успешный вывод за рецензента.
7. Результат (`completed_no_findings`, `completed_with_findings`, `incomplete`) и актуальность (`current`, `stale`) — разные оси. Если до/после отличаются, отчет stale навсегда для этого запуска, даже после возврата прежнего содержимого. При чтении сравни манифест с текущим заново; сохраненное freshness не доказательство.
8. State, review, внешние источники и инструкции линз не входят в автоматический хеш. Существенное внешнее изменение оцени вручную и предложи ревью, не объявляй автоматическое отслеживание. Любая правка нормативного комплекта делает stale все линзы стадии независимо от темы. Покажи все stale/missing проверки и перейди к [рассмотрению](user-review.md).

Завершение запуска: исходные отчеты сохранены с ограничениями и обоими манифестами, покрытие линз и актуальность проверены, checkpoint записан. Наличие отчета не означает согласие пользователя с его находками.
