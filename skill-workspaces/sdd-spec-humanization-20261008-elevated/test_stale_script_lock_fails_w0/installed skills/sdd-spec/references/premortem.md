# Премортем изменения

Проверь, почему реализованное изменение может не дать ожидаемого результата.
Проводить проверку нужно после установления цели и контекста, до подробной
спецификации, в том числе при прямом draft и малом исправлении.
Актуальный сохранённый разбор используй повторно по правилам продолжения ниже.

## Проверка предпосылок

1. Установи цель, границы и условия успеха по доступным документам, исходникам,
   тестам, diff и сохранённым ответам пользователя. Прочитай источники прежде,
   чем задавать вопрос о проверяемом факте.
2. Рассмотри конкретный возможный провал и предпосылку, от которой зависит
   результат. Различай подтверждённый факт, гипотезу и недостающие сведения.
   Недоступный источник оставляет ограничение, а не подтверждает предпосылку.
3. Проверь предпосылку по доступным основаниям. Если остаётся существенная
   неопределённость, выбери ближайший вопрос, влияющий на цель, объём,
   наблюдаемое поведение или подход. Например, расписание отчёта без назначения
   не доказывает его пользу: обозначь гипотезу и выясни, какое решение получатель
   принимает по данным. Найденный в источнике ответ повторно не запрашивай.
4. Сохрани наблюдаемый итог. Число находок и вопросов не задано: при достаточных
   основаниях продолжай без интервью. Для опечатки, чей diff не меняет поведение,
   достаточно короткой проверки и отметки об отсутствии находок.

Проверка завершена, когда итог сохранён, у каждой находки есть основания
и дальнейшее действие, а существенные пробелы отражены в вопросах.
Подробные внутренние рассуждения записывать не требуется.

## Хранение и вопросы

В разделе «Премортем» state сохраняй только краткий итог:

- При первой проверке без находок: «Премортем: находок нет». Новый premortem.md
  в этом случае не создавай.
- При находках: «Есть находки: [premortem.md](premortem.md)».

При находках создай или обнови `sdd/changes/<change-id>/premortem.md` по
[шаблону](../templates/premortem.md). Запиши цель и границы разбора. Для каждой
находки используй заголовок для ссылки и четыре части: возможный провал,
предпосылка успеха, основания со ссылками и пробелами, дальнейшее действие.
Действие содержит доступную проверку, ссылку на Q-ID в questions.md либо итог
решения с основанием. Находки премортема не являются FIND независимого ревью.

Вопросы храни в questions.md по формату Q; из находки ссылайся на
заголовок соответствующей записи и называй Q-ID. Применяй правила
[explore](../flows/explore.md):

- Если без ответа пришлось бы угадывать цель, объём, поведение или ключевой
  подход, задай `blocking: true`. Сохрани зависимое решение открытым; продолжай
  независимую часть исследования или черновика. До готовности к ревью закрой
  блокирующий вопрос.
- Для открытого неблокирующего Q запиши `reason` и конкретный `return_at`.
  Повтори причину отсрочки и условие возврата в действии находки без расхождений.
  Отсрочка оставляет вопрос открытым и сама по себе не означает принятия риска.
- Доступное свидетельство может снять неопределённость без отдельного согласия
  на каждую находку. Сохрани источник и итог проверки. Принятие оставшегося
  риска и расширение объёма требуют реального решения пользователя; новую
  функцию до этого сохраняй как предложение.

Обновляй существующую находку, сохраняя её историю и основания закрытия.
Когда открытых находок больше нет, оставь документ и ссылку; краткий итог:
«Открытых находок нет; история: [premortem.md](premortem.md)».
Полный разбор в раздел state не переноси; Q-записи остаются в questions.md.
Для русской авторской прозы предложи [гуманизацию по согласию](editorial-pass.md).

## Продолжение и пересмотр

При resume прочитай итог и premortem.md по сохранённой ссылке. Сопоставь цель,
границы и существенные основания с текущими источниками и ответами пользователя.
При совпадении используй разбор без повторного интервью и дублей находок:
смена сессии сама по себе не является причиной нового разбора.

При изменении цели, существенной предпосылки или противоречащих данных пересмотри
затронутую часть в текущем explore, draft или revise. Сохрани остальные выводы
и проверь зависимые документы. Смену цели обрабатывай по правилам revise.

Если итога нет, область прежней проверки нельзя восстановить или документ
по ссылке недоступен, завершённость прежней проверки не подтверждена.
Восстанови доступные сведения и выполни короткую проверку. При отметке
«находок нет» область восстанавливай из state и документов изменения.
Недоступный источник обозначь как ограничение; только оставшийся существенный
пробел требует вопроса. Потеря источника не разрешает зависимое решение
и не требует автоматически нового интервью. Старые изменения проверяй при
продолжении; отсутствие прежней записи само по себе не отменяет согласования.

## Граница нормативного комплекта

premortem.md — материал исследования: обычный Markdown без нового
`document_type`, `sdd_record`, пространства ID или вида USER.
Он исключён из snapshot documents и plan. Правка только разбора не меняет
манифест и автоматически не делает ревью устаревшим.

Проверь смысл правки: если пользователь выбрал изменение поведения, перенеси
его в specs с проверяемым AC, изменение цели и границ — в proposal,
изменение подхода — в design. В разборе оставь ссылки. Пересчитай актуальность
ревью и согласований изменённого нормативного комплекта по обычным правилам.
Совпадение нормативного манифеста после правки разбора не доказывает,
что выбранное поведение уже отражено в спецификации.

Завершённый премортем не заменяет независимое ревью, применимый waiver,
согласование документов или команду планирования. Переход выполняй по
[plan](../flows/plan.md). Дополнительного согласования премортема не вводи;
действующий waiver применяй в его стадии, версии и области.
