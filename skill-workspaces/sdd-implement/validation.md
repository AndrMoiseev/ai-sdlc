# Проверка переноса sdd-implement

Дата: 2026-10-02.

Пользовательский `openspec-autopilot` перенесён в `skills/sdd-implement`
и добавлен в существующий пакет `aisdlc-core` по подтверждению пользователя.
Изменены имя, описание, UI-метаданные и политика вызова. Три файла
`references/` побайтно совпадали с оригиналом перед его удалением.
Рабочий процесс по-прежнему требует OpenSpec CLI.

Проверено:

- YAML: имя `sdd-implement`, `disable-model-invocation: true`,
  `policy.allow_implicit_invocation: false`, новый default prompt.
- Все локальные Markdown-ссылки разрешаются; старого имени внутри пакета нет.
- Исходники и установленные копии в `.agents/skills/` и `.claude/skills/`
  содержат одинаковые пять файлов с одинаковыми SHA-256.
- В пакетах нет скрытого или игнорируемого runtime-состояния. Скриптов
  исполнения в этом скилле нет, запускатель не требуется.
- `eval_skill.py`: 9 проверок пройдено, 0 ошибок, 3 предупреждения.
  Предупреждения относятся к отсутствию автоматических триггеров в описании
  и к `disable-model-invocation`. `quick_validate.py` не принимает это поле:
  его список допустимых ключей не учитывает политику явного вызова Claude Code.
  Булевы значения политик проверены отдельно YAML-парсером.
- `apm audit local:skills/sdd-implement`: проверены 10 установленных файлов,
  замечаний нет. `git diff --check` проходит.
- Пользовательский каталог `openspec-autopilot` удалён после проверки копий.

APM не завершил общую переустановку: запросил доверие к исполняемым файлам
Archify. Автоматическая проверка безопасности отклонила повторный запуск
с неинтерактивным подтверждением. Вместо него скопирован только локальный
`sdd-implement`, а в lock-файл добавлены его зависимость, хэши и 12 записей
развёртывания. Все прежние записи зависимостей и развёртываний сохранены
без изменений, что проверено сравнением разобранного YAML. Полная установка
и полный CI-аудит APM не подтверждены; dry run проверил только наличие lock-файла.

Проверки автоматического выбора и оптимизация описания пропущены:
скилл вызывается явно. Полный сценарий исполнения, модельные baseline-прогоны
и обнаружение в новой сессии Codex/Claude Code не запускались при этом переносе.
Для ручной проверки в новой сессии вызвать `$sdd-implement` либо `/sdd-implement`
на готовом изменении; проверить загрузку скилла и начало его pre-flight.

Для проверок использован `uv 0.12.5` с пользовательским кэшем вне коллекций
скиллов, `PYTHONDONTWRITEBYTECODE=1` и `PYTHONUTF8=1`.
Временные файлы переноса и первоначальной попытки проверки находятся в
`%TEMP%/sdd-implement-migration/` и `%TEMP%/sdd-implement-validation/`.
