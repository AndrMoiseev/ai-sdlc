# SDD Doc

Создавай глоссарий как словарь для последовательного именования в коде:
одно понятие в пределах домена — один термин. Агент использует существующие
понятия; новые вводит только по явно описывающей их спецификации.

## Вызов

Пользователь запускает скилл явно: `$sdd-doc` и задача.
В Codex автоматический выбор отключён в `agents/openai.yaml`.

## Подготовка

Определи целевой проект и прочитай его инструкции и существующий глоссарий.
Найди исходный код, контракты и тесты; документацию используй для сверки.
Проверь доступность исходных материалов и возможность редактировать
целевые файлы. Если материалы недоступны, запроси их расположение; при наличии
части материалов выполни подтверждённую часть работы и укажи границы проверки.

Используй язык и расположение документации проекта. При отсутствии соглашения
выбери `docs/glossary.md`. Локальные соглашения и явная задача пользователя
определяют формат и область изменения.

## Работа с глоссарием

Перед созданием или обновлением прочитай целиком
[порядок работы и формат записи](references/glossary.md).

Выбери ветку по состоянию проекта:

- Глоссария нет — исследуй понятия и их использование в коде по доменам.
- Глоссарий существует — внеси изменения в затронутые определения и связи.
- Источники противоречат друг другу — сохрани различия и обозначь вопрос рядом
  с термином; продолжи работу с подтверждёнными изменениями.

## Результат

Сохрани изменения в документации, если пользователь запросил её создание или
обновление. Для запроса на анализ или предложение представь соответствующий
результат без записи. Сообщи путь к глоссарию, существенные изменения, проверенные
источники и оставшиеся вопросы. При отсутствии изменений объясни причину.
