# Происхождение критериев simplicity

Референс: [Architecture Simplicity Guard, svishniakov](https://github.com/svishniakov/arch-simplicity-guard).
При подготовке 2026-10-28 изучено дерево Git
`6716df99b707dc67948d3e31b4663c7c7ec7d90d`: `references/core.md`, модельные
дополнения и таблица профилей в `scripts/render_instructions.py`.

Инструкции изложены заново для SDD: проверка необходимости механизма,
последствий удаления, полной стоимости и избыточных условий приёмки; отдельные
уточнения для GPT-6 Astra, GPT-6.1 Sol, Claude Fable 5.1, Opus/Sonnet/Haiku 5.5,
Kimi K3/K3.1 Pro и общие дополнения OpenAI, Claude, Kimi.
Повторяющиеся гарантии собраны в общей линзе; модельные файлы сохраняют акценты.

Правила выбора модели, наследования контекста, чтения журналов и запрет реализации
до закрытия находок не перенесены. Селектор SDD выбирает текст после назначения
исполнителя; пользовательские полномочия, роли, независимость и согласования
задаются действующим SDD. Форматы документов и USER-записей не изменены.

В референсе дополнения обозначены как проектные адаптации рекомендаций поставщиков,
без отдельного подтверждения эффективности на архитектурных задачах. Их наличие
не доказывает особенности или качество конкретной модели. Семейное дополнение
не означает поддержку её запуска в среде. Поведенческую пользу проверяют
по [сценариям simplicity](../evals/simplicity.md), отдельно от структурных тестов.
