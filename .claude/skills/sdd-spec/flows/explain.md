# Пояснение решения

Маршрут создаёт производные документы по прямому запросу или сохранённому
поручению пользователя. Предложение без ответа не разрешает генерацию.

1. Выбери изменение через [resume](resume.md). Прочитай основной комплект,
   сохранённый выбор, область поручения и уже выполненную часть. Поздний запрос
   заменяет прежний отказ в указанной области. Отмена прекращает старое поручение;
   расширение области требует отдельного решения. Пояснение черновика допускается
   при открытых вопросах, если неопределённость обозначена явно.
2. Прочитай [контракт пояснения](../references/explanation.md) и
   [шаблон](../templates/explanation.md). Получи snapshot documents через
   [запускатель](../references/runtime-setup.md). Для существующего пояснения
   выполни сверку актуальности из контракта до использования прежних диаграмм.
3. Составь таблицу покрытия затронутых модулей, всех новых и изменённых процессов
   и сценариев основного комплекта. Свяжи каждую строку с источником и разделом
   пояснения. Укажи неизвестное исходное поведение и причины неприменимости
   представлений. Новое обязательство перенеси на обычный [revise](revise.md):
   пояснение не заменяет требования и согласование.
4. Найди установленный archify по [условиям запуска](../references/runtime-setup.md).
   Прочитай его инструкции, схемы и примеры нужных типов. Создай текст и
   применимые architecture/workflow/sequence по правилам контракта, с независимыми
   статусами элементов и связей. Передай каждому вызову явные пути внутри
   `sdd/changes/<change-id>/archify/`. Если зависимости нет, сохрани доступный текст,
   покрытие, ограничения и следующий шаг; диаграммы не объявляй созданными.
5. Выполни предусмотренные archify проверки со снимками. Для каждого HTML проверь
   привязку имеющихся результатов к его текущим байтам; пригодные результаты
   используй повторно. Осмотри выбранные PNG и вставь кликабельные превью с
   относительными ссылками. Статусы генерации, браузерной проверки, снимков и
   осмотра запиши раздельно в `archify/index.md` по фактическим результатам.
6. Для незавершённых превью примени соответствующую ветку контракта: недоступный
   браузер, ошибка проверки либо непригодный снимок. Сохрани видимый маркер с
   причиной и ссылкой только на существующий HTML. Заполни
   [промпт продолжения](../templates/preview-handoff.md) конкретными путями,
   ID и диагностикой в `archify/preview-handoff.md`; предложи его пользователю.
7. Проверь полноту таблицы покрытия и все локальные ссылки из каждого документа.
   После сверки всего содержания сохрани исходный манифест в index.md. Предложи
   [гуманизацию](../references/editorial-pass.md) новой прозы, учти выбор и сохрани checkpoint:
   выбор, область, манифест, выполненная часть, ограничения и следующий шаг.

Завершение: каждый затронутый предмет объяснён либо имеет явное ограничение;
каждая диаграмма имеет запись в индексе и проверенное превью либо обозначенную
незавершённую работу. Сообщи фактические статусы и оставшиеся шаги. Ограничения
пояснения не добавляют условий готовности основного комплекта; его блокирующие
вопросы, отдельное согласие на ревью и команда планирования сохраняются.
