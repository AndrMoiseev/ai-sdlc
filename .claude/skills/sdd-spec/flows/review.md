# Независимое ревью комплекта

Оркестратор организует этот флоу. До проверки получи от
[архитектора](../references/architect.md) завершённый комплект и остановку записи.
Авторские исправления возвращай архитектору; рецензенты сохраняют независимость.

Ревью проверяет все подготовленные документы в одном запуске. Прочитай
[общий контракт](../../sdd-shared/references/document-format-review.md),
[правила обсуждения](../references/discussion.md) и [формат документов](../../sdd-shared/references/document-format-normative.md).
При наличии tasks добавь [формат задач](../../sdd-shared/references/document-format-tasks.md).
Для refactoring используй [его предмет проверки](../references/refactoring.md#ревью-и-согласование);
отсутствие specs не является дефектом.

1. Сверь состав комплекта, журнал, вопросы и результат архитектора. Передай [explorer](../references/explorer.md)
   структурный check documents без плана или plan при наличии tasks. Однозначные
   структурные ошибки передай архитектору и повтори проверку до успешного
   результата. Существенные развилки покажи пользователю. По явному запросу
   пользователя ревью допускается с открытыми вопросами; включи их во входы.
2. Прочитай индекс sdd/arch-lenses/index.md. Назначь consistency, simplicity,
   premortem и проектные линзы; при наличии плана добавь plan. Для каждой линзы
   нужен отдельный чистый контекст, simplicity выполняется один раз. Повреждённый
   индекс исправь по общему контракту. Отсутствие плана до его подготовки не дефект.
3. Примени [настройки субагентов](../../sdd-shared/references/subagents.md):
   используй sdd-spec.reviewer для всех линз, включая plan в общем ревью комплекта.
   Для simplicity подготовь [инструкции](../references/simplicity-instructions.md).
   Сохрани resolver selection и дополнение к заданию. После фактического запуска
   добавь его аргументы, context_id, trace и наблюдаемые model/effort; неизвестные
   значения оставь null. Храни эти свидетельства рядом с отчётом в отдельном JSON
   текущего review run. Настройка модели не заменяет разрешения на ревью.
4. Учти [выбор гуманизации](../references/editorial-pass.md). Заверши авторские
   правки через [checkpoint](../references/checkpoint.md). Покажи состав комплекта,
   линзы и ограничения. Получи согласие на этот запуск, если оно ещё не дано,
   и сохрани review_consent с run-id, stage: review, линзами и basis_commit.
   Отказ или отсутствие ответа не требуют waiver и не разрешают запуск.
5. Все рецензенты читают весь доступный комплект из одного неизменяемого дерева
   reviewed_commit: proposal, design, specs, research.md и tasks при наличии;
   для refactoring — proposal/design, research.md и tasks при наличии.
   Используй Git object reads или проверенную внешнюю копию. Передай пути,
   проектные ограничения, релевантные источники, журнал, открытые вопросы,
   точные ответы пользователя и решения агента с основаниями делегирования.
   Для принятых мер приложи исходные FIND и completion. Не передавай рассуждения
   автора и оценки других рецензентов о текущем комплекте.
6. Для plan используй [задание плана](../references/reviewer-plan.md), для остальных
   [контракт рецензента](../references/reviewer-documents.md) и выбранную линзу.
   При проверке программного дизайна обычного изменения или рефакторинга передай
   каждому рецензенту документов абсолютные пути [sdd-code-design](../../sdd-code-design/SKILL.md)
   и [диагностики](../../sdd-code-design/workflows/diagnose-code.md), предмет
   `proposed design` и явное поручение по контракту рецензента. Разрешай эти ссылки
   относительно данного флоу; проверь чтение до запуска. Недоступность
   зависимости оставляет эту проверку незавершённой. Для рефакторинга передай
   исходную и целевую структуру, критерии `result`/`preservation` с источниками
   и изменения групп тестов при наличии. Линза plan использует свой контракт
   без дополнительного вызова диагностики.
   Рецензенты только читают и возвращают отчёт; основной агент сохраняет файлы.
   Примени адаптер [Codex](../references/codex.md), [Claude Code](../references/claude-code.md)
   или [произвольного агента](../references/generic.md). При лимите контекстов
   запускай последовательно с одинаковыми входами.
7. Проверь фактически прочитанный комплект, reviewed_commit, полноту и ограничения
   каждого результата. Не объявляй неполное ревью успешным. Сохрани отчёты
   review/<run-id>/<lens-id>.md и сводку, затем отдельный checkpoint. Собственный
   OID коммита с отчётами не подставляй вместо прочитанного основания.
8. Покажи результат через [user-review](user-review.md). Рекомендации необязательны.
   Новые существенные вопросы требуют решения пользователя или нового поручения
   по показанному списку. Прежнее делегирование их не охватывает.

Завершение: отчёты сохранены с истинным основанием и ограничениями; пользователь
видит результат и открытые вопросы. Ревью не утверждает комплект и не запускает
план. После закрытия вопросов предложи написать отсутствующий план либо выбрать
между ревью текущего комплекта и его утверждением, если план уже готов.
