# Пересмотр

После завершённой правки документов предложи [гуманизацию](../references/editorial-pass.md)
и учти сохранённый выбор пользователя; выполняй её только в согласованной области.
Исходные отчёты ревью и ответы пользователя сохраняй дословно.

1. Выбери изменение и проверь полномочия через [resume](resume.md). Прочитай все существующие proposal, capability-specs, design, tasks, state и историю решений. Для существенной переработки перечитай [формат](../references/document-format.md), соответствующий шаблон и источники с диска.
2. Начни с запрошенной правки либо проверки согласованности. Прочитай [правила обсуждения](../references/discussion.md), журнал decisions.md и questions.md при наличии. Запиши авторство и основание нового выбора; при замене сохрани прежнее решение и связь с новым. Проверь связи в обоих направлениях: изменение design/tasks может потребовать поправки specs и границ proposal. Порядок создания документов не ограничивает направление пересмотра.
3. При изменении цели, существенной предпосылки или противоречащих данных пересмотри затронутую часть [премортема](../references/premortem.md), сохраняя остальные выводы. Выбранное пользователем изменение поведения отрази в specs с AC и связанных proposal/design. Правка только premortem.md не меняет нормативный манифест; проверь, не требует ли её смысл нормативной правки.
4. Покажи необходимые содержательные изменения и причины. Явная просьба внести конкретную правку или согласованный disposition уже разрешает работу в этой области: не спрашивай повторно о каждом файле. Новый выбор поведения, расширение объема или смена цели требуют отдельного решения. При смене цели предложи отдельное изменение, не подменяй старое.
5. Редактируй только существующие артефакты и сохраняй незатронутое содержание. Если комплект уже согласован и исправлять нечего, не переписывай файлы. Отсутствующий документ обозначь и уточни дальнейшую область подготовки; отсутствующий tasks не создавай без команды планирования.
6. Выполни соответствующую структурную проверку; автоматически исправь однозначные ошибки без изменения смысла. Сверь манифесты: любая правка общего комплекта делает устаревшими все ревью этой стадии и прежние согласования версии. Разрешение закончить порученные исправления при этом сохраняется в прежнем scope.
7. Для существующего пояснения сравни полный snapshot documents с archify/index.md по [контракту пояснения](../references/explanation.md). Учитывай добавленные и удалённые specs. До обновления затронутых частей и сверки остальных пометь пояснение и индекс устаревшими; новый манифест сохрани только после сверки всего комплекта. Отдельно проверь привязку снимков к текущему HTML. Обновление выполняй через [explain](explain.md) в порученной области; само наличие пояснения её не расширяет. Правка только производных материалов не делает устаревшим согласование неизменённых нормативных документов.
8. Проверь происхождение существенных положений после правки по discussion. Обнови вопросы и checkpoint, сохрани результаты исправлений отдельно от исходных ответов, перечисли измененные файлы и все stale/missing ревью. При открытом существенном выборе продолжи обсуждение через explore. После его завершения предложи повтор через [user-review](user-review.md); предыдущий запуск не разрешает повтор автоматически.

Завершение: все существующие связанные документы проверены, согласованная область исправлена либо указан конкретный нерешенный вопрос, актуальность пересчитана; код не изменен.
