# Рассмотрение результатов

После завершённой правки документов предложи [гуманизацию](../references/editorial-pass.md)
и учти сохранённый выбор пользователя; выполняй её только в согласованной области.
Исходные отчёты ревью и ответы пользователя сохраняй дословно.

Созданную или изменённую производную сводку отредактируй перед показом пользователю
и предложением выбора по находкам. Подтверждённые USER-ответы в эту правку не включай.

1. Прочитай исходные отчеты, текущий комплект и `review/decisions.md`; пересчитай актуальность. Создай производную сводку по [шаблону](../templates/review-summary.md). Объединяй дубли только здесь, сохраняя полные ссылки `<run-id>/<lens-id>/<FIND-ID>` на каждую исходную находку. Покажи расхождения рецензентов, не прячь их за общим вердиктом.
2. Новая находка повторного запуска имеет новую полную ссылку. Запиши в сводке `related_to` со всеми относящимися прежними ссылками, но не переноси прежнее пользовательское решение. ID уникален внутри отчета; одинаковый смысловой FIND-ID разных отчетов допустим.
3. Предложи по всем находкам выбор: исправить, отклонить с причиной или отложить с причиной и конкретным `return_at`. Групповое решение допустимо, если перечислены все полные ссылки. Молчание, предложение агента или прежнее решение по related_to не являются ответом.
4. Сохрани явный ответ отдельной USER-записью по [decisions](../templates/decisions.md): вид, scope, текст ответа, дата, ссылка на сообщение при наличии, исходный манифест; для disposition — ссылки и действие. Не придумывай сообщение или авторство. Историю не переписывай; выполнение исправлений фиксируй отдельно со ссылками на документы.
5. Выполни выбранные исправления через [revise](revise.md). Разрешение относится ко всей перечисленной работе, сохраняется после ожидаемых изменений файлов и перерыва; новая находка или расширение scope требуют нового решения. Не требуй повторного подтверждения оставшегося исправления только из-за измененного хеша.
6. Перечисли все stale/missing ревью, предложи повтор и получи отдельное согласие на новый запуск. Выбор части линз не разрешает пропустить остальные: для продолжения без них нужен явный waiver текущей версии и точной области. Сохраняй новые отчеты отдельно. Отмена/замена поручения пользователем прекращает прежнюю работу в затронутой области; сохрани этот ответ и обнови checkpoint, не возобновляй его из старой записи.
7. После обработки находок предложи согласование текущих specs/design отдельной `document_approval`. Согласование версии, waiver и разрешение работать имеют разный срок действия: approval/waiver требуют совпадения комплекта, consent — конкретного запуска, disposition/planning_command — неоконченной разрешенной области. «Все хорошо» в неоднозначном контексте уточни, а не преобразуй в несколько разрешений.
8. После согласования документов сохрани ожидание команды планирования. Вопросы и новые материалы допустимы без перехода к tasks. Для финального согласования плана используй условия [plan](plan.md).
