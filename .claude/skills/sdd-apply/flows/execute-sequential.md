# Sequential execution

Read [task events](../references/api-tasks.md), [checks and evidence](../references/api-checks.md), and [role coordination](../references/role-coordination.md) if not already loaded. Keep the parallel flow unloaded.

1. Ask the `available` operation for admission. Maintain one unfinished task. If a previous task is running, verifying, reviewing, repairing, committing or blocked, continue it; do not admit another task. A blocked current task blocks the entire run, even when other dependencies would permit work.
2. Submit `worktree_create` with a workspace outside skill collections. Register the task's complete checks and inspected project/CI inventory. Launch a fresh executor using [executor](../agents/executor.md) and the host adapter. Pass the assigned worktree, register its observed launch, send its generated packet, then submit `start` with explicit owned paths. Before the executor writes, launch/register an independent verifier and run `check_run` at stage `baseline` on the clean starting commit. Record planned absence only for approved setup requirements.
3. Let the executor implement in its worktree. Save `role_result`, confirm writing stopped, and submit `candidate` to create the local candidate commit. Run the assigned self-checks against that commit. Handle failure through [repair](repair.md); each changed result needs a new candidate commit and fresh checks.
4. Launch a fresh independent [verifier](../agents/verifier.md), register the real context, and run `check_run` with stage `independent`. If checks are unavailable, block. If they fail, reserve repair before editing or retrying.
5. Launch/register a fresh [reviewer](../agents/reviewer.md), or a second role ID in the same independent verifier context only when their [agent selections](../references/subagents.md) have matching launch identities. Reserve `review_start` before substantive review. Save its `review_result`; apply [repair](repair.md) for changes or more checks. Count every new substantive review against the same task budget.
6. After passing worktree evidence and review, call `transfer` then `integrate`. Preserve the worktree and recorded intent if integration conflicts; use [worktree recovery](../references/worktree-recovery.md) and the supported resolution events. Submit `candidate` to commit the integrated result, run independent checks at stage `integration`, and obtain a passing integration review within the same task budget. Call `commit` to confirm that reviewed commit, inspect its SHA, then call `accept`. A local commit alone is not acceptance.
7. After acceptance and all roles stop, call `worktree_remove`. Preserve the tree if cleanup finds unknown data. Only after `accepted`, request the next available task. After all tasks are accepted, use [finalize](finalize.md).

For a resumed execution with multiple previously started tasks, admit no new task until those tasks have been resolved under the current approved mode. Preserve any mode-switch blocker and its evidence.
