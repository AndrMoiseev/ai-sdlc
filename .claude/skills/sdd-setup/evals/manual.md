# Проверки sdd-setup

Применяй этот документ только при изменении или проверке самого скилла.

Детерминированные тесты, включая сериализацию обеих сред:

```text
uv run --locked --script "<skill-root>/scripts/test.py" -q
```

Для проверки установки с пустым онлайн-кэшем включи `SDD_SETUP_RUNTIME_TESTS=1`
на время тестового процесса. Эти тесты запускают uv и могут обращаться к PyPI;
они не запускают модели. Нативный Claude Code проверяется отдельно ниже.

## Поведенческие сценарии

В [evals.json](evals.json) четыре сценария. Для каждой пары скилл/контроль создай
свежий каталог вне репозитория и коллекций скиллов. Кандидату скопируй полные
`sdd-setup` и `sdd-spec` рядом, сохрани manifest зависимостей вне контекста
исполнителя. Контролю не раскрывай скилл, ответы или критерии. Используй один
хост и модель; записывай недоступную телеметрию как null.

Для микротестов проведи пять независимых повторов fresh-project с инструкциями
и пять без них. Это проверяет формирование диалога; не называй такой тест
подтверждением фактической записи или выбора модели хостом. В полном сценарии
после таблицы ответь «принимаю показанные пресеты» и проверь файлы. Для
stale-plan меняй settings после plan до apply. Discovery пропускается:
скилл вызывается явно.

## Нативный Claude Code — запуск пользователем

Работай в отдельном временном проекте. Установи полные `sdd-setup` и `sdd-spec`
рядом в `.claude/skills`, сохрани обычные разрешения среды. Нужны uv и доступ к
моделям, выбранным в диалоге. Не используй реальные ключи в тестовых файлах.

1. В новой сессии вызови `/sdd-setup`. Убедись, что предложены восемь общих имён
   и пресеты Claude из `assets/defaults.json`, с выбором модели и effort.
2. Прими показанные пресеты. Проверь восемь `.claude/agents/*.md` и
   `.sdd/settings.json`. Повтори setup с сохранением значений: содержимое
   и время изменения файлов должны остаться прежними.
3. Измени model одного агента, оставив effort. Проверь сохранение тела, комментариев,
   tools и прочих полей. Если определение пользовательское, должна появиться
   только проектная копия.
4. Настрой тем же мастером проект, уже настроенный в Codex. Назначения ролей
   сохраняют имена, TOML-файлы — байты; `.claude/agents` получает пресеты Claude.
5. Проверь агент из plugin/managed/CLI каталога без локального файла. При
   сохранении имени дубликат не создаётся. Попытка изменить модель предлагает
   новое проектное имя или проверку реального источника.
6. Проверь новые имена в Agent tool. При необходимости перезапусти сессию.
   Запусти выбранному агенту задачу «17 + 25» и сохрани реальную трассу,
   имя и модель/effort из метаданных хоста. Самоопределение агента не является
   проверкой. Если метаданные скрыты, отметь их как неизвестные.

В отчёте запиши версию Claude Code, способ установки, пресеты/замены, вывод
inspect/plan/apply, исходный и конечный каталог, изменённые файлы и runtime-поля.
Эти сценарии не выполняются Python-тестами.

## Источники для сопровождения адаптеров

Схема Codex сверена с [документацией custom agents](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents),
формат и приоритеты Claude Code — с [документацией subagents](https://code.claude.com/docs/en/sub-agents).
При изменении адаптеров сверяй их с этими источниками.
При разработке Claude Code на машине разработчика не запускался; сценарии
нативной проверки приведены выше.
