# План перехода на Git-чекпойнты

Основание: [согласованные решения](decisions.md).
Статус: план подготовлен; задачи реализации не выполнялись.

## Результат

Скиллы используют принятый Git-коммит и контролируют следующий переход.
Незакоммиченные изменения на входе требуют выбора пользователя: удалить
или закоммитить. Неожиданное расхождение `HEAD` с принятой точкой показывается
пользователю. Его подтверждение устанавливает новую принятую точку и снимает
возражения к состоянию, сохраняя границы действующего поручения.

Сохранённые версии отдельных документов в манифестах заменяются ссылками
на коммиты. Проверка всех исторических согласований не становится условием
продолжения. Информирование о последствиях изменений сохраняется.

## 1. Определить общий контракт

- [ ] Описать принятую точку, текущий `HEAD`, незавершённые изменения и область
  поручения. Разделить принятие состояния и разрешение следующей работы.
- [ ] Определить размещение Git-ссылки на основе согласованного
  `refs/sdd/checkpoints/<change-id>` с защитой от смешения видов работ и worktree.
- [ ] Зафиксировать переходы: первый запуск, чистое совпадающее состояние,
  грязное дерево, неожиданный `HEAD`, подтверждение пользователя, собственный
  чекпойнт, пустой чекпойнт, сбой между commit и обновлением ссылки.
- [ ] Определить формат записи подтверждения и ссылок отчётов на коммиты,
  версию схемы и обработку старых пакетов. Не сохранять собственный commit ID
  внутри порождающего его коммита.
- [ ] Определить замену `inputs`, `inputs_after`, сохраняемых манифестов и
  `checks.freshness`. Отделить диагностические сведения от блокирующих условий.

Готово, когда каждое состояние имеет однозначный следующий шаг и формат
не требует циклического вычисления хэша или повторного одобрения принятого состояния.

## 2. Реализовать операции Git в sdd-shared

- [ ] Добавить общий адаптер для чтения `HEAD`, принятой ссылки, статуса
  репозитория и списка изменений. Учитывать индекс, unstaged, untracked,
  удаления и переименования; корректно обрабатывать пробелы и Unicode в путях.
- [ ] Разделить чтение состояния, принятие коммита и создание чекпойнта.
  Операции принятия выполняются только при наличии решения вызывающего агента;
  скрипт не может сам устанавливать факт согласия пользователя.
- [ ] Создавать коммит только из проверенного набора изменений и проверять
  итоговое дерево. Не использовать безусловное добавление всех файлов.
- [ ] Проверять ожидаемые `HEAD` и старое значение ссылки перед изменениями.
  При гонке возвращать диагностику и сохранять данные.
- [ ] Обработать отказ commit/hook, отказ обновления ref и частично завершённый
  чекпойнт без ложного сообщения об успехе и без автоматического удаления работы.
- [ ] При отсутствии изменений не создавать пустой коммит. При отсутствии Git
  или исходного коммита возвращать понятный следующий шаг.

Готово, когда операции имеют проверяемые результаты и не изменяют принятую
точку при ошибке до создания коммита; частичные сбои явно различимы.

## 3. Перевести машинный формат и проверки

- [ ] Обновить `skills/sdd-shared/scripts/sdd_shared/documents.py` и
  `reviews.py`, связанные схемы и CLI под новый контракт.
- [ ] Пересмотреть `snapshots.py` и его потребителей: убрать сохраняемые
  манифесты документов из нового пути работы. Не удалять хэши других артефактов,
  если они решают самостоятельную задачу, например привязку проверки к HTML.
- [ ] Заменить автоматическое блокирование по историческим хэшам на проверку
  принятой точки и текущего перехода. Не превращать подтверждение состояния
  в разрешение новых действий.
- [ ] Обеспечить понятную обработку старого формата: сообщить о необходимости
  установления новой принятой точки; не переносить старое согласование молча.
- [ ] Обновить шаблоны state, отчёта ревью и пользовательских решений.

Готово, когда новый пакет читается всеми потребителями без требования старых
манифестов, а старые данные не интерпретируются как несуществующее подтверждение.

- [ ] Сохранить различие принятого состояния, согласованного плана и поручения

- [ ] Найти остальные потребители snapshot/inputs/freshness в SDD-скиллах;

Готово, когда согласованный переход между скиллами не требует одновременно
старого и нового форматов и не теряет действующее поручение.

## 6. Проверить скрипты автотестами

Автоматические эвалы агентов не добавлять и не запускать. Все проверки этого
плана — автотесты скриптов; модельные прогоны и эвал-инфраструктура исключены.

- [ ] Сначала использовать существующие тесты и фикстуры: в `sdd-spec` —
  `test_snapshots.py`, `test_authorizations.py`, `test_review_records.py`,
  `test_questions.py`, `test_template_contract.py`, `test_package_contract.py`;
  в `sdd-shared` — тесты общего формата и рефакторинга; в `sdd-apply` —
  `test_inputs.py`, `test_refactoring_inputs.py` и связанные регрессии.
- [ ] Проверить матрицу переходов модульно через Git-адаптер: отсутствие ссылки,
  совпадение/расхождение `HEAD`, грязное дерево, пользовательское подтверждение,
  отсутствие подтверждения, пустой чекпойнт, гонки и частичные сбои.
- [ ] Проверить, что подтверждение коммита снимает возражение к состоянию,
  но не принимает незакоммиченные правки и не расширяет поручение.
- [ ] Проверить формат, корректность диагностики, выбор проверенного набора
  файлов, сохранение чужих правок и отсутствие побочных записей при ошибках.
- [ ] Обосновать минимальные тесты с настоящим Git: реальная семантика индекса,
  commit и update-ref не должна подтверждаться только имитацией адаптера.
  Использовать существующую фикстуру, если она покрывает границу. Комбинации
  бизнес-правил и варианты ошибок проверять без запуска процессов.
- [ ] Для каждого нового интеграционного теста указать конкретный риск и почему
  модульного теста или существующего адаптера недостаточно.
- [ ] Прогнать обязательный последовательный набор каждого затронутого скилла
  до добавления тестов и после изменений. Зафиксировать точные команды, состав,
  состояние кэша, результаты и полное время каждого набора отдельно.

Окружение: запускать Python через uv по `AGENTS.md`, сохранять кэши, временные
репозитории и результаты вне проекта и коллекций скиллов. Использовать уникальный
абсолютный `--basetemp`; первый запуск после изменения окружения — с `-x`.
Для известного ограничения Windows pytest заранее запросить штатное разрешение
среды на конкретную команду, как предписывает `AGENTS.md`.

Лимит каждого обязательного набора одного скилла — 60 секунд реального времени
включая подготовку и запуск среды. Если лимит превышен, остановить прогон и
работу, сообщить команду, время и известную причину; продолжить только после
нового указания пользователя. Исходное превышение требует оптимизации до
добавления тестов. Разбиение набора на команды не обнуляет лимит.

## Приёмка

- [ ] Дополнительный коммит обнаруживается при чистом дереве после перезапуска.
- [ ] Грязное дерево на входе приводит к выбору пользователя «удалить или
  закоммитить»; автоматического удаления или продолжения нет.
- [ ] Подтверждённый пользователем текущий коммит становится принятой точкой.
- [ ] Собственный чекпойнт фиксирует проверенные изменения, оставляет чистое
  дерево и совпадающие `HEAD` и ссылку. Пустой чекпойнт не создаёт коммит.
- [ ] Агент сообщает о выходе за поручение; подтверждение состояния не
  подменяет поручение на новую работу.
- [ ] Форматы и потребители не требуют отдельных хэшей нормативных документов
  и повторного доказательства всей истории согласований.
- [ ] Автотесты скриптов проходят в установленном лимите; пакеты не содержат
  кэшей, bytecode, временных репозиториев или отчётов тестов.
- [ ] Автоматические эвалы агентов не входят в выполненные работы или требования
  приёмки этой доработки.
