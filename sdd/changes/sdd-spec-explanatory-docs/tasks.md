# План реализации

Основания: согласованные [требования](specs/solution-explanation/spec.md)
и [дизайн](design.md), команда USER-plan-explanation.
Реализация инструкций и локальные проверки завершены. По уточнению
пользователя «только локальные проверки» сравнительные поведенческие прогоны
через Codex CLI исключены из текущей проверки. Их сценарии сохранены, результаты
прохождения не заявляются. Итоговые свидетельства и ограничения записаны
в [отчёте реализации](implementation-report.md).

## Порядок и общие условия

Задачи выполняются последовательно по depends_on. Их общие файлы:
flows/explain.md, references/explanation.md и evals/evals.json внутри
skills/sdd-spec/. Изолированные участки для одновременной записи не выделены;
цепочка зависимостей предотвращает конфликт правок. Отдельные ограничения
cannot_parallel_with не нужны.

Перед первой правкой сохранить прежний пакет и подготовить проверочные
сценарии по sdd-skill-conductor. Для каждой задачи сравнить прежние
и новые инструкции в свежих контекстах по назначенным ей критериям. Одинаковый
вход и одна среда запуска нужны обеим версиям. До сравнения проверить изоляцию:
прежняя версия не должна обнаруживать новые инструкции через каталог скиллов
или родительский каталог. При ограничении native-среды использовать отдельный
CLI-запуск по процедуре conductor. Явный режим вызова sdd-spec сохраняется;
проверка автоматического обнаружения скилла не требуется.

Фикстуры и результаты прогонов хранить вне исходных и установленных каталогов
скиллов. Артефакты сценария находятся в archify/ его тестового изменения.
Сохранять фактические результаты, ограничения, длительность и доступные метрики
по conductor; его обязательные сравнения и разбор результатов входят в каждую
задачу. Эти шаги не вынесены в отдельную задачу тестирования.

Подставленные ответы инструментов допустимы для проверки ветвления инструкций.
Они не подтверждают генерацию HTML, читаемость меток или работу браузера.
Для таких утверждений нужны реальные проверки archify и осмотр снимков.
Если нужная среда недоступна, сохранить непройденный сценарий и способ запуска,
указать ограничение и не отмечать соответствующую проверку успешной.

После правок инструкций проверить их через writing-for-agents и провести
редактуру русской авторской прозы по принятому процессу. archify, sdd v1
и скрипты check/snapshot сохраняются без изменений.

### Создать пояснение с диаграммами и переносимыми артефактами

```yaml
sdd_record: task
id: TASK-explanation-diagrams
number: 1
covers:
  - AC-explanation-coverage
  - AC-diagram-types-and-dependency
  - AC-visible-independent-statuses
  - AC-portable-artifact-layout
depends_on: []
status: done
verification:
  - criteria: [AC-explanation-coverage, AC-diagram-types-and-dependency]
    test_description: По явному запросу создать пояснение с несколькими процессами и сценариями, неизвестным исходным поведением и неприменимым представлением; отдельно выполнить случай без archify.
    location: skills/sdd-spec/evals/evals.json
    run:
      setup_required: Добавить случаи explanation-content и explanation-missing-archify, подготовить изолированные фикстуры и выполнить парные прогоны по conductor с проверкой выходных документов и вызванных типов диаграмм.
  - criteria: [AC-visible-independent-statuses]
    test_description: На реальных диаграммах проверить независимые статусы узлов и связей, изменённое сообщение прежнего участника, возврат и видимость меток на HTML и снимках.
    location: skills/sdd-spec/evals/manual.md
    run:
      setup_required: Добавить процедуру explanation-markers, подготовить среду с доступным archify и браузером, сгенерировать три типа диаграмм, выполнить проверку со снимками и осмотреть метки.
  - criteria: [AC-portable-artifact-layout]
    test_description: Разделить пояснение на несколько документов, сохранить разные диаграммы и результаты повторной проверки, перенести каталог изменения и проверить каждую ссылку и сохранность прежних файлов.
    location: skills/sdd-spec/evals/evals.json
    run:
      setup_required: Добавить случай explanation-portable-layout, выполнить его в изолированной фикстуре, перенести её копию в другой каталог и проверить относительные ссылки, стабильные ID и сохранность результатов.
```

### Вставлять превью из проверки archify

```yaml
sdd_record: task
id: TASK-checked-previews
number: 2
covers: [AC-preview-from-check]
depends_on: [TASK-explanation-diagrams]
status: done
verification:
  - criteria: [AC-preview-from-check]
    test_description: Выполнить проверку со снимками в среде с браузером, осмотреть PNG, вставить кликабельное превью и повторить запрос при уже имеющихся актуальных результатах.
    location: skills/sdd-spec/evals/manual.md
    run:
      setup_required: Добавить процедуру explanation-checked-preview и выполнить её на реальном HTML из первой задачи. Проверить привязку результатов к HTML, читаемость снимка, ссылки из обоих вариантов размещения документов и отсутствие повторной генерации актуального PNG.
```

Дополнить flows/explain.md, references/explanation.md и templates/explanation.md
веткой доступного браузера. Получать снимки при предусмотренной archify проверке;
проверка без снимков сама по себе не закрывает получение превью.

Использовать реальные пути из результата инструмента. До вставки сверять
привязку к текущему HTML и осматривать изображение. Для большой диаграммы
допускать несколько снимков, если один обрезает значимую часть или делает
метки нечитаемыми. Проверить кликабельность превью из explanation.md
и документов внутри explanation/.

В index.md сохранять пути выбранных изображений и проверок, фактический статус
браузерной проверки и осмотра. Уже пригодные снимки использовать повторно
по правилам archify. Добавить поведенческий случай explanation-preview-reuse
в evals/evals.json; подставленный ответ проверки помечать отдельно от реального
прогона, предусмотренного verification.

```yaml
    test_description: Передать свежей среде только каталог изменения и промпт, завершить недостающие превью при частично готовом наборе, затем повторить запрос и сравнить результат.
```

```yaml
sdd_record: task
id: TASK-explanation-freshness
number: 4

  - AC-stale-explanation-on-revision
  - AC-preview-keeps-normative-manifest
depends_on: [TASK-preview-handoff]

verification:
  - criteria: [AC-stale-explanation-on-revision]
    test_description: После создания пояснения изменить design, добавить или удалить spec и продолжить через revise, resume либо промпт превью; проверить, что устаревший комплект выявлен до выдачи диаграмм как актуальных.
    location: skills/sdd-spec/evals/evals.json
    run:
      setup_required: Добавить случай explanation-stale-inputs с отдельными фикстурами трёх видов изменения манифеста. Выполнить парные прогоны; проверить отметки устаревания, сверку затронутых и сохранённых частей и момент записи нового манифеста.
  - criteria: [AC-preview-keeps-normative-manifest]
    test_description: В фикстуре с согласованными документами заменить заглушку на превью, сравнить нормативные байты и snapshot до и после, затем проверить сохранение document_approval.
    location: skills/sdd-spec/evals/manual.md
    run:
      setup_required: Добавить процедуру explanation-approval-preserved, выполнить замену через новый маршрут и запустить штатные snapshot и check documents для фикстуры до и после. Проверить совпадение манифестов и применимость исходного согласования.
```

В flows/revise.md, flows/resume.md, explain и промпт продолжения добавить сверку
манифеста из index.md со всеми текущими proposal, design и specs. При несовпадении
отмечать пояснение как устаревшее. Новый манифест сохранять после обновления
затронутых частей и проверки применимости остальных.

Отдельно сверять результаты archify с текущими байтами HTML. Добавить случай
с прежним PNG и изменившимся HTML: совпадения SDD-манифеста недостаточно для
выдачи такого PNG за актуальный. Изменения внешнего кода оценивать по необходимости,
не обещая их автоматического отслеживания через snapshot документов.

Закрепить в references/document-format.md исключение производных файлов
из нормативного манифеста. Новое обязательство, обнаруженное при обновлении
пояснения, обрабатывается обычным revise; согласование требований не переносится
на изменившуюся версию. Скрипты snapshots.py и check.py не менять.

```yaml
  - criteria: [AC-reuse-explanation-request]

    location: skills/sdd-spec/evals/evals.json
    run:
      setup_required: Добавить случай explanation-existing-request, выполнить его со свежими контекстами и сохранённым выбором. Проверить создание порученного пояснения, отсутствие лишнего запроса и сохранение отдельных условий ревью и планирования.
```

В resume учитывать сохранённый выбор и уже выполненную часть поручения.

отказ не вызывает повторного предложения той же версии, а существующее
пояснение само по себе не разрешает новую область. Блокирующие вопросы основного
комплекта сохраняют значение, даже если для черновика создано пояснение.

Завершить примеры вызова и описания маршрутов в SKILL.md и README.md.
Выполнить проверки пакета из исходной и перемещённой копий, из внешнего рабочего
каталога. Использовать штатный запускатель с внешними кэшами. Полную регрессию
запустить командой `python skills/sdd-spec/scripts/run.py test`; сценарии поведения

сохраняя единственного ответственного за каждый AC.
