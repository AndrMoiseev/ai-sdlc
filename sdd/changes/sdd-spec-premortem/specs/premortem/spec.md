# Премортем изменения

Это новая capability. Она добавляет обязательную проверку предпосылок
результата к существующим правилам исследования и вопросов SDD.

### Короткая проверка каждого изменения

```yaml
sdd_record: requirement
id: REQ-premortem-entry
operation: add
```

Когда известны цель и контекст изменения, агент проводит короткий мысленный
премортем до подробной спецификации. Он рассматривает возможную причину,
по которой реализованное изменение не даст ожидаемого результата. Проверка
нужна и для малого изменения. Прямой вход в draft не позволяет её пропустить.
Актуальный ранее выполненный разбор используется повторно без нового интервью.

### Вход через исследование

```yaml
sdd_record: acceptance
id: AC-premortem-explore
requirement: REQ-premortem-entry
conditions: В explore определены цель и контекст нового изменения.
expected: До подробной спецификации агент проводит премортем и сохраняет его итог.
```

### Прямой вход в подготовку документов

```yaml
sdd_record: acceptance
id: AC-premortem-direct-draft
requirement: REQ-premortem-entry
conditions: Пользователь сразу просит документы, актуального итога премортема нет.
expected: Агент проводит короткую проверку до подробной спецификации; отсутствие explore не считается основанием для пропуска.
```

### Проверка малого изменения

```yaml
sdd_record: acceptance
id: AC-premortem-small-change
requirement: REQ-premortem-entry
conditions: Изменение исправляет опечатку, цель ясна, доступный diff подтверждает отсутствие изменения поведения.
expected: Агент сохраняет краткий итог проверки без отдельного интервью и без выдуманных находок.
```

### Основания находок и вопросы

```yaml
sdd_record: requirement
id: REQ-premortem-evidence
operation: add
```

Находка связывает конкретный возможный провал с предпосылкой успеха.
Агент различает факты, гипотезы и недостающие сведения, изучает доступные
источники до вопроса пользователю. Вопрос возникает только при конкретной
существенной неопределённости. Из нескольких вопросов выбирается ближайший,
влияющий на решение. Обязательного количества находок или вопросов нет.
Недоступный источник не считается подтверждением предпосылки.

### Ответ в доступном источнике

```yaml
sdd_record: acceptance
id: AC-premortem-known-answer
requirement: REQ-premortem-evidence
conditions: Основание предполагаемого риска можно проверить по доступному документу проекта или сохранённому ответу пользователя.
expected: Агент читает источник, учитывает найденный ответ и не просит пользователя повторить его.
```

### Существенный пробел

```yaml
sdd_record: acceptance
id: AC-premortem-unknown-assumption
requirement: REQ-premortem-evidence
conditions: Для автоматического отчёта задана периодичность, но неизвестно, какое решение получатель принимает по его данным; доступные материалы этого не объясняют.
expected: Агент обозначает гипотезу о бесполезности отчёта и задаёт вопрос о его назначении, не выдавая гипотезу за факт.
```

### Отсутствие заданного числа находок

```yaml
sdd_record: acceptance
id: AC-premortem-no-quota
requirement: REQ-premortem-evidence
conditions: Короткая проверка по доступным вводным не выявила существенных находок.
expected: Агент фиксирует отсутствие находок и продолжает работу; он не дополняет список общими опасениями ради количества.
```

### Краткий итог и отдельный документ

```yaml
sdd_record: requirement
id: REQ-premortem-storage
operation: add
```

Раздел «Премортем» в state.md содержит только краткий итог: отсутствие находок
либо наличие находок со ссылкой на premortem.md в каталоге изменения.
Сценарии, основания и решения по находкам в этом разделе не дублируются.
Обычные записи вопросов SDD в state.md сохраняются.

premortem.md создаётся только при находках. Он содержит цель и границы разбора,
а для каждой находки описывает возможный провал, предпосылку, основания и
дальнейшее действие. Основания включают ссылки на источники и обозначенные
пробелы. Действие содержит доступную проверку, ссылку на Q-ID либо итог решения
с его основанием. Содержание существующего документа сохраняется при
обновлении; закрытые находки остаются с итогами и ссылками.

### Отсутствие находок при первой проверке

```yaml
sdd_record: acceptance
id: AC-premortem-empty-result
requirement: REQ-premortem-storage
conditions: Премортем выполнен, находок нет, premortem.md ещё не существует.
expected: 'В state.md записано «Премортем: находок нет»; premortem.md не создаётся.'
```

### Сохранение находки

```yaml
sdd_record: acceptance
id: AC-premortem-findings-document
requirement: REQ-premortem-storage
conditions: Премортем выявил существенную находку.
expected: Создан или обновлён premortem.md с четырьмя частями находки и контекстом; раздел премортема в state.md содержит только краткую отметку и рабочую ссылку на документ.
```

### Сохранение закрытых находок

```yaml
sdd_record: acceptance
id: AC-premortem-closed-history
requirement: REQ-premortem-storage
conditions: В premortem.md были находки, все они получили решение, новых находок нет.
expected: Документ и ссылка в state.md сохранены; краткий итог отмечает отсутствие открытых находок, а premortem.md содержит основания закрытия.
```

### Работа с последствиями находок

```yaml
sdd_record: requirement
id: REQ-premortem-disposition
operation: add
```

Находка, без ответа на которую пришлось бы угадывать цель, объём или поведение,
порождает блокирующий вопрос по существующим правилам SDD. Пока он открыт,
агент не фиксирует зависимое решение; независимую часть исследования или
черновика можно продолжать. До готовности документов к ревью блокирующий
вопрос закрывается. Отсрочка допустима только для неблокирующего вопроса
с причиной и условием возврата; эти сведения сохраняются в premortem.md
и соответствующей записи Q в state.md без расхождений.

Отдельное согласование каждой находки не требуется. Агент может снять
неопределённость по доступным источникам и сохранить основание. Принятие
оставшегося риска и изменение объёма требуют решения пользователя.
Новая функция не становится требованием только потому, что предложена
как ответ на риск. Выбранные изменения цели, поведения и подхода отражаются
в proposal, specs и design по их назначению.

### Блокировка зависимого решения

```yaml
sdd_record: acceptance
id: AC-premortem-block-dependent
requirement: REQ-premortem-disposition
conditions: Открытая находка требует решения пользователя об объёме, но другая часть черновика от этого решения не зависит.
expected: Создан блокирующий Q; зависимое решение не утверждается, независимая работа продолжается, документы не объявлены готовыми к ревью.
```

### Допустимая отсрочка

```yaml
sdd_record: acceptance
id: AC-premortem-defer
requirement: REQ-premortem-disposition
conditions: Находка не мешает текущему решению и её вопрос отложен.
expected: В premortem.md и записи неблокирующего Q совпадают причина и условие возврата; риск не объявлен принятым без решения пользователя.
```

### Защита объёма

```yaml
sdd_record: acceptance
id: AC-premortem-no-scope-growth
requirement: REQ-premortem-disposition
conditions: Для снижения риска агент предлагает новую функцию или принятие оставшегося риска, пользователь ещё не выбрал вариант.
expected: Предложение остаётся предложением; новая функция не включается в согласованный объём и риск не считается принятым.
```

### Продолжение и повторная проверка

```yaml
sdd_record: requirement
id: REQ-premortem-resume
operation: add
```

При resume агент читает краткий итог и, если есть ссылка, premortem.md.
Сохранённые выводы применимы, пока цель, границы и существенные основания
остаются актуальными. Смена сессии сама по себе не запускает новый разбор.
При изменении цели, существенной предпосылки или появлении противоречащих
данных агент пересматривает затронутую часть в explore, draft либо revise.

Если записи нет, она не позволяет восстановить область проверки или документ
по ссылке недоступен, завершённость премортема не считается подтверждённой.
Агент восстанавливает доступные сведения и выполняет короткую проверку;
обращение к пользователю определяется существенной неопределённостью.
Исчезновение источника не означает ни разрешения продолжить зависимое решение,
ни автоматического запроса на новое интервью.

### Продолжение без изменений

```yaml
sdd_record: acceptance
id: AC-premortem-resume-current
requirement: REQ-premortem-resume
conditions: Сессия возобновлена, итог и источники доступны, цель и существенные основания не изменились.
expected: Агент использует сохранённый разбор и ответы, не повторяет интервью и не создаёт дубли находок.
```

### Изменение основания

```yaml
sdd_record: acceptance
id: AC-premortem-revisit
requirement: REQ-premortem-resume
conditions: В revise или при продолжении изменена существенная предпосылка одной находки; остальные основания сохранены.
expected: Агент пересматривает затронутую часть, сохраняет остальные выводы и отражает последствия в зависимых документах.
```

### Отсутствующая запись или источник

```yaml
sdd_record: acceptance
id: AC-premortem-restore
requirement: REQ-premortem-resume
conditions: В старом изменении нет итога премортема либо документ по сохранённой ссылке недоступен.
expected: Агент не заявляет о завершённой проверке, восстанавливает доступные основания и выполняет короткий премортем; оставшийся существенный пробел оформляет вопросом.
```

### Граница с ревью и согласованием

```yaml
sdd_record: requirement
id: REQ-premortem-authority
operation: add
```

premortem.md служит материалом исследования и не входит в нормативный комплект
proposal, specs и design. Он не вводит новую стадию согласования и не заменяет
независимое ревью. Изменение только этого документа не меняет манифест комплекта.
Если находка меняет нормативное поведение, агент обновляет соответствующие
документы; действуют обычные правила устаревания ревью и согласований.

### Перенос изменения поведения в нормативный комплект

```yaml
sdd_record: acceptance
id: AC-premortem-normative-change
requirement: REQ-premortem-authority
conditions: После ревью пользователь выбирает по находке премортема изменение поведения.
expected: Агент обновляет spec с проверяемым AC и связанные документы; прежние ревью и согласования изменённого комплекта становятся устаревшими по обычным правилам.
```

### Сохранение границы процесса

```yaml
sdd_record: acceptance
id: AC-premortem-no-gate-bypass
requirement: REQ-premortem-authority
conditions: Премортем завершён, но независимое ревью или команда планирования ещё отсутствуют.
expected: Агент не подменяет отсутствующие основания результатом премортема и не создаёт tasks без разрешённого перехода.
```
