# Выполнение согласованного SDD-плана

## Проверенный вход

```yaml
sdd_record: requirement
id: REQ-approved-input
operation: add
```

Скилл начинает реализацию после явного поручения выполнить выбранное
изменение. Он предназначен для совместной работы с `sdd-spec`, который
готовит и согласует спецификации и планы. Новый скилл не подменяет этот
процесс при отсутствующих или неполных входах и не выполняет отдельный
проход автоматического переписывания проектных инструкций.
Проверяет текущий комплект, готовность документов и плана,
актуальные согласования и отсутствие блокирующих вопросов по правилам
`sdd-spec`. Статус в checkpoint и наличие файла задач не заменяют эти
основания. Читает инструкции проекта и фиксирует исходное состояние кода
и проверок. Если изменение неоднозначно, показывает кандидатов.

### Согласованный комплект

```yaml
sdd_record: acceptance
id: AC-approved-start
requirement: REQ-approved-input
conditions: Пользователь явно поручил выполнить выбранное изменение с актуальным согласованным планом
expected: Скилл сохраняет манифест входов и основание поручения, проверяет среду и начинает доступные задачи
```

### Отсутствующее или устаревшее основание

```yaml
sdd_record: acceptance
id: AC-invalid-input
requirement: REQ-approved-input
conditions: План существует, но согласование отсутствует, устарело или не выполнено другое условие готовности
expected: Реализация не начинается; сохранены конкретная причина и следующий шаг восстановления через sdd-spec
```

### Чужие изменения

```yaml
sdd_record: acceptance
id: AC-existing-work
requirement: REQ-approved-input
conditions: При запуске обнаружены незакоммиченные изменения или исходно падающие проверки
expected: Исходное состояние сохранено; чужие правки не удалены и не включены в результат задачи; затронутые работы отделены или заблокированы с причиной
```

### Постоянная граница ответственности

```yaml
sdd_record: acceptance
id: AC-companion-scope
requirement: REQ-approved-input
conditions: Скилл обрабатывает выбранное изменение от проверки входов до завершения исполнения
expected: Подготовка и пересмотр спецификации и плана остаются в sdd-spec; новый скилл их не создаёт и не запускает автоматическое переписывание проектных инструкций
```

## Автономное исполнение графа

```yaml
sdd_record: requirement
id: REQ-autonomous-execution
operation: add
```

После запуска скилл выполняет весь согласованный план без подтверждения
каждой задачи. По умолчанию используется последовательный режим: одновременно
ведётся одна задача, включая реализацию, проверки, ревью, исправления и коммит.
Следующая задача начинается после приёмки текущей либо её блокировки,
если следующая от неё не зависит.

Параллельный режим включается только по явному запросу пользователя для
текущего исполнения. Просьбы работать автономно или быстрее, независимые
задачи и доступные ресурсы таким запросом не считаются. Разрешение допускает
параллелизм при соблюдении зависимостей и изоляции; если это невозможно,
скилл сообщает причину и продолжает последовательно. Выбранный режим
и основание сохраняются. При продолжении того же исполнения прежний явный
запрос действует, пока не отменён; без подтверждённого запроса применяется
последовательный режим. Новое исполнение начинает с последовательного
режима, если пользователь явно не указал иное. При возврате к последовательному
режиму новые задачи не запускаются до завершения или блокировки уже активных.

Скилл использует TASK-ID, связи `depends_on`, `cannot_parallel_with`
и критерии `covers`. Задача доступна только после приёмки всех предшественников.
Каждая задача получает отдельного исполнителя с чистым контекстом, нужными
разделами документов, границами записи и условиями проверки. Оркестратор
ведёт исполнение и передаёт исправления исполнителям.

### Переход между задачами

```yaml
sdd_record: acceptance
id: AC-continue-plan
requirement: REQ-autonomous-execution
conditions: Предыдущая задача принята, осталась доступная задача согласованного плана
expected: Следующая задача запускается без нового согласия пользователя и с необходимыми входами
```

### Неуспешный предшественник

```yaml
sdd_record: acceptance
id: AC-block-dependents
requirement: REQ-autonomous-execution
conditions: Предшественник заблокирован, завершился ошибкой или ещё проходит ревью
expected: Зависимая задача не запускается; независимые доступные задачи могут продолжаться
```

### Разделение изменений

```yaml
sdd_record: acceptance
id: AC-isolated-work
requirement: REQ-autonomous-execution
conditions: Пользователь явно запросил параллельный режим, но изоляция изменений или проверок недоступна
expected: Скилл сообщает причину и выполняет задачи последовательно с соблюдением ограничений плана
```

### Последовательный режим по умолчанию

```yaml
sdd_record: acceptance
id: AC-sequential-default
requirement: REQ-autonomous-execution
conditions: Несколько независимых задач готовы к запуску и изоляция доступна, но пользователь не запрашивал параллельный режим
expected: Одновременно ведётся одна задача, включая проверки, ревью и исправления; следующий запуск не перекрывается с её выполнением
```

### Явный выбор параллельного режима

```yaml
sdd_record: acceptance
id: AC-explicit-parallel
requirement: REQ-autonomous-execution
conditions: Пользователь явно запросил параллельное выполнение, есть независимые задачи и доступна изоляция
expected: Скилл сохраняет запрос как основание режима и может запускать задачи одновременно в пределах зависимостей и ограничений изоляции
```

### Режим при продолжении

```yaml
sdd_record: acceptance
id: AC-mode-resume
requirement: REQ-autonomous-execution
conditions: Скилл продолжает прерванное исполнение с сохранённым режимом
expected: Параллельный режим сохраняется только при подтверждённом действующем явном запросе пользователя; иначе используется последовательный режим без перекрытия новых запусков с активными задачами
```

## Прогресс отдельно от согласованных документов

```yaml
sdd_record: requirement
id: REQ-execution-record
operation: add
```

Скилл сохраняет прогресс и доказательства отдельно от нормативного комплекта.
Запись исполнения связана с манифестом плана, TASK-ID и версией кода.
Для задачи видны состояние, попытки, проверки, замечания, коммиты, результат приёмки
и следующий шаг. У каждой проверки есть команда или процедура, результат,
ограничения и ссылка на проверенный материал. Вывод исполнителя считается
свидетельством, требующим проверки, а не самостоятельным основанием приёмки.

### Сохранение согласования

```yaml
sdd_record: acceptance
id: AC-stable-plan
requirement: REQ-execution-record
conditions: Задача запущена, проверена и принята
expected: Запись исполнения отражает прогресс, а байты proposal, specs, design и tasks и их исходный манифест не изменились
```

### Недостаточное доказательство

```yaml
sdd_record: acceptance
id: AC-no-unproven-done
requirement: REQ-execution-record
conditions: Исполнитель сообщает DONE без подтверждённой проверки обязательного критерия
expected: Задача остаётся непринятой; запись указывает, какого доказательства недостаёт
```

## Независимое ревью и исправления

```yaml
sdd_record: requirement
id: REQ-independent-review
operation: add
```

Каждая реализованная задача проходит независимое ревью соответствия
спецификации и качества кода с учётом правил проекта. Автор изменений
не рецензирует их. Замечания содержат проверяемое основание,
затронутый критерий или контракт и условие устранения. Блокирующие дефекты
исправляются в рамках задачи; рекомендации сохраняются для итогового
разбора и сами по себе не разрешают расширять объём.

Повторное ревью проверяет исправления и связанные последствия. Если правка
изменила более широкую область, область проверки расширяется. Результаты
ревью и тестов относятся к конкретной версии кода. Повторные неудачи
не приводят к бесконечному циклу: попытки и новые основания сохраняются,
при исчерпании установленного бюджета задача блокируется.

### Исправление дефекта

```yaml
sdd_record: acceptance
id: AC-review-repair
requirement: REQ-independent-review
conditions: Независимый рецензент обнаружил подтверждённое нарушение обязательного критерия
expected: Замечание передано исполнителю; задача принимается только после исправления, соответствующих проверок и повторного независимого ревью
```

### Изменение после проверки

```yaml
sdd_record: acceptance
id: AC-review-freshness
requirement: REQ-independent-review
conditions: После успешного ревью изменился код, от которого зависит проверенный результат
expected: Прежнее ревью не подтверждает новую версию; перед приёмкой выполнены затронутые проверки
```

### Ограниченная серия попыток

```yaml
sdd_record: acceptance
id: AC-bounded-repair
requirement: REQ-independent-review
conditions: Очередная попытка не устранила блокирующий дефект, бюджет попыток исчерпан
expected: Задача заблокирована с сохранением причин и результатов попыток; её потомки не запускаются
```

## Возврат к спецификации

```yaml
sdd_record: requirement
id: REQ-spec-revision
operation: add
```

Если реализация требует изменить поведение, критерий приёмки или обязательное
решение design, скилл сохраняет доказательство и затронутые задачи для
возврата в `sdd-spec`. Он не меняет согласованные документы и не принимает
новое требование самостоятельно. Локальные решения в разрешённых пределах
не требуют возврата. После согласования новой версии скилл сверяет
оставшуюся работу и применимость прежних результатов.

### Обнаруженное противоречие

```yaml
sdd_record: acceptance
id: AC-spec-conflict
requirement: REQ-spec-revision
conditions: Исполнитель доказал невозможность согласованного решения без изменения обязательного контракта
expected: Сохранены доказательство и затронутые задачи; соответствующая цепочка приостановлена; подготовлено обращение к sdd-spec без подмены документов
```

### Новый согласованный план

```yaml
sdd_record: acceptance
id: AC-revised-plan
requirement: REQ-spec-revision
conditions: После пересмотра получен новый согласованный комплект и поручение продолжить прежнюю работу
expected: Скилл фиксирует новое основание, пересматривает затронутые задачи и доказательства, сохраняет историю и продолжает оставшуюся разрешённую работу
```

## Продолжение после перерыва

```yaml
sdd_record: requirement
id: REQ-resume-execution
operation: add
```

Продолжение опирается на файлы и фактическое состояние репозитория.
Скилл сверяет согласование плана, код, незавершённую работу и доказательства.
Потерянный агент не считается активным только из-за сохранённого статуса.
Незавершённые изменения сохраняются; преемник получает выполненное,
оставшиеся критерии, принятые решения и отвергнутые подходы.
Результаты проверок повторно используются только при подтверждённой
применимости. Смена сессии не требует повторно разрешать уже порученную работу.

### Потеря исполнителя

```yaml
sdd_record: acceptance
id: AC-lost-executor
requirement: REQ-resume-execution
conditions: Сессия прервана во время задачи, прежний исполнитель недоступен
expected: Частичные правки и доказательства сверены и сохранены; новый исполнитель получает точку продолжения, а задача не остаётся фиктивно активной
```

### Внешняя правка документов

```yaml
sdd_record: acceptance
id: AC-resume-drift
requirement: REQ-resume-execution
conditions: При продолжении обнаружено неподтверждённое изменение нормативного комплекта
expected: Работа на прежнем основании не возобновляется автоматически; скилл показывает расхождение и что нужно для восстановления согласования
```

## Коммиты по задачам

```yaml
sdd_record: requirement
id: REQ-task-commits
operation: add
```

Результат исполнения плана сохраняется локальными коммитами по задачам.
Скилл проверяет доступность Git и ветку исполнения до начала реализации.
После успешных проверок и независимого ревью он создаёт отдельный коммит
реализации задачи с её TASK-ID и сохраняет SHA. Коммит содержит только
изменения этой задачи. Общий коммит нескольких задач не заменяет их
отдельные результаты. Только после подтверждения коммита задача принимается
и разблокирует зависимые задачи.

Последующие исправления по результатам интеграционной или итоговой проверки
сохраняются дополнительными коммитами с TASK-ID затронутой задачи,
проверками и ревью. Уже созданная история автоматически не переписывается.
При продолжении скилл сверяет историю Git и запись исполнения, чтобы
не повторить уже сделанный коммит. Ошибка коммита оставляет задачу непринятой.
Итоговый набор находится в локальной ветке исполнения; коммиты, оставшиеся
только в рабочих копиях исполнителей, не считаются переданным результатом.

### Отдельный проверенный коммит

```yaml
sdd_record: acceptance
id: AC-task-commit
requirement: REQ-task-commits
conditions: Реализация задачи прошла обязательные проверки и независимое ревью
expected: В ветке исполнения создан отдельный коммит с TASK-ID; сохранён SHA, содержимое соответствует проверенной задаче и не содержит чужих правок; затем задача принята
```

### Ошибка и повторное продолжение

```yaml
sdd_record: acceptance
id: AC-commit-recovery
requirement: REQ-task-commits
conditions: Создание коммита завершилось ошибкой либо сессия прервана между созданием коммита и записью его SHA
expected: Скилл сверяет историю и содержимое изменений, сохраняет найденный коммит без дублирования либо блокирует задачу с причиной; неподтверждённый коммит не закрывает задачу
```

### Исправление после коммита

```yaml
sdd_record: acceptance
id: AC-followup-commit
requirement: REQ-task-commits
conditions: Итоговая проверка обнаружила дефект в уже закоммиченной задаче
expected: Исправление проходит проверки и ревью и сохраняется новым коммитом с TASK-ID; исходный коммит остаётся в истории, запись приёмки обновляется
```

## HTML-дашборд прогресса

```yaml
sdd_record: requirement
id: REQ-progress-dashboard
operation: add
```

Скилл создаёт HTML-дашборд до запуска первой задачи и предоставляет
пользователю способ открыть его. Дашборд входит в обязательный объём.
Он показывает изменение, режим выполнения, время последнего обновления,
принятые задачи относительно общего числа, текущую работу, состояния
остальных задач, блокировки, результаты проверок и ревью, TASK-ID и SHA
созданных коммитов. При явном параллельном режиме видны все активные задачи.
Отсутствующая проверка отличается от успешной.

Дашборд читает сохранённое состояние исполнения и не является отдельным
источником прогресса. При доступном локальном просмотре он автоматически
подхватывает изменения. Если обновление недоступно, явно показывает потерю
связи и время последнего известного состояния. Сохранённый HTML содержит
снимок для просмотра без сервера, помеченный как снимок. После завершения
в нём остаётся итоговый результат и набор коммитов. Ошибка отображения
не меняет состояния задач; скилл сообщает её и способ восстановления.

### Доступность с начала работы

```yaml
sdd_record: acceptance
id: AC-dashboard-start
requirement: REQ-progress-dashboard
conditions: Согласованный план принят к исполнению и первая задача ещё не запущена
expected: HTML-дашборд создан, содержит весь список задач и выбранный режим, пользователь получил ссылку или локальный путь для открытия
```

### Обновление прогресса

```yaml
sdd_record: acceptance
id: AC-dashboard-progress
requirement: REQ-progress-dashboard
conditions: В сохранённом состоянии задача перешла к ревью, исправлению, блокировке или приёмке с коммитом
expected: Открытый дашборд автоматически показывает новое состояние, результаты проверок и коммит при наличии; число завершённых задач соответствует принятым задачам
```

### Потеря связи и итоговый снимок

```yaml
sdd_record: acceptance
id: AC-dashboard-snapshot
requirement: REQ-progress-dashboard
conditions: Обновление состояния недоступно либо выполнение завершено и HTML открыт без сервера
expected: Дашборд показывает последнее сохранённое состояние с отметкой снимка или потери связи и временем обновления; итоговый снимок содержит результат и коммиты, незавершённая работа не выглядит принятой
```

### Восстановление и завершение просмотра

```yaml
sdd_record: acceptance
id: AC-dashboard-recovery
requirement: REQ-progress-dashboard
conditions: Генерация или локальный просмотр дашборда прерваны, затем исполнение продолжено либо завершено
expected: Состояния задач сохранены, ограничение показано пользователю; просмотр и снимок восстанавливаются из записи исполнения, а после завершения останавливается только сервер этого исполнения
```

## Приёмка всего результата

```yaml
sdd_record: requirement
id: REQ-final-acceptance
operation: add
```

После приёмки задач скилл независимо проверяет общий результат по всем AC,
включая предусмотренные интеграционные сценарии. Проверяющий получает
согласованные требования и проект, без авторского вывода о выполнении.
В доказательстве исполнения отдельно отмечаются запуск сценария,
статическое чтение и недоступная проверка. Чтобы объявить план выполненным, скилл должен подтвердить
все обязательные результаты на итоговой версии. Итог исполнения: набор
коммитов по задачам в локальной ветке исполнения. Отчёт и дашборд перечисляют
TASK-ID и SHA и подтверждают проверки этого набора.

После передачи набора коммитов скилл заканчивает работу. Создание PR, push,
merge, публикация, синхронизация baseline, архивирование и автоматическое
переписывание проектных инструкций не являются последующими этапами.

Если продолжить невозможно, скилл возвращает частичный результат
с невыполненными критериями, причинами и следующим действием. Для каждой рекомендации
ревью указывается итог: исправлено в разрешённой области, оставлено с причиной
или отклонено с основанием. Отчёт строится по сохранённым доказательствам.

### Полное выполнение

```yaml
sdd_record: acceptance
id: AC-final-complete
requirement: REQ-final-acceptance
conditions: Все задачи приняты, их коммиты находятся в ветке исполнения и все обязательные AC подтверждены на итоговой версии
expected: Отчёт и итоговый дашборд содержат набор коммитов по TASK-ID и SHA, ссылки на доказательства и оставшиеся рекомендации; выполнение плана завершено без последующих этапов доставки
```

### Ограниченная приёмка

```yaml
sdd_record: acceptance
id: AC-final-incomplete
requirement: REQ-final-acceptance
conditions: Обязательный сценарий не работает или его проверка недоступна
expected: Отчёт явно обозначает частичный результат и затронутые AC; план не объявляется выполненным
```

## Переносимый пакет

```yaml
sdd_record: requirement
id: REQ-portable-package
operation: add
```

Пакет работает из исходной и установленной копий, обнаруживает зависимости
в текущей среде и поддерживает явный вызов в Codex и Claude Code.
Детерминированная проверка структуры не считается независимым ревью.
Если свежие исполнители или независимое ревью недоступны, скилл сохраняет
состояние и конкретное ограничение. Самопроверка не заменяет независимость.
Окружения, кэши, байткод и результаты запусков хранятся вне каталогов скиллов.

### Ограниченная среда

```yaml
sdd_record: acceptance
id: AC-host-limits
requirement: REQ-portable-package
conditions: Среда не позволяет получить требуемого отдельного исполнителя или независимого рецензента
expected: Скилл сохраняет прогресс и способ восстановления, не заявляя о проведённом независимом ревью или выполнении недоступного шага
```

### Чистая установка

```yaml
sdd_record: acceptance
id: AC-clean-install
requirement: REQ-portable-package
conditions: Документированные команды выполнены из установленной копии и стороннего рабочего каталога
expected: Пути разрешаются корректно; исходный и установленный пакеты не содержат созданных окружений, кэшей, байткода и результатов запусков
```
