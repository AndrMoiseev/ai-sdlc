```yaml
sdd_record: finding
id: FIND-verification-gap-extension-deadlock
source: >-
  specs/sdd-execution/spec.md: REQ-verification-result,
  AC-verification-dual-gate и AC-verification-gaps;
  design.md: DEC-verification-result, строки 128–136.

  skills/sdd-apply/scripts/lib/verification.py:199–203,

  skills/sdd-apply/references/review-policy.md:47–51.

  path: design.md
  element_id: DEC-verification-result
severity: blocker
problem: >-
  Дизайн одновременно требует passed verification_result до review_start
  и предписывает использовать существующий review/more_checks при
  содержательном пробеле без падения команды. Эти условия несовместимы
  для прямо предусмотренного AC-verification-gaps случая: зарегистрированная
  команда зелёная, но не подтверждает обязательный AC, и требуется добавить
  проверку. Verifier обязан сохранить failed/unavailable, поэтому
  review_start запрещён. Между тем существующий checks_extend разрешён
  только после reviewer verdict more_checks и требует соответствующий
  review_round. Дизайн не меняет это условие и не задаёт другой допустимый
  переход от отрицательного заключения к расширению реестра.
impact: >-
  Оркестратор не сможет зарегистрировать необходимую дополнительную
  проверку в пределах уже согласованного требования. Для продолжения
  придётся выдать необоснованный passed, обойти запрет review_start либо
  объявить обычный пробел доказательств нормативным конфликтом. Первые
  варианты нарушают новый контракт, последний подменяет существующее
  различие между more_checks и spec_conflict и возвращает обычную
  проверочную работу в согласование спецификации.
suggestion: >-
  Указать один достижимый путь устранения такого пробела до passed
  verification_result. Минимальный вариант — разрешить существующему
  checks_extend принимать конкретный запрос verifier, связанный с его
  актуальным failed/unavailable verification_result и AC, вместо
  обязательного reviewer more_checks. Сохранить прежние обязательные
  проверки, обновить registry revision, потребовать новый запуск explorer
  и новое заключение; учёт бюджетов описать без фиктивного падения теста.
  Дополнить AC-verification-gaps наблюдаемым результатом этого перехода.
  Новый lifecycle или отдельное событие для этого не требуются.
```
