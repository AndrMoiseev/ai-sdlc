# Премортем роли explorer

## Контекст

Проверяется перенос детерминированных запусков в принятую новую роль без потери независимости, доказательств, финальной проверки и бюджетов. Источники: исследование 0011 и текущий код на `ac83d5fbab13492d697e581e185e9dca7890afd9`; runtime-оценки нового поведения ещё нет. Выбор необходимости роли повторно не рассматривается.

## Успешный лог подменяет проверку требований

**Возможный провал:** после переноса запуска verifier остаётся декоративной ролью, задача принимается только по exit code.

**Предпосылка успеха:** приёмка проверяет отдельное содержательное заключение.

**Основания:** `skills/sdd-apply/scripts/lib/commits.py` вызывает valid_evidence и reviewed, `finalize.py` собирает command/procedure evidence; role_result хранит произвольный результат и сам не является обязательным критерийным заключением.

**Действие:** предложены REQ-verification-result и AC-verification-dual-gate; в задаче 5 отрицательные тесты «лог без заключения» и «заключение без лога». Реализация ещё не подтверждена.

## Null scope ошибочно означает только final

**Возможный провал:** исследование до задачи не регистрируется либо получает неверный final packet.

**Предпосылка успеха:** scope поручения не определяется наличием task_id.

**Основания:** `roles.py` вычисляет whole через null task и refactoring/final registry, а packet вызывает функции final_checks.

**Действие:** apply использует research packet существующей роли без final registry; spec сохраняет внешние request/result со ссылкой из checkpoint. AC-explorer-assignment и AC-explorer-check-stages проверяют отсутствие фиктивного execution/TASK и null scope до final registry. По ревью отдельный spec journal исключён.

## Потеря обязательных пропусков в сводке

**Возможный провал:** exit 0 и короткий summary скрывают skip обязательного сценария.

**Предпосылка успеха:** unknown не превращается в zero, первичные данные доступны, verifier устанавливает достаточность.

**Основания:** run_command сейчас фиксирует exit code/stdout/stderr и не извлекает полноту тестового набора. Гипотеза о полезности компактного результата не является доказательством полноты.

**Действие:** AC-check-summary-skips, AC-verification-gaps и финальный сценарий обязательного skip. Добавление неподдерживаемых report parsers отложено за пределы изменения; generic metadata обязателен.

## Потеря истории при смене роли

**Возможный провал:** миграция переписывает verifier в explorer, обнуляет счётчики либо принимает старые логи как новый final.

**Предпосылка прежнего предложения:** неизменная история и отдельный явный переход формата.

**Основания:** execution schema 3 имеет object/history integrity, budget reservations и несколько видов final evidence. `resume.py` уже сохраняет эти состояния.

**Итог пересмотра:** снято из объёма [решением пользователя](decisions.md#без-обратной-совместимости): обратная совместимость, миграция и повышение версии не нужны. Миграционный механизм и его тесты удалены. Сохранение бюджетов при обычном resume нового execution остаётся действующим требованием 10; прежние файлы автоматически не меняются.

## Поведенческая оценка ошибочно становится детерминированной

**Возможный провал:** запуск LLM-оценки через CLI поручают explorer как обычный тест, а её verdict трактуют как exit code.

**Предпосылка успеха:** тип проверки задаётся явно, смысловую аттестацию сохраняет проверяющий.

**Основания:** действующий API различает command/procedure, но форма запуска не доказывает детерминированность. Исследование 0011 явно оставляет behavioral на final приёмке.

**Действие:** execution_kind и AC-check-procedure-boundary; отсутствие обязательного типа процедуры отклоняется обычной валидацией без legacy-классификации.

## Приёмка выходит за лимит времени

**Возможный провал:** новый набор реальных процессов и agent evals превышает 60 секунд и блокирует работу.

**Предпосылка успеха:** сценарные матрицы используют существующие memory adapters; реальные границы проверяются минимально.

**Основания:** AGENTS.md задаёт строгий предел на каждый полный набор скилла; в tests уже есть memory_state, memory_repository и artifact adapters. Текущий runtime baseline наборов в этой документной задаче не измерялся.

**Действие:** план требует измерения исходного полного набора до добавления тестов и нового полного набора после, без исключения установки/подготовки и без деления лимита. При превышении остановка и новое указание пользователя. Это ограничение готовности реализации, а не выполненная проверка.
