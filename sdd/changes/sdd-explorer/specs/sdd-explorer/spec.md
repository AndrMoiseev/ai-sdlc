# Исследовательские и проверочные поручения explorer

Границы роли приняты в [журнале](../../decisions.md#принятое-направление). REQ/AC этого документа и [дизайн](../../design.md) согласованы [пользователем](../../decisions.md#согласование-документов-и-ревью-плана); план после ревью утверждён [без перехода к реализации](../../decisions.md#план-утверждён-без-запуска-реализации).

## 1. Настраиваемая роль

```yaml
sdd_record: requirement
id: REQ-explorer-selection
operation: add
```

Проект может независимо выбрать explorer для sdd-spec и sdd-apply через существующий механизм выбора агентов. По умолчанию обе роли могут использовать общий профиль с наследованием модели. Обычный запуск не пишет настройки. Существующие правила приоритета определений, ошибок, fallback и фиксации фактического launch сохраняются. Роль SDD не означает наличие инструментов встроенного одноимённого агента.

### Выбор профиля

```yaml
sdd_record: acceptance
id: AC-explorer-selection
requirement: REQ-explorer-selection
conditions: Проект использует ключи explorer, оставляет их без настройки или выбирает раздельные профили
expected: Resolver принимает обе роли, сохраняет прежние настройки и правила fallback, применяет выбранный профиль; setup показывает обе роли и не создаёт два конфликтующих общих определения
```

### Возможности исполнителя

```yaml
sdd_record: acceptance
id: AC-explorer-capabilities
requirement: REQ-explorer-selection
conditions: Выбранный агент доступен по имени, но не имеет нужного чтения, запуска команды или записи разрешённых артефактов
expected: Зависимое поручение не запускается; сохранена конкретная недоступная возможность; роль не симулируется и запрет среды не обходится подменой профиля
```

## 2. Ограниченное поручение и результат

```yaml
sdd_record: requirement
id: REQ-bounded-assignment
operation: add
```

Explorer получает research либо checks с вопросом/набором, областью чтения, разрешёнными выходами, основанием, лимитами и ожидаемой формой ответа. Источники и нормативные документы в этой роли не редактируются. Research возвращает проверенные факты с источниками, границами поиска и ограничениями. Checks возвращает фактический запуск и диагностику отдельно от оценки требований. Выход за поручение возвращается оркестратору.

В sdd-spec запрос, результат и сведения о запуске сохраняются в отдельном подкаталоге системного временного каталога, определяемого через API текущей среды без привязки к ОС. Каталог находится вне проекта, коллекций скиллов и uv cache; его абсолютный путь сохраняется в точке продолжения. Очистка временного каталога допустима и означает недоступность удалённых артефактов при resume. [Решение пользователя](../../decisions.md#временный-каталог-результатов-sdd-spec).

### Исследование и граница записи

```yaml
sdd_record: acceptance
id: AC-explorer-research
requirement: REQ-bounded-assignment
conditions: Explorer получает вопрос о реализации и потребителях, а ответ требует исследования нескольких файлов
expected: Ответ содержит проверяемые ссылки, просмотренную область и пробелы; исходники, требования, настройки и реестр неизменны; необходимая правка передана ответственному участнику
```

### Сохраняемая идентичность поручения

```yaml
sdd_record: acceptance
id: AC-explorer-assignment
requirement: REQ-bounded-assignment
conditions: Создаётся поручение до execution или без конкретной задачи, затем сессия прерывается и возобновляется; временные результаты сохранены либо удалены
expected: В sdd-spec каталог результатов создаётся в системной временной области через API среды без фиксированного пути ОС, отдельно от проекта, скиллов и uv cache; из сохранённых запроса, результата и точки продолжения с абсолютным путём восстанавливаются ID, вопрос, basis, фактический launch и выполненная часть без фиктивного TASK; отсутствие ответа остаётся незавершённым поручением, удалённый временный артефакт обозначен unavailable
```

## 3. Независимость и повторное использование контекста

```yaml
sdd_record: requirement
id: REQ-explorer-independence
operation: add
```

Explorer не совмещает контекст с автором реализации или содержательным проверяющим. Контекст одной задачи можно продолжить для research/baseline/self/independent/integration с новым поручением, актуальным basis и неизменным профилем. Изменение входов требует нового запуска проверок; повторное использование explorer не разрешает использовать устаревшие доказательства. Final требует свежего explorer. Другая настройка применяется через новый запуск агента. Финальный проверяющий всегда отдельный от explorer и всех авторов.

### Допустимое продолжение

```yaml
sdd_record: acceptance
id: AC-explorer-context-reuse
requirement: REQ-explorer-independence
conditions: Explorer продолжает research или baseline/self/independent/integration своей задачи либо переходит к другой задаче, final или роли автора/проверяющего
expected: Продолжение своей задачи допускается с новым поручением, актуальным basis и прежним профилем; другая задача и final требуют нового контекста, совмещение с автором или содержательным проверяющим запрещено
```

### Свежая финальная пара

```yaml
sdd_record: acceptance
id: AC-explorer-final-independence
requirement: REQ-explorer-independence
conditions: Готовится итоговая проверка после реализации и локальных исследований
expected: Регистрируются фактические отдельные свежие explorer и final_verifier; контексты авторов, исследователей и прежних проверок не удовлетворяют финальному контракту
```

## 4. Использование в sdd-spec

```yaml
sdd_record: requirement
id: REQ-spec-exploration
operation: add
```

В explore/draft/revise/plan/resume основной агент может делегировать ограниченный поиск фактов. Все детерминированные проверки документов выполняются через explorer с сохранением команды, состояния проверенных документов и результата. До появления change исследования допустимы с project scope. Основной агент принимает результат как источник и сам вносит авторские документы. Детерминированный check не заменяет согласование или независимое смысловое ревью.

### Передача результатов исследования

```yaml
sdd_record: acceptance
id: AC-spec-research-handoff
requirement: REQ-spec-exploration
conditions: Explorer исследовал проект до выбора change или во время подготовки документов
expected: Основной агент получает компактный ответ с источниками и ссылкой на поручение; после создания change сохраняет ссылку в точке продолжения без искусственного execution и без изменения нормативных документов explorer
```

### Проверка документов

```yaml
sdd_record: acceptance
id: AC-spec-check-delegation
requirement: REQ-spec-exploration
conditions: Documents или plan check выполнен explorer, а затем изменён проверенный документ либо check вернул ошибку
expected: Сводка различает корректную структуру, структурную ошибку и невыполненную проверку; после изменения документа старый результат не подтверждает новую версию; даже exit 0 не создаёт согласование
```

## 5. Согласованный процесс поставляемого комплекта

```yaml
sdd_record: requirement
id: REQ-explorer-workflow
operation: add
```

Входные инструкции, роли, task/final flows, recovery, API help и пользовательская документация описывают один и тот же порядок передачи. Обычный успешный запуск передаётся verifier без повторного исполнения и загрузки полного лога. При падении или пробеле проверяющий получает первичное доказательство и запрашивает следующее действие через оркестратора. Обновление bundle сохраняет explicit invocation, правила разрешений и границы независимого ревью.

### Сквозные сценарии роли

```yaml
sdd_record: acceptance
id: AC-explorer-workflow
requirement: REQ-explorer-workflow
conditions: Пользователь отдельно явно поручил финальный эвал комплекта; выполняются сценарии обычного успеха, многословного падения и exit 0 с пропуском обязательного теста
expected: Trace показывает фактический запуск explorer, использование summary проверяющим и отсутствие необоснованного повторного запуска; падение и обязательный пропуск блокируют приёмку с доступными raw evidence; инструкции и help не назначают детерминированный запуск verifier
```

При выполнении этого плана никакие эвалы не запускаются автоматически, включая финальную приёмку. Подготовка процедур и фикстур не разрешает их запуск. До отдельного явного поручения пользователя указывается, что эвал не запускался и поведенческий результат не подтверждён; согласование плана не заменяет такого поручения.
