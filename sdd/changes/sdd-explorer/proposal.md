# Explorer и разделение запуска проверок с оценкой требований

## Проблема и результат

Сегодня verifier одновременно организует запуск команд и оценивает достаточность доказательств. Его контекст получает инструментальные детали и логи, а API связывает право запуска с проверяющей ролью. Исследовательские поручения до реализации не имеют общего сохраняемого контракта.

Выделение explorer и границы роли **приняты пользователем**: [основание](decisions.md#принятое-направление), [исследование](../../../docs/decisions/research/0011-sdd-explorer-and-deterministic-checks.md). Explorer исследует проект и выполняет все детерминированные проверки в `sdd-spec` и `sdd-apply`. Verifier оценивает соответствие требованиям; final_verifier делает отдельное итоговое заключение. Оркестратор управляет поручениями и переходами, скрипты сохраняют результаты и проверяют условия переходов.

Результат изменения: проверяющий получает компактные доказательства с доступом к первичным данным, не повторяет исправный запуск без причины и не может принять результат только по коду выхода. Результат explorer сам по себе не разрешает приёмку.

## Объём

- Новая capability [sdd-explorer](specs/sdd-explorer/spec.md): выбор модели, ограниченное поручение, независимость контекстов, исследование до execution и делегирование в sdd-spec.
- Изменяемая capability [sdd-execution](specs/sdd-execution/spec.md): запуск команд ролью explorer на всех стадиях, сводка доказательств, отдельное заключение verifier, финальная приёмка и восстановление.
- Общий контракт и настройка в `sdd-shared` и `sdd-setup`; инструкции, API, тесты и пользовательская документация потребителей.
- Оба вида работы: `change` и `refactoring`, включая task-level final, refactoring whole checks и ordinary final project checks.

Спецификация и технический [дизайн](design.md) **согласованы пользователем**: [решение](decisions.md#согласование-документов-и-ревью-плана). [План](tasks.md), подготовленный по прямому поручению одновременно со спецификацией, передан на независимое ревью; plan_approval и разрешение реализации ещё не получены.

По поручению пользователя решение ограничено минимальным объёмом, достаточным для требований. Существующие role events, checkpoint и recovery переиспользуются; отдельные протоколы для маловероятных случаев не вводятся. [Ревью отдельного агента](simplification-review.md) выявило три упрощения; все внесены в текущие design/specs/tasks.

Повторное [ревью документов](review/summary.md) выявило блокировку расширения проверок до допуска к ревью. По [решению пользователя](decisions.md#расширение-проверок-и-передача-результата) требование 8 допускает checks_extend по актуальному запросу verifier; положительное заключение для review_start остаётся обязательным. Передача summary и первичных доказательств через оркестратора уточнена в требовании 7 и дизайне без отдельного транспорта.

## Исключения

Новый самостоятельный пользовательский скилл, универсальный планировщик агентов, автоматический выбор модели по сложности, новые права доступа, расширение задач исполнителя, изменение обязательных проверок и бюджетов повторов не входят в объём. Обратная совместимость, миграция старых executions и повышение версий исключены [решением пользователя](decisions.md#без-обратной-совместимости). Эвалы не запускаются автоматически при выполнении этого плана, включая финальную приёмку скиллов: любое такое исполнение требует [отдельного явного поручения пользователя](decisions.md#эвалы-только-по-отдельному-поручению). Подготовка сценариев и детерминированные тесты разрешены в рамках реализации; без запуска поведенческий результат остаётся неподтверждённым. Экономия токенов и стоимости не заявляется измеренным результатом. Общий перенос существующего execution-хранилища за пределы проекта не входит в изменение.

## Влияние

Настройки получают две необязательные роли, execution — поручения explorer и отдельные заключения. Номера версий сохраняются; новый контракт применяется напрямую. Обычное использование не переписывает настройки или старые execution-артефакты. В поставке меняются четыре скилла одного bundle; sdd-sync получает уточнение чтения завершённого результата без новой роли.
