# Parallel execution

Read [API](../references/api.md) and [roles](../references/roles.md). Keep the sequential flow unloaded. Require saved explicit user authorization and working isolation before admission.

1. Request `available`; respect accepted dependencies, `cannot_parallel_with`, shared files and mutable resources. Isolate ports, databases, scratch directories and mutable caches per task. A conflict serializes the affected work; free slots alone do not authorize unsafe overlap.
2. Submit `worktree_create` with `workspace` outside skill collections and the task's `resources`. The script creates a registered detached worktree at the execution branch's current HEAD. Register exact checks and project/CI inventory. Launch/register a fresh [executor](../agents/executor.md), pass the worktree and owned paths, then submit `start`. The executor leaves changes uncommitted and does not manage shared refs or other trees.
3. Before writing, launch/register an independent verifier and run `check_run` at stage `baseline` for existing mandatory checks. Record planned absence only for approved setup requirements. Implement in the assigned tree. On executor completion, save `role_result` and freeze `candidate`. Stop writers during checking and review.
4. Launch/register an independent [verifier](../agents/verifier.md) and run stage `independent` in that tree. Reserve `review_start` for a fresh [reviewer](../agents/reviewer.md), or another role ID in the verifier's context. Record separate verification and review results. Handle failures through [repair](repair.md).
5. Serialize integration into the execution branch. After worktree checks/review pass, call `transfer` then `integrate`. The script owns complete binary packaging and application. Preserve the worktree and package on conflict or ambiguous recovery. Assign semantic conflict resolution within that task; do not overwrite execution files with worktree copies. For a conflicted recorded intent, a registered executor resolves and stages only the conflicted task paths, returns `role_result`, then the orchestrator calls `integration_resolve` with `intent_id`, resolver `role_id`, and `resolution`. This adopts the resolved working candidate for mandatory integration checks and review.
6. Freeze the integrated candidate. Run independent `check_run` with stage `integration` on the execution branch even if transfer was clean. Reserve and complete a review of the integrated candidate, consuming the same task-lifetime review budget. Then call `commit` and `accept` in the execution branch. Executors create no task branches or intermediate commits.
7. After acceptance and all roles stop, call `worktree_remove`. The script verifies ownership, saved transfer, accepted commit and absence of unknown data. Preserve a tree when cleanup is rejected. A cleanup failure cannot revoke a valid commit or justify a duplicate one.
8. Continue eligible work while honoring blockers. Either exhausted task budget stops new work across the whole run: bring active roles to a saved stop, reconcile already-started effects, and ask for the concrete decision described in [repair](repair.md). After all tasks are accepted, use [finalize](finalize.md).

If the user changes mode after this flow was loaded, use [resume](resume.md) for fresh-owner handoff. Preserve unintegrated worktree candidates; a rejected transition is not permission to integrate after authorization was withdrawn.
