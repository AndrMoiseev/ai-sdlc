# Plan completion

1. Read the saved state. Require all planned tasks accepted with confirmed commits in the execution branch and a clean reconciled HEAD. Retain each task's worktree evidence, verifier conclusion and review. Completion launches no workers and runs no checks.
2. Submit `finalize`. It summarizes accepted tasks and their original `verification_result` references; it does not create a new assessment of the integrated result. Unaccepted tasks, missing acceptance records or unreconciled Git state yield `partial`. For refactoring, report `unassessed_criteria` explicitly: a contribution to a whole result does not prove that result. Checks needed as acceptance conditions belong to approved task work before acceptance.
3. Apply the [review policy](../references/review-policy.md). Omitted `recommendation_decisions` defer all debt. Explicit decisions identify each finding once, with `defer` or `reject` and a reason. Follow-up fixes need explicit user approval and retain the completed plan.
4. Regenerate the summary/dashboard using [progress](../references/progress.md). Report accepted TASK-ID to SHA, accepted and unassessed criteria, original evidence references and limitations. Preserve a partial result when blocked. Push, release and deployment require their own instruction.
