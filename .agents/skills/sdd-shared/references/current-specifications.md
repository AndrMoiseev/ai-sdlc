# Текущие спецификации

Текущая спецификация (baseline) описывает действующее поведение capability.
Спецификация изменения описывает принятую дельту к этому поведению. Переносом и
архивом управляет [sdd-sync](../../sdd-sync/SKILL.md).

По умолчанию текущие spec находятся в `sdd/specs/<capability>/spec.md`.
Существующее размещение проекта и явные `source.path` сохраняются: перенос в новый
каталог не является частью синхронизации. Вложенный путь capability сохраняется.

Baseline является обычным Markdown, а не комплектом изменения schema v1.
Для существующих документов сохраняй их формат. Для новых используй `#` для
capability, `##` для требований и `###` для их критериев. Сохраняй смысловые ID
в fenced YAML рядом с заголовком:

````markdown
# Экспорт заказов

Пользователь выгружает выбранные заказы в CSV.

## Выгрузка CSV

```yaml
sdd_record: requirement
id: REQ-order-export
```

Выгрузка содержит выбранные заказы и строку заголовков.

### Формат файла

```yaml
sdd_record: acceptance
id: AC-export-encoding
requirement: REQ-order-export
conditions: Пользователь выгружает выбранные заказы
expected: CSV в UTF-8 со строкой заголовков
```
````

В новой baseline не нужны frontmatter изменения, `change_id`, `operation` и
`source`: применённая операция уже отражена в содержании. История происхождения
остаётся в архивной дельте и отчёте sync. Не добавляй фиктивные `operation: add`
ради парсера изменения. Существующие метаданные проекта сохраняй, кроме
перенесённых по ошибке полей операции и идентичности изменения.

Проверяй уникальность REQ/AC-ID внутри файла, принадлежность каждого AC одному
существующему REQ и хотя бы один AC у каждого нового или изменённого требования.
Ключ ссылки на baseline состоит из пути файла и REQ-ID либо точного заголовка;
ID из разных файлов не обязаны быть глобально уникальными.

`check.py` проверяет документы изменения. Его разрешение `source.kind:
specification` распознаёт точные заголовки и ID в YAML baseline без требования
frontmatter изменения. Проверка текущих spec выполняется по этому контракту и
проектным средствам; отдельного CLI для baseline в API v2 нет. Версия API не меняет формат baseline или версию нормативных документов изменения (v1). Исторические
spec в архиве сохраняют исходный формат дельты и не проверяются как активный
change с датированным change-id.
