# SDD Spec

Единый явно вызываемый скилл для исследования, спецификаций, дизайна, независимого ревью и согласованного плана. Рабочие документы сохраняются в `sdd/changes/<change-id>/`; реализация, синхронизация baseline и архивирование находятся за границей процесса.

## Ручное подключение

Скопируйте **весь** каталог `skills/sdd-spec/`, включая скрытые файлы при наличии, `agents/openai.yaml`, flows, references, templates, scripts и pyproject.toml. Для Codex выберите `.agents/skills/sdd-spec/` проекта либо `~/.agents/skills/sdd-spec/`; для Claude Code — `.claude/skills/sdd-spec/` либо `~/.claude/skills/sdd-spec/`. Если целевой каталог уже существует, сравните версии и сохраните собственные изменения до замены. Не перезаписывайте чужие настройки, AGENTS.md, CLAUDE.md или определения агентов. Автоустановщика нет. Пути подключения подтверждены [OpenAI](https://learn.chatgpt.com/docs/build-skills) и [Claude Code](https://code.claude.com/docs/en/skills).

Откройте новую сессию и вызовите `$sdd-spec`/выберите скилл в Codex либо `/sdd-spec` в Claude Code. Например: «`$sdd-spec` исследуй экспорт заказов» или «`/sdd-spec` продолжи order-export». После запуска достаточно обычного диалога. Общая просьба «спланируй изменение» в новой сессии не активирует скилл. Не копируйте только SKILL.md: это потеряет инструкции и политику явного входа.

Для работы нужен установленный [uv](https://docs.astral.sh/uv/getting-started/installation/).
Агент сам запускает служебные скрипты скилла, а uv автоматически устанавливает
их зависимости. Дополнительная настройка Python в проекте не требуется.

OpenSpec не требуется. При отключении скилла сохраните рабочее дерево `sdd/`:
в нём документы и история решений.

Для согласованной гуманизации русских документов требуется установленный `humanizer-ru` и
возможность запускать свежих субагентов. В APM эта зависимость входит в
`common-dependencies`; при ручном подключении установите её отдельно.
После порции правок скилл предлагает гуманизацию и запускает её только по явному
согласию. Отказ или отсутствие ответа не блокируют основной процесс;
область поручения и порядок прохода описаны в [контракте](references/editorial-pass.md).

## Черновики и обсуждение

Черновик можно сохранить до завершения обсуждения. После сохранения агент
продолжает ближайший существенный вопрос; предложения не становятся принятыми
от появления в документах. Существенные решения принимает пользователь.
Журнал `decisions.md` хранит автора предложения, статус и основание принятия;
`questions.md` хранит открытые и закрытые вопросы. В `state.md` остаются ссылки
и следующий шаг. Согласования и решения по ревью сохраняются отдельно,
в `review/decisions.md`.

При продолжении агент читает эти материалы и проверяет существенные положения
черновика. Старые вопросы в state поддерживаются; при обновлении checkpoint
они переносятся без потери ID и ответов. Подробности — в
[правилах обсуждения](references/discussion.md).

## Пояснение решения

После подготовки черновика скилл предлагает необязательное пояснение: один документ,
набор документов или отказ. Ранее выданное поручение выполняется без повторного
вопроса в той же области. Выбор сохраняется для продолжения; отсутствие ответа
не разрешает генерацию и не блокирует основной процесс.

Прямые запросы: «`$sdd-spec` поясни решение order-export с диаграммами»;
«`/sdd-spec` обнови пояснение order-export». Для незавершённых превью используйте
сохранённый в изменении archify/preview-handoff.md. Маршрут описан в
[explain](flows/explain.md), размещение и проверки в [контракте](references/explanation.md).

Для диаграмм требуется установленный archify. В APM он входит в
common-dependencies; при ручном подключении установите его отдельно. Скилл
находит пакет через каталог среды. Без зависимости сохраняется доступный текст
и описание ограничения. Если HTML создан, но превью не готово, сохраняются
диаграмма, результаты проверок и промпт продолжения с фактической причиной.
Ошибки проверки отличаются от отсутствия браузера; учитывается и локальный
Chrome/Chromium. Снимки получают при проверке archify, осматривают и вставляют
ссылками на HTML. Все сохраняемые артефакты находятся внутри каталога изменения.

Пояснение сверяется с текущими proposal/design/specs; снимки отдельно сверяются
с HTML. Производные файлы не входят в нормативный манифест SDD. Замена превью
сохраняет согласование неизменённого основного комплекта.

## Проверенный объем

Техническая сверка 2026-09-29: `codex-cli 0.159.0`, локальная справка exec и официальные контракты skills/subagents. CLI сообщил предупреждения о временном PATH-каталоге, не помешавшие чтению справки. `claude --version` недоступна: Claude Code отсутствует в PATH, адаптер сверен только с [документацией субагентов](https://code.claude.com/docs/en/sub-agents). Минимальная поддерживаемая версия Claude Code не установлена. Инструкции обеих сред поставлены; полная runtime-совместимость не доказана статическими проверками.

Скрипты проверяют структуру и манифесты, но не истинность согласований и не качество рецензента. Контекст и доступность независимых агентов проверяются при запуске. Сквозные испытания на реальном проекте в обеих средах — отдельная работа и здесь не заявляются.

[Ручные процедуры](evals/manual.md) разделяют статическую проверку инструкций и фактическое выполнение; [происхождение](references/openspec-origin.md) содержит адаптации OpenSpec и лицензию.
