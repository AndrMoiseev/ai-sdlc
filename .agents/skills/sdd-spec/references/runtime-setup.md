# Условия запуска и проверки

Определи абсолютные `<skill-root>` (каталог скилла), `<repo>` (корень проверяемого
проекта) и безопасный `<id>`. Проверь комплектность flows,
references, templates, scripts, соседних script lock-файлов и метаданных хоста, доступ
к источникам и запись в выбранный корень `sdd/changes/` или `sdd/refactoring/`. Существующее изменение сохраняй.

## Автономные скрипты uv

Установи полный `sdd-shared` рядом с этим скиллом и прочитай
[общие условия запуска](../../sdd-shared/references/runtime-setup.md).
Парсер, проверки, Git-чекпойнты и resolver принадлежат API v2 общего пакета;
команды ниже сохраняют прежний интерфейс. Обновляй комплект скиллов вместе.

## Команды

Детерминированные проверки документов выполняет explorer по
[контракту поручения](explorer.md). Команды check.py ниже предназначены для его
checks-пакета; основной агент сохраняет запрос и принимает машинный результат.
Перед запуском проверь возможность записи внешних артефактов и выполнения
точных команд. Недоступность explorer означает невыполненную проверку.

Запускай из любой директории, подставляя абсолютные пути в кавычках:

```text
uv run --locked --script "<skill-root>/scripts/check.py" --project-root "<repo>" --change <id> --stage documents
uv run --locked --script "<skill-root>/scripts/check.py" --project-root "<repo>" --change <id> --stage plan
uv run --locked --script "<skill-root>/scripts/test.py" -q
uv run --locked --script "<skill-root>/scripts/resolve_agent.py" --project-root "<repo>" --role sdd-spec.document_reviewer --host codex --parent-model "<observed-model>"
uv run --locked --script "<skill-root>/scripts/simplicity.py" --model "<selected-or-observed-model>"
```

Зависимости команд объявлены в самих скриптах и устанавливаются при запуске;
pytest нужен тестовому runner. simplicity только читает поставляемые инструкции:
[правила подготовки](simplicity-instructions.md). Модель неизвестна — опусти `--model`.

Check только читает проект; JSON идёт в stdout. Для Git-входа и завершения перехода используй inspect/accept/create по [общему API](../../sdd-shared/references/api.md). Записи выполняет основной агент; snapshot сообщает о миграции и не создаёт нормативный манифест.
Check разделяет errors/warnings, checkpoint_status, discussion_status, review_status и approval_status:
exit 0 — структура корректна, 1 — структурные ошибки, 2 — проверка
не выполнена. Ошибка запуска uv также означает, что проверка не выполнена.
Exit 0 не разрешает переход. Documents не требует tasks;
plan добавляет покрытие AC, граф и проверки задач.

`review_status` сохраняет покрытие, актуальность и находки опционального ревью;
его `complete` не является условием `approval_status.ready`. Для передачи
согласованного плана в реализацию нужен установленный sdd-apply. Если он
недоступен, сохрани согласование и сообщи о недостающем скилле; повторного
разрешения пользователя после восстановления зависимости не требуется.

discussion_status показывает открытые и блокирующие Q-ID только из questions.md.
Открытый блокирующий вопрос препятствует approval_status.ready, сохраняя
само свидетельство согласования. Смысловую полноту вопросов и авторство журнала
агент проверяет по [правилам обсуждения](discussion.md).

При ошибках сообщи причину. Исправь однозначную структуру с сохранением
смысла и повтори проверку; развилку поведения или объёма вынеси пользователю.
Структурные исключения не предусмотрены. Недоступную проверку не считай
успешной; доступное исследование и сохранение черновиков допустимы.

До независимого ревью проверь чистый контекст и ограничения чтения через
адаптер хоста. Самопроверка не заменяет независимого рецензента. OpenSpec CLI,
openspec-скиллы и LLM-ключи в файлах пакета для процесса не нужны.

## Зависимость пояснения

Для [explain](../flows/explain.md) найди установленный archify через каталог
скиллов текущей среды и прочитай его SKILL.md, схемы нужных типов и процедуру
проверки со снимками. Разрешай пути инструментов от найденного пакета;
расположение в авторском репозитории не предполагается. В APM archify входит
в common-dependencies; при ручном копировании sdd-spec установи его отдельно.

Если archify отсутствует или его требования нельзя выполнить, сохрани доступный
текст пояснения и конкретное ограничение, укажи следующий шаг подключения
или проверки. Необязательное пояснение не блокирует основной процесс.
Браузер проверяй средствами archify, учитывая локальный Chrome/Chromium.
Различай недоступную зависимость, недоступный браузер и ошибку самой проверки.
Пути сохраняемых артефактов явно задавай внутри archify/ текущего изменения
по [контракту пояснения](explanation.md).

## Команды рефакторинга

Для check и checkpoint передавай --work-kind refactoring при работе в sdd/refactoring. Для обычного изменения сохраняй прежние команды. Передавай вид явно при совпадающих ID; комплект proposal/design проверяется на documents, tasks добавляется на plan. Разрешение схемы и безопасного корня выполняет shared; сообщение об ошибке не обходи переносом согласования.
