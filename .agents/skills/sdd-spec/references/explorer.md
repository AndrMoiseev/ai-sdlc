# Поручения explorer до execution

Используй [общий контракт](../../sdd-shared/references/explorer.md) и
[инструкцию роли](../../sdd-shared/agents/explorer.md). Основной агент ставит
поручение, сохраняет ответ и сам переносит подтверждённые факты в документы.
Research можно делегировать в explore/draft/revise/plan/resume. Все
детерминированные проверки документов передавай explorer, включая проверки
из других флоу; результат не заменяет смысловое ревью или USER-согласование.

## Подготовка и передача

1. Раздели research (вопрос, источники и границы поиска) и checks (точные команды
   штатного check.py из [runtime-setup](runtime-setup.md)). В research разрешены
   поиск, чтение и просмотр справки; тесты и валидаторы требуют checks.
2. Получи системный временный каталог через API текущей среды: например,
   `tempfile.gettempdir()` в Python или `[IO.Path]::GetTempPath()` в PowerShell.
   Создай в нём уникальный подкаталог стандартными средствами среды. Проверь,
   что его разрешённый абсолютный путь находится вне проекта, всех установленных
   коллекций скиллов и uv cache. При конфликте останови зависимый запуск и
   сообщи путь; фиксированный путь другой ОС не подставляй. Проверь создание,
   запись, чтение и перечисление через тот runtime, которым будет работать роль.
3. Сохрани `<id>.request.json` до запуска. Включи assignment по общему контракту,
   resolver selection, наблюдения capabilities и ожидаемую форму результата.
   Выбирай `sdd-spec.explorer` по [resolver](../../sdd-shared/references/subagents.md).
   `scope.project` содержит корень проекта; work/task до появления равны null.
   В basis сохрани версию источников, абсолютные пути и SHA-256 проверяемых
   документов, конфигурации и точные аргументы команд с cwd. Для checks задай
   check_ids, stage и registry_revision этого сохранённого набора. Это локальная
   идентичность набора, без создания execution, фиктивного TASK или нового реестра.
   Разреши outputs только внутри временного каталога; исходники, настройки,
   нормативные документы и реестры остаются только для чтения.
4. Проверь capabilities по общему контракту и запусти отдельный контекст с
   выбранным профилем через фактический инструмент хоста. Передай пути запроса
   и инструкции роли, read_scope, outputs и лимиты. Сохрани `<id>.launch.json`
   с context_id, фактическим trace и аргументами запуска. Неизвестные effective
   model/effort остаются null. Имя встроенного explorer не доказывает возможности.
   Недоступная возможность блокирует зависимое поручение; сообщи её конкретно.
5. Получи ответ и сохрани `<id>.result.json`, связанный с id/kind/scope/basis и
   сохранённым launch. Research возвращает answer, sources с путями/строками,
   inspected_scope, gaps, assumptions, questions и limitations. Checks возвращает
   summary, raw_artifacts и отдельно diagnosis. Основной агент проверяет ссылки
   и границы ответа; запрос правки передаёт автору, а не расширяет права explorer.

Контекст explorer отделён от автора и рецензентов. Продолжение допускается с
тем же профилем и scope, новым id и актуальным basis; другая задача или профиль
требует нового контекста. Каждый повтор получает новый каталог и ссылку на
предыдущий запрос. Пределы времени и разрешённых повторов сохраняются.

## Проверка документов

Explorer выполняет точные команды documents/plan через штатный check.py.
Сохрани stdout JSON и stderr отдельными файлами в outputs, фактические аргументы,
cwd, время, exit code и basis до/после. Для запуска доступен общий
`sdd_shared.module('check_runner')`; summary и ссылки на raw artifacts формирует
исполнитель, не основной агент по догадке. JSON check.py уже содержит структуру
результата; неизвестные счётчики тестов оставь null. Полные логи передавай ссылками.

| Наблюдение | Значение |
|---|---|
| exit 0 и читаемый JSON текущего basis | Структура корректна |
| exit 1 и читаемый JSON текущего basis | Структурные ошибки |
| exit 2, сбой uv/запуска, отсутствующий или повреждённый JSON | Проверка не выполнена |
| Изменение любого проверяемого документа или конфигурации | Старое доказательство unavailable для новой версии; нужен новый запуск |

Сохрани машинный результат без изменения outcome; diagnosis объясняет его отдельно.
Exit 0 не создаёт USER, planning_command, document_approval или plan_approval.
После исправления автором документов выдай новое checks-поручение с новым basis.
Отсутствующее доказательство не восстанавливай из пересказа или успешного старого exit.

## Checkpoint и восстановление

В текущей точке продолжения сохрани id, краткий итог, абсолютный каталог и для
каждого существующего request/launch/result/raw файла абсолютный path и SHA-256.
До появления change верни эту точку пользователю и сохрани её в доступном хосту
контексте продолжения. После создания change перенеси ссылки в state.md, сохраняя
исходные null work/task в запросе. В state.yaml.document_links входят только
существующие локальные Markdown-документы; JSON и внешние файлы туда не добавляй.

При resume прочитай файлы по абсолютным ссылкам, сравни digest, id, scope, basis,
launch и выполненную часть. Живой context_id проверь инструментами хоста перед
продолжением. Ответ ещё не получен — incomplete; удалённый, повреждённый,
подменённый или устаревший артефакт — unavailable с конкретной причиной.
Очистка временной области допустима: краткий итог в state.md не заменяет файл.
Потерянный контекст не отменяет сохранившийся ответ с актуальным basis, но требует
нового запуска роли для следующего поручения. Запись request сама по себе не
доказывает, что агент был запущен, и не обеспечивает однократность запуска.

## Необязательный библиотечный helper

[scripts/explorer.py](../scripts/explorer.py) доступен для импорта из Python-среды
хоста с каталогом scripts в пути импорта. Это не CLI: `uv run --script` для него
не используется. Если хост пишет файлы своими инструментами, следуй тому же
контракту без импорта. Helper не запускает агентов и не обновляет checkpoint.

- `create_directory(project_root, skill_roots, uv_cache)` выбирает temp API и
  проверяет исключённые корни; передай реальные корни из runtime preflight.
- `save_request(directory, assignment, selection, capabilities)` сохраняет запрос
  после проверки общей формы, capabilities и выходной области.
- `write_artifact(directory, name, value)` сохраняет launch или result JSON и
  возвращает `{path, sha256}`; `read_artifact(reference)` проверяет digest.
- `validate_result(assignment, result)` сверяет идентичность и поля ответа перед
  сохранением; `recover(request_ref, result_ref, current_basis, launch_ref)` читает
  сохранённые файлы. Для неполученного ответа передай result_ref null. Дай текущий
  basis из повторного чтения источников; helper сам его не вычисляет.

Хост остаётся источником фактического launch и прав доступа. Проверка формы JSON
не подтверждает истинность фактов, реальный запуск или согласование пользователя.
