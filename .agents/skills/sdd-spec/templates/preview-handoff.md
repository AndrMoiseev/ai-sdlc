# Продолжение проверки превью

Шаблон: перед сохранением в archify/preview-handoff.md подставь конкретные значения
и удали подсказки. Пути внутри изменения относительные; после переноса новый
корень проекта задаётся при запуске, путь установки скилла из старой среды не нужен.

## Задание для новой среды

Продолжи пояснение изменения `<change-id>`. Корень проекта: `<repo в этой среде>`.
Каталог изменения: `sdd/changes/<change-id>/`. Прочитай `<пути документов пояснения>`,
`archify/index.md`, `state.md`, proposal.md, design.md и все specs/**/spec.md.
Найди установленные sdd-spec и archify через каталог скиллов среды, прочитай их
инструкции и контракт проверки archify со снимками. Это продолжение поручения
в области `<сохранённая область>`; выполнено `<готовая часть>`, осталось `<остаток>`.

| ID диаграммы и точный маркер | Документ и место вставки | Candidate и HTML | Результаты проверки, PNG и диагностика |
|---|---|---|---|
| `<id>`, `ARCHIFY_PREVIEW_PENDING:<id>` | `<относительный путь и заголовок>` | `<существующие пути; отсутствие укажи явно>` | `<пути, фактическая причина, требуемое исправление>` |

1. Получи snapshot documents штатным запускателем sdd-spec. Сравни полный состав
   и хеши с сохранённым в index.md манифестом. При несовпадении пометь пояснение
   и индекс устаревшими; сначала обнови содержание в уже порученной области
   и проверь применимость остальных частей. При новой области уточни только
   зависимую работу. Новый манифест запиши после сверки всего пояснения.
2. Проверь по archify привязку результатов к текущим байтам каждого HTML.
   Актуальные проверенные изображения сохрани. Совпадение документов SDD
   не подтверждает пригодность прежнего PNG после изменения HTML.
3. Выполни недостающие проверки archify со снимками. Задавай все сохраняемые
   результаты внутри archify/ соответствующей диаграммы; прежние результаты
   сохраняй по правилам повторных проверок archify. При проверке доступности браузера учитывай
   локальный Chrome/Chromium. Ошибки геометрии и выполнения исправляй в пределах
   archify; смена среды не исправляет содержательный дефект.
4. Осмотри PNG: подписи, статусы и расшифровки читаются, значимые части не обрезаны.
   При необходимости выбери несколько снимков. Замени только указанные заглушки
   кликабельными превью с относительными ссылками на соответствующий HTML.
   Готовые актуальные вставки сохраняй; повторный запрос не дублирует изображения.
5. Обнови index.md, этот список оставшейся работы и checkpoint. Отдельно запиши
   результаты генерации HTML, браузерной проверки, получения снимков и осмотра.
   Для неготового превью сохрани маркер с фактической причиной и ссылкой только
   на существующий HTML. Проверь ссылки из каждого документа и предложи гуманизацию
   новой авторской прозы по sdd-spec; запускай её только в согласованной области.

Сохрани смысл диаграмм и нормативные байты при работе только с превью. Новое
обязательство требует обычного revise; согласование на изменённую версию
не переносится. Сообщи заменённые и оставшиеся маркеры, пути результатов,
ограничения и следующий шаг. Полное завершение означает отсутствие недостающих
превью и подтверждённые проверки актуальности и осмотр, а не одно наличие PNG.
