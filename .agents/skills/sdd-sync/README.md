# sdd-sync

`sdd-sync` обновляет текущие спецификации по завершённому изменению и переносит
весь каталог изменения в архив. Требования, которых изменение не касается,
остаются на месте. В архиве сохраняются план, решения и результаты проверок.

Скилл завершает работу, подготовленную через [sdd-spec](https://github.com/AndrMoiseev/ai-sdlc/blob/main/skills/sdd-spec/README.md)
и принятую через [sdd-apply](https://github.com/AndrMoiseev/ai-sdlc/blob/main/skills/sdd-apply/SKILL.md). Подходит и для реализации,
которую приняли вне sdd-apply. Текущие спецификации становятся основой следующих
изменений; прежние документы остаются доступными по архивному пути.

| Сценарий | Пример запроса | Результат |
|---|---|---|
| Перенос и архив | `$sdd-sync order-export` | Обновлённые текущие spec и весь каталог изменения в `sdd/changes/archive/YYYY-MM-DD-order-export/`. |
| Просмотр перед переносом | `$sdd-sync покажи, что изменится при переносе order-export` | Список правок, найденные препятствия и будущий путь архива. Файлы остаются прежними. |
| Только спецификации | `$sdd-sync синхронизируй order-export без архива` | Текущие spec обновлены, изменение остаётся активным. |
| Архив после синхронизации | `$sdd-sync теперь архивируй order-export, ранее синхронизированный без архива` | Агент проверит прежний перенос, поправит ссылки на новый путь и перенесёт каталог в архив. |
| Продолжение после сбоя | `$sdd-sync продолжи перенос order-export` | Проверка уже сделанных правок и завершение оставшейся работы. |
| Несколько изменений | `$sdd-sync перенеси order-export и invoice-download` | Последовательный перенос; при пересечении требований агент уточнит порядок. |
| Реализация вне sdd-apply | `$sdd-sync order-export: реализацию я принял, результаты проверок в completion.md` | Перенос с указанным основанием завершения. |
| Изменение без spec | `$sdd-sync архивируй завершённое docs-cleanup; требований в нём нет` | Архив изменения, текущие спецификации остаются прежними. |

В Claude Code используйте `/sdd-sync` вместо `$sdd-sync`. При нескольких активных
изменениях без указанного имени агент предложит выбрать одно. Повторный вызов для
уже архивированного изменения покажет его расположение.

Если источник требования пропал, проверки не прошли или имя архива уже занято,
агент сообщит причину и сохранит активное изменение. Архивирование начнётся только
после успешной проверки переноса всех его спецификаций.

Семантика опирается на [синхронизацию и архивирование OpenSpec](references/openspec-origin.md).
Обычный вызов `sdd-sync` объединяет оба действия; работает он с документами SDD.
