# Продолжение переноса

Прочитай существующий `sync.md` до выбора архива и любых правок. Чужой документ
не перезаписывай. Для подтверждённого переноса сохрани записанную архивную цель,
даже если дата изменилась; проверь её принадлежность выбранным проекту и изменению.
Смена цели требует нового плана ссылок и хэшей. Если после «без архива» цель ещё
не выбиралась, назначь её по [шагу 1](workflow.md#1-выбери-область), включая
проверку коллизии. В превью выполняй только анализ, без записей в проекте.

При каждом продолжении, включая переход из успешного «без архива», заново выполни
[проверку завершения](workflow.md#2-проверь-завершение) до записей и архивирования.
Проверь текущие свидетельства, доступность принятых коммитов и открытые блокеры.
Совпадение хэшей spec и прежний успешный перенос эту проверку не заменяют.

При переходе из успешного «без архива» к архивированию сначала подтверди прежний
результат по хэшам. Поведенческую дельту повторно не применяй. Подготовь только
замену ссылок с активного пути изменения на выбранный архивный путь. Добавь в
отчёт отдельный этап: его хэши «до» соответствуют уже синхронизированным spec,
«после» соответствуют тем же spec с исправленными ссылками. Сохрани предыдущий
этап, исходный успешный check и отображение удалённых/переименованных требований.
Проверь будущее размещение по [шагу 3 процесса переноса](workflow.md#3-подготовь-слияние), запиши ссылки и продолжи архивирование.
При отсутствии таких ссылок новые записи spec не нужны. Прерванный переход
продолжай по хэшам последнего этапа, сохраняя выбранную архивную цель.

При наличии отчёта сверяй исходные хэши дельты и для каждого целевого файла
состояние «до» или «после». Совпадение с «после» означает уже выполненную запись;
совпадение с «до» допускает оставшуюся запись. Любое третье состояние требует
разбора конфликта. Отчёт не даёт права перезаписать новые правки.

После удаления/переименования исходное `source` может перестать разрешаться.
Повторный check старой дельты тогда не является проверкой результата. Опирайся на
сохранённый успешный исходный check, неизменные хэши дельты, план переноса и
текущие байты; остальные диагностики не игнорируй. Без такого свидетельства
не объявляй пропавший источник «уже применённым» по одному его отсутствию.

При сбое записи сохрани активное изменение и отчёт о выполненной части. Откатывай
только собственные записи, если их текущие хэши всё ещё совпадают с записанными
тобой. В противном случае сохрани данные и сообщи конфликт. Архив до устранения
сбоя не создавай.

После проверки текущего завершения и сверки хэшей продолжи подготовку, оставшиеся
записи и проверки по [процессу переноса](workflow.md). Уже применённую поведенческую
дельту пропусти; этап ссылок и проверки перед [архивированием](archive.md) сохрани.
