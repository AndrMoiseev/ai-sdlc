# SDD Setup

Запускай по явному `$sdd-setup`, `/sdd-setup` или выбору этого скилла пользователем.
Последующие ответы продолжают настройку без повторного вызова.

## Выбор этапов

Без параметров проведи пользователя через все этапы по порядку:
**1. Аудит проекта и исправление несоответствий → 2. Настройка агентских ролей**.
Это также маршрут просьбы «подготовь проект». Покажи этот порядок перед началом.
Переходи к следующему этапу после выполнения критерия текущего.

| Явное уточнение при вызове | Что выполнить |
| --- | --- |
| «только аудит», «проверь соответствие» | Этап 1 только с чтением; покажи результат и необходимые исправления |
| «проверь и исправь требования», «установи mise» | Этап 1 с исправлениями и повторной проверкой |
| «только роли», изменение назначений, моделей или effort | Только этап 2; общий аудит проекта не заявляй выполненным |

Последующий ответ продолжает выбранный маршрут. После перерыва перепроверь
незавершённый этап; уже принятые решения используй без повторного вопроса.

## Этап 1. Аудит проекта

Определи корень проекта и среду, в которой агент будет выполнять его команды.
Прочитай [условия запуска](references/runtime-setup.md), затем выполни
[аудит проекта](references/project-audit.md). Сопоставь факты со всеми требованиями
из этого документа; первое обязательное требование — работающая mise.

В полном маршруте устрани обнаруженные несоответствия в пределах поручения и
повтори проверку. Переход к ролям открыт, когда все обязательные требования
подтверждены. При отказе, ошибке или недоступном исправлении покажи причину и
следующее действие; полный setup остаётся незавершённым. В маршруте только аудита
результатом служит отчёт о соответствии, включая найденные несоответствия.

## Этап 2. Настройка агентских ролей

1. Прочитай условия запуска для ролей. Определи текущую агентскую среду
   по контексту хоста. Выполни `inspect`
   с `--output` по [интерфейсу скрипта](references/api.md). Готово, когда получены
   все роли из общего контракта, текущие значения, пресеты и сведения об агентах.
2. Проведи [диалог настройки](references/dialogue.md) по текущим значениям и
   пресетам из `inspect`. Зафиксируй решение для каждой роли и модель/effort
   каждого уникального агента; согласие на показанную группу покрывает всю группу.
3. Составь request со ссылкой на inspection и выполни `plan --output`.
   Скрипт включит создание отсутствующих агентов в родном формате текущей среды.
   Покажи решения и точный diff из сводки; полные данные храни в файлах.
   Если план соответствует ответам, примени его без дополнительного запроса
   разрешения. Если появился новый существенный выбор, уточни только его.
4. Выполни `apply` по [интерфейсу скрипта](references/api.md).
   Проверь список записанных файлов и повторный `inspect`. Для Claude Code
   сверяй обнаружение с живым каталогом по [правилам сред](references/hosts.md).
   Сообщи, какие роли и агенты настроены, и отдели проверку файлов от проверки
   фактического запуска модели.

### На границе записи ролей

- Все роли из общего контракта имеют явное решение пользователя.
- Модель и effort каждого уникального агента показаны и выбраны.
- Новый вариант имени заново проверен через `inspect --names`.
- План построен из свежего снимка; неизвестные поля проекта сохраняет скрипт.

Записывай настройки ролей только через скрипт. При изменении файлов после обсуждения
повтори чтение и согласуй только изменившиеся значения: устаревший план не
перезаписывает более свежие настройки. Ошибка конфигурации требует исправления
конкретной ошибки, а не замены файла пресетом.

## Область настройки

Скилл подготавливает проект к агентной разработке и единолично изменяет настройки
проекта для `sdd-*`. Реализованы аудит требований с установкой/восстановлением mise
и настройка `.sdd/settings.json` версии 1 с моделью/effort связанных агентов.
Настройка зависимостей проекта через mise будет расширять этот процесс; текущий
аудит проверяет только реализованные требования и не переносит зависимости.

Установка mise затрагивает рабочую систему пользователя. Остальные глобальные
настройки среды, права доступа, провайдеры, ключи и MCP не входят в эти этапы.
Аудит не зависит от формата агентского хоста. Для настройки ролей неизвестного
хоста выясни формат и поддерживаемый адаптер; скрипт поддерживает Codex и Claude Code.

В завершение перечисли пройденные этапы, подтверждённые требования, исправления
и оставшиеся препятствия. Успешная настройка ролей сама по себе не подтверждает
соответствие проекта требованиям.

Только при изменении самого скилла читай [проверки разработчика](evals/manual.md).
