# Метрики кода и архитектуры

Конвейер: `make metrics` собирает снимок в `metrics/data/` (скрипты — в `metrics/scripts/`), `make metrics-report`
(metrics/scripts/report.py) выводит производные виды. Основа — план пилота
`ai-sdlc/docs/decisions/research/0013-kotlin-architecture-quality-metrics/pilot-plan.md`.

## Обобщённое и проектное в конвейере

Конвейер устроен так, что обобщённая часть переносится на другой проект
заменой конфигурации, без изменения самих метрик.

| Часть | Статус |
|---|---|
| `drh.py`: DRH, propagation cost, циклические рёбра | **обобщённое** — ввод любой граф зависимостей (CSV `from,to[,weight]`), чистая теория графов |
| `modules.py`: сплочённость, сродство, I/A/D Мартина | **обобщённое** — граф + объявленное разбиение; разбиение — входной параметр, не часть метрик |
| `hotspots.py`: видимость×история, fan-out×история, неявная связность | **обобщённый мост** (статический граф + история git); JVM-специфика — только маппинг класс→файл по пути пакета |
| `crap.py`: CRAP (mcc²×(1−cov)³+mcc) | **обобщённый мост** сложность×покрытие; входы — SARIF полного ряда + пофайловое покрытие |
| `report.py`: виды A–E | алгоритмы переносимы, но опираются на корзины — проектную конфигурацию `_buckets.py` (вид C, горячность на 100 строк, — полностью общий) |
| `history.py`: revisions / coupling / entity-churn / summary | **обобщённое** — вход любой git-лог формата `--rev--date--author` + numstat; семантика code-maat 1.0.4, сверена выводами |
| Сборщик: scc | универсальный инструмент |
| Сборщики: detekt, jacoco, jdeps | привязаны к стеку Kotlin/JVM; для другого стека — свой линтер, свой coverage, свой источник графа зависимостей |
| `coverage.py`: чтение jacoco XML | JVM-специфика формата |
| `deps.py`: фильтр сгенерированного (composition root Kora, OpenAPI) | стек этого проекта |
| `_buckets.py` (CONTEXTS, classify) | проектная конфигурация объявленной архитектуры |
| Охват/исключения (apm_modules, build/generated, `src/main`), префикс `ru.tbank.gp.matcher` | проектные |
| Пороги классификации (сродство: 50/33/25/34%; I/A/D: ≥5 типов; горячие точки: ≥10 ревизий × ≥5% видимости) | калибруемые параметры; дефолты обобщённые |

Перенос на другой проект = заменить `_buckets.py`, фильтры сгенерированного
и охваты в `deps.py`/`coverage.py`; на не-JVM стеке — заменить источник графа
зависимостей, остальное без изменений.

## Что собирает make metrics

| Сигнал | Инструмент | Артефакт |
|---|---|---|
| Сложность и размер функций/классов (mcc, когнитивная, длина, параметры, методы классов) | detekt 1.23.8, задача `detektMetrics`: полный ряд (порог 1 — каждый элемент со своим значением); отбор кандидатов — в представлениях | `detekt-metrics.sarif` |
| LOC/SLOC/комментарии пофайлово | scc 4.1.0 | `scc-metrics.json` |
| Покрытие line/branch (полный тест-прогон, нужен Docker) | jacoco из сборки + `coverage.py` | `coverage-latest.csv` |
| Статический граф зависимостей: классы → пакеты → контексты | jdeps (JDK, по байткоду) + `deps.py` | `deps-class.csv`, `deps-pkg.csv`, `deps-ctx.csv` |
| Частота изменений, co-change пары, churn в строках | `metrics/scripts/history.py` (ранее code-maat 1.0.4 — семантика воспроизведена и сверена) | `revisions.csv`, `coupling.csv`, `entity-churn.csv`, `summary.csv`; вход — `git.log` |

Конфиг метрик detekt: `config/detekt/metrics.yml` поверх проектного
`default-detekt.yml` (merge, второй приоритетнее; без `buildUponDefaultConfig` —
дефолты отключены, в снимок не попадает посторонний шум). Исторические сигналы
считает `metrics/scripts/history.py` по `git.log` — java-зависимости нет; семантика
один-в-один с code-maat 1.0.4 (проверено сравнением выводов на одном логе:
множества строк всех четырёх видов совпадают; отличие — детерминированный
порядок строк при равных ключах сортировки). `summary.csv` — санити-чек
экспорта: числа коммитов/сущностей должны совпадать с ожиданиями по `git.log`.

## Охват и исключения

- Код: `src/main/{kotlin,java}` модулей сборки. Тесты, `build/generated`
  (OpenAPI), `apm_modules/` — исключены; совпадает с jacoco-исключениями
  (`**/openapi/**`, `**/generated/**`).
- История: вся (репозиторий моложе шести месяцев), `--no-merges`,
  `:(exclude)apm_modules`. Ренеймы git вида `path/{old => new}` нормализуются
  к новому пути; миграции «удалили + добавили заново» не склеиваются — такие
  пути попадают в D0 «горячие пути, которых нет на диске».
- Встроенные фильтры code-maat: min-revs 5, coupling ≥ 30%, changeset ≤ 30.

## Определения и их границы

- mcc и когнитивная сложность — определения detekt (считает элвисы, scope
  функции, `catch`). Ряд вёдем только внутри одного инструмента; LOC — только
  по scc, сложность — только по detekt, числа разных инструментов не смешивать.
- «Частота контекста» — число **коммитов**, затронувших контекст, а не сумма
  частот файлов (иначе один коммит считается многократно).
- Покрытие — line/branch по байткоду; это не качество assertions
  (мутационное тестирование — отдельная тема, по плану «перед изменением
  рискового участка»).
- Вес ребра графа зависимостей — число уникальных пар классов, не вызовов.
  Граф строится по байткоду (`jdeps`): рефлексию и строковые ссылки не видит;
  сгенерированное (composition root Kora, OpenAPI-кодогенерация) отфильтровано.
  Всё вне контекстов — одна корзина `legacy`. Сырой вывод jdeps не хранится
  (мегабайты), восстанавливается перезапуском `deps.py`.

## Известные пробелы снимка

- Функции с `@Suppress` невидимы для detekt (12 в проекте: 5×Cyclomatic,
  4×NestedBlockDepth, 3×LongMethod). `@Suppress("ALL")` не видит и
  `ForbiddenSuppress` — контролируется grep'ом.
- Снимок — **полный ряд** (порог 1): медианы и перцентили считаются по нему,
  кандидаты (mcc ≥ 10, длина ≥ 20 и т.п.) отбираются в представлениях.
  Цена — большой SARIF (~157 тыс. строк). Полный ряд восстановлен из истории
  снимка de7b4c11 (исходники с тех пор не менялись); следующий
  `make metrics` перегенерирует его штатно.
- `CognitiveComplexMethod` в проектном конфиге выключен, включается только
  конфигом метрик.
- `LongMethod` меряет только блочные тела; expression-body без длины.

## Производные виды (metrics/scripts/report.py)

- A — коммиты по корзинам (контексты AGENTS.md / плоские пакеты), вся история
  и последние 30 дней;
- B — co-change пары между разными корзинами production-кода;
- C — горячность относительно размера (revs на 100 строк, только .kt);
- D0/D — горячие пути, удалённые при миграции flat→контексты; ownership
  живых горячих файлов (число авторов, доля главного);
- E — покрытие: общий уровень, по корзинам, склейка с горячими файлами
  («без страховки» = revs ≥ 13 и line < 50%).

## Структурные виды (metrics/scripts/drh.py, читает deps-*.csv)

- **DRH** (Design Rule Hierarchy): слои дизайн-правил, циклические ядра,
  листья — на уровнях классов/пакетов/контекстов. Классы — DAG без циклов
  (1023 класса, 7 слоёв), дизайн-правила — типизированные ID и api-модели;
  на пакетном уровне — ядро из 18 пакетов (кластер
  `settings.internal.adapters.outbound.dao.*` + `domain` + `config` +
  `catalog.api.model`) и 4 малых клуба (`matching.internal.temporal.workflow`
  трио, `matching.internal.service` пара, `adapter.kleks.impl↔mapper`,
  orchestration `processor↔reaper`); контекстный клубок 11/11 —
  агрегационный эффект: на классовом уровне циклов нет вовсе.
- **Propagation cost** (MacCormack–Rusnak–Baldwin): доля узлов, транзитивно
  зависящих от данного. Системный: 0.8% (классы) / 13.1% (пакеты);
  топ-классы — типы (`TskuId` виден 23% классов); на пакетном уровне ядро
  settings-DAO делает ~82% пакетов взаимно видимыми.

## Горячие точки (metrics/scripts/hotspots.py)

Мост структура × история: видимость классов (propagation) сцепляется
с ревизиями и churn из git.log. Снимок: **риски разделены** — ни один файл
не является одновременно частым (≥10 ревизий) и видимым (≥5% системы);
дизайн-правила меняются редко, волатильные файлы — листья. Реальные
горячие точки — телеметрия (`TelemetryService` 3.9% × 15 ревизий × 451
строк churn, `MatchingTelemetryGateway` 3.3% × 11) и модельные типы ядра
(`Sku`, `CategoryInfo`, `Task*`: правки редки, но светятся на 5–12% классов).
Оговорка: класс → файл по имени (легли 498/1023 классов: companion-объекты
и мультиклассовые файлы не мапятся), видимость файла = max по его классам.

Два зеркальных вида того же моста:

- **fan-out сторона**: транзитивный охват импортов × частота правок — файлы,
  которые «часто правят И зависят от многого»: первыми чувствуют движение
  контрактов. Снимок: `SupportController` №1 (7.5% системы в импортах,
  35 ревизий), рядом кластер Kleks и ML-адаптеры.
- **неявная связность**: живые co-change пары production-кода без статического
  ребра между файлами — сцепка через общий контракт. Снимок: две пары
  (`MlProxyAdapter ↔ MlGatewayImpl` 71% с общим контрактом `adapter.ml`;
  Kleks-маппер ↔ модель 76%). Мёртвых пар (миграция разорвала сцепку) — 17.

## Метрики модулей (metrics/scripts/modules.py и циклические рёбра в drh.py)

Обобщённые метрики над пакетным графом + объявленным разбиением
(конфигурация разбиения — `_buckets.CONTEXTS`, метрики от проекта не зависят):

- **Сплочённость модуля** — внутренние рёбра / все рёбра модуля. Снимок:
  `settings` 61% (лидер), `deduplication` 50%, `matching` 29%,
  `categorization` 21%, `brand` 15%.
- **Сродство узла с модулями** (declared vs actual) — доля внешнего веса
  узла в каждый объявленный модуль; классы: согласован / смещён / мост /
  сирота / серая зона (необъявленная масса забирает больше 2/3 связи —
  нормальное состояние системы в миграции). Снимок: 71 пакет в серой зоне,
  23 смещённых, 29 необъявленных с явной доминантой.
- **I / A / D по Мартину** — Instability (fan-out/(fan-in+fan-out) по внешним
  рёбрам), Abstractness (доля интерфейсов/abstract-классов, эвристика по
  исходникам), Distance = |A+I−1|. «Зона боли» = стабильный и конкретный.
  Снимок: зона боли — типовые ядра (`sharedKernel`, `settings/catalog/tsku.api.model`,
  `domain`) при A≈0: data-классы без абстракций.
- **Циклические рёбра** (в `drh.py`) — рёбра, замыкающие циклы SCC, и жадная
  оценка числа инверсий для разрыва клубка. Снимок: ядро из 18 пакетов —
  13 инверсий (лидер `settings.internal.domain → settings.api.model`, 68),
  малые клубки — по 1–3.

## CRAP (metrics/scripts/crap.py)

CRAP = mcc² × (1 − line-coverage)³ + mcc (Савойя/Эванс): сложность,
не покрытая тестами; порог беспокойства 30 из первоисточника. mcc — сумма
по функциям класс-файла из полного ряда SARIF, покрытие — пофайловое из
`coverage-latest.csv`; уровни: класс-файл → пакет → контекст (плоские
пакеты — legacy). Снимок: `SupportController` — 2905 (mcc 59 × 6% line,
№1 с отрывом ×6), `DefaultKleksAdapter` — 2414; legacy ΣCRAP 8584 при 22
файлах выше порога — против 1433 у ближайшего контекста; всего CRAP > 30
у 59 файлов из 364 покрытых.

## Базовый срез (2026-11-02/03, d8c2af3f..de7b4c11)

- mcc: 2207 функций, медиана 1, p90 = 4, p99 = 8, max 13 (+5 подавленных) —
  локальная сложность проблемой не является; крупнейший класс — 13 методов
  (3 класса выше порога 10);
- покрытие: line 69%, branch 55%; контексты 69–89%, `flat:adapter` — 52/28;
- хотспот №1 — `SupportController` (35 коммитов, mcc Σ 59, line 6%);
- co-change риск — в плоских пакетах (`service↔workflow`, ML-группа,
  task-DAO трио); пар между контекстами нет;
- статический граф (jdeps, 3788 рёбер): потребители (matching 724 исх.,
  categorization 265, dedup, groupidReconcile) и поставщики (orchestration
  243 вх., catalog 214, tsku 203, brand); контексты тянут из `legacy`
  873 ребра против 274 обратно (3.2×); самое тяжёлое ребро —
  `matching → legacy` (293);
- DRH: классы — DAG из 7 слоёв (1023 класса, циклов нет), дизайн-правила —
  типы (`TskuId` виден 23% классов, `CategoryInfo` 12%); пакетное ядро
  settings-DAO (18 пакетов) + 4 малых клуба; propagation cost 0.8% (классы) /
  13.1% (пакеты);
- горячие точки (видимость × история): ноль файлов «частых и видимых»;
  топ — телеметрия (`TelemetryService` 3.9% × 15 ревизий) и типы ядра
  (`Sku` 11.5%, `CategoryInfo` 12% при редких правках);
- CRAP: `SupportController` 2905 и `DefaultKleksAdapter` 2414 — вне лиги
  остальных; 59 файлов выше порога 30, из них 22 — в legacy.

## Воспроизводимость вручную

```sh
./gradlew detektMetrics
scc --by-file --format json --no-cocomo -o metrics/data/scc-metrics.json app/src/main/kotlin
./gradlew :app:jacocoTestReport && python3 metrics/scripts/coverage.py
python3 metrics/scripts/deps.py
git log -M -C --numstat --date=short --pretty=format:'--%h--%cd--%cn' --no-merges \
  -- . ':(exclude)apm_modules' > metrics/data/git.log
python3 metrics/scripts/history.py
python3 metrics/scripts/report.py
python3 metrics/scripts/drh.py
python3 metrics/scripts/hotspots.py
python3 metrics/scripts/modules.py
python3 metrics/scripts/crap.py
```
