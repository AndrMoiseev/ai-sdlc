# Командная память для агентов. Обзор открытых проектов

21 ноября 2026 года · 103 проекта · обзор по первоисточникам

Как дать агенту одного проекта знания, накопленные всей командой, и возможность проверить, откуда они взялись и продолжают ли действовать? В каталоге есть готовые командные системы, библиотеки для сборки своей БЗ и примеры внедрения. Предыдущее исследование посвящено памяти отдельного проекта. Здесь рассматривается повторное использование знаний за его пределами. [Исследование № 0010](../0010-ai-sdlc-project-memory-and-github-landscape.md)

**Как читать карточки.** В карточке указано, что именно агент сможет предъявить по описанию авторов. Это может быть запись о сессии, документ, версия, фрагмент, точная цитата или коммит. Ссылка на исходник позволяет агенту проверить вывод. Отдельной проверки требуют соответствие цитаты смыслу вывода и применимость вывода к другому проекту. В последней содержательной колонке различаются обновление поискового индекса, исправление самого знания и пересмотр зависимых выводов.

**Масштаб и доступ.** Общая папка позволяет нескольким агентам читать одинаковый текст. Сервер с несколькими пользователями, поиск по выбранным проектам и наследование прав оригинального источника — дополнительные возможности. Они указаны там, где их описывает первоисточник. MCP (Model Context Protocol) даёт агенту инструменты для вызова. REST, CLI и SDK тоже подходят для агентского поиска, хотя могут потребовать обёртки.

## Основание обзора и границы проверки

Поиск шёл по разным формулировкам задачи, в том числе *cross-project team memory*, *source-backed facts*, *claim evidence provenance*, *connector sync*, *temporal agent memory*, *GraphRAG source chunks* и *engineering decision drift*. Включены проекты, для которых удалось найти первоисточник с открытым кодом интересующего компонента и конкретный способ решить хотя бы часть задачи. Переименования, SDK и облачную редакцию того же продукта считали одной позицией. В каждой строке ссылки ведут к материалам авторов. Лицензия относится к указанному коду, у внешней модели, сервера или коммерческого модуля могут быть свои условия.

Граница открытого кода повлияла на выбор. Например, у Hunch действующая FSL ограничивает конкурирующее использование и предусматривает переход версии на Apache-2.0 через два года. Для самостоятельного развёртывания сервер Supermemory поставляется из закрытого исходного кода. Обе позиции исключены из числа проектов выше. [Лицензия Hunch](https://github.com/davesheffer/hunch/blob/main/LICENSE) · [условия поставки Supermemory](https://github.com/supermemoryai/supermemory/blob/main/apps/docs/self-hosting/overview.mdx)

Из FPF применены KCAE.SEARCH для расширения поиска за пределы продуктов с названием «память», KCAE.ASSESS для ограничения каждого вывода тем, что показывает источник, и A.10 для различения утверждения, его носителя и конкретного свидетельства. [FPF Library, использованная редакция](https://github.com/ailev/FPF/commit/1e57ccda08ebbb9d49b7b2190bc2740b72075a13)

Это обзор документации, схем, примеров API и опубликованного кода. Продукты не разворачивались. Качество поиска на материалах команды, полнота выдачи на русском, корректность отзыва при удалении источника и соблюдение межпроектных прав остаются вопросами практической проверки.
