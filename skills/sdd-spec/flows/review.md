# Независимое ревью

Для refactoring используй [формат и предмет ревью](../references/refactoring.md#ревью-и-согласование): documents содержит proposal/design, plan добавляет tasks. Передай вид и полный корень; отсутствие specs не является дефектом. Обычные правила consent, линз и неизменности входов сохраняются.

Перед запуском разреши [настройки субагентов](../../sdd-shared/references/subagents.md):
`sdd-spec.document_reviewer` для каждой линзы документов либо `sdd-spec.plan_reviewer`
для каждой из двух линз плана. Для simplicity после выбора модели подготовь
[общую инструкцию и модельное дополнение](../references/simplicity-instructions.md).
Сохрани выбор, дополнение и наблюдения запуска рядом с отчётом в отдельном JSON;
модель из конфигурации не заменяет согласие на ревью и чистый контекст.

Перед шагом 3 учти [выбор гуманизации](../references/editorial-pass.md). Если проход согласован,
заверши его либо зафиксируй ограничение до фиксации основания ревью.
Рецензенты читают неизменяемое дерево коммита независимо от последующих рабочих правок.

1. Прочитай текущие документы, [общую основу](../../sdd-shared/references/document-format.md), [нормативный формат](../../sdd-shared/references/document-format-normative.md) и [формат ревью и согласований](../../sdd-shared/references/document-format-review.md); для стадии plan добавь [формат задач](../../sdd-shared/references/document-format-tasks.md); передай [explorer](../references/explorer.md) check для `documents` или `plan`. До ревью устрани структурные ошибки по [runtime](../references/runtime-setup.md). По [discussion](../references/discussion.md) проверь журнал, вопросы и основания существенных положений: до готовности закрой блокирующие выборы, включая обнаруженные при чтении черновика.
2. Для документов всегда включай встроенные [consistency](../references/consistency.md) и [simplicity](../references/simplicity.md). Прочитай `sdd/arch-lenses/index.md`: отсутствие файла или `lenses: []` оставляет обе встроенные линзы. Для каждой записи индекса добавь указанную линзу; случайные файлы каталога не подключай. Повтор ID, зарезервированные `consistency`, `simplicity`, `plan`, неразбираемый индекс или неразрешимый path — ошибка. Перечитывай индекс при каждом входе: новая линза означает недостающее ревью, даже без изменения документов. Для плана всегда назначай две линзы: [plan](../references/reviewer-plan.md) и [simplicity](../references/simplicity.md); проектные линзы относятся к стадии документов.
3. Заверши авторские правки через [checkpoint](../references/checkpoint.md) и зафиксируй полный OID основания. Назначь уникальный run-id из UTC-времени и суффикса. Покажи пользователю стадию, полный перечень линз и предмет проверки. Получи явное согласие на конкретный запуск, сохрани `review_consent` с run-id, областью и basis_commit в decisions. Уже полученное согласие на этот запуск не запрашивай повторно. Пропуск не требует `review_waiver` или ответа на предложение: ревью опционально по [общим правилам](../../sdd-shared/references/document-format-review.md#опциональное-ревью-и-разрешение-на-реализацию).
4. Используй зафиксированный коммит как `reviewed_commit`; запись consent и сами отчёты сохраняй следующим checkpoint. Все линзы читают одно его неизменяемое дерево: proposal, design, все specs, а для плана также tasks. Передай доступ через Git object reads либо проверенную внешнюю копию этого дерева; пути рабочего дерева без гарантии соответствия коммиту недостаточны.
5. Создай нового рецензента с чистым контекстом для каждой линзы на обеих стадиях. Для plan передай [задание плана](../references/reviewer-plan.md); для остальных, включая simplicity плана, — [контракт рецензента](../references/reviewer-documents.md) и выбранную линзу. Передай stage, reviewed_commit, пути всего комплекта в неизменяемом дереве, проектные ограничения и релевантные источники. Обе линзы плана читают proposal/specs/design/tasks; для refactoring — proposal/design/tasks. Не передавай историю, рассуждения автора или отчеты других рецензентов. Используй [адаптер Codex](../references/codex.md), [Claude Code](../references/claude-code.md) либо [произвольного агента](../references/generic.md); при лимите агентов запускай последовательно, сохраняя одинаковые входы. Рецензенты только читают и возвращают отчет, основной агент сохраняет файлы.
6. После возврата всех результатов проверь фактически прочитанное основание. Основной агент сохраняет каждый отчет по [шаблону](../templates/review-report.md) в `review/<run-id>/<lens-id>.md`, используя run-id согласованного запуска этой стадии. Для плана это отдельные `plan.md` и `simplicity.md`; отчёт simplicity документов не покрывает план. Не перезаписывай предыдущие отчеты. Если источник критичен и недоступен, агент упал, контекст не удалось изолировать или отчет неверен, сохрани доступный результат с `incomplete` и причиной. Не додумывай успешный вывод за рецензента.
7. Сохрани `reviewed_commit` отчёта. Если рецензент читал рабочие файлы без доказанного соответствия этому коммиту, запиши `incomplete` и ограничение; не выдумывай основание. Изменение HEAD после ревью даёт диагностику `changed_since_review`, а недоступный исторический коммит — `evidence_unavailable`; они не отменяют поручение.
8. Покажи изменения после reviewed_commit и их последствия, покрытие линз, отсутствующие отчёты и ограничения. Существенные внешние источники оцени отдельно. Повторное ревью остаётся опцией; принятие текущего состояния не требует повторного обхода истории. Сохрани отчёты следующим checkpoint и перейди к [рассмотрению](user-review.md).

Завершение запуска: исходные отчеты сохранены с ограничениями и reviewed_commit, покрытие линз и актуальность проверены, checkpoint записан. Наличие отчета не означает согласие пользователя с его находками.
