# Вопросы изменения

Храните здесь открытые и закрытые вопросы: один Q-ID — один отдельный выбор.
Части, которые пользователь может выбрать независимо, оформляйте разными Q-ID.
Порядок отражает зависимости: результат и границы раньше деталей. Покажите вопросы
и варианты в сообщении; можно несколько сразу, с явной границей каждого выбора.
При просьбе пользователя задавайте по одному. Удалите пример при записи реальных вопросов.

### Режим выполнения

```yaml
sdd_record: question
id: Q-execution-mode
text: Какой режим выполнения использовать по умолчанию?
blocking: true
status: open
```

Причина: выбор меняет поведение запуска без параметров.
Варианты и рекомендация: опишите варианты с существенными компромиссами.
Затронутые документы: дайте ссылки на существующие положения черновика.
Предложение и источник рекомендации: [запись журнала](decisions.md#режим-выполнения).

Для открытого неблокирующего вопроса добавьте `reason` и конкретный `return_at`.
При закрытии задайте `status: resolved` и `resolution: decisions.md#режим-выполнения`
либо путь к проверенному источнику. Это строка с относительным путём от каталога
изменения, без Markdown-обёртки; файл должен существовать, якорь после `#` непустой.
Для существенного выбора основание содержит ответ пользователя либо решение
агента по явному поручению решить показанный список Q-ID. Исследование или общее
согласование комплекта его не заменяет. Новые вопросы требуют нового решения.
Любой открытый Q препятствует финальному утверждению; рекомендации не являются Q.
Проверенный источник может закрыть фактический вопрос. Сохраните исходный вопрос,
точный ответ и ссылку на основание; не удаляйте историю.
