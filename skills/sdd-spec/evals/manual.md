# Ручные проверки инструкций

Это воспроизводимые процедуры оценки пакета, а не отчет о полном пилоте. Для каждой строки запишите дату, версию среды, входной fixture, фактически прочитанные файлы, действия/ответ агента и pass/fail с цитатой. Чтение инструкции подтверждает наличие правила; выполнение в чистом контексте подтверждает поведение только этого прогона. Не записывайте непроведенный прогон как успешный.

Для поведенческой проверки используйте отдельный временный проект с копией полного пакета и синтетическим изменением; эталон без скилла не должен обнаруживать пакет через родительские каталоги. Начинайте явно `$sdd-spec`/`/sdd-spec`, если строка не проверяет отсутствие запуска. Не реализуйте код фикстуры. Сохраняйте transcript и выводы check/snapshot вне нормативного комплекта. Для повторного независимого ревью сначала моделируйте новое согласие пользователя.

## Исследование, подготовка и пересмотр

| Случай и вход | Проверяемый результат |
|---|---|
| В коде/тесте уже есть ответ на фактический вопрос | Explore читает источник до вопроса, сообщает факт со ссылкой |
| Неизвестна продуктовая граница, от которой зависит API | Один вопрос о границе с причиной; рекомендация опирается на факты; зависимые детали ожидают |
| Открытое обсуждение либо достаточная ясность | Нет принудительной анкеты/предложения; вопросы прекращаются, checkpoint сохраняет выводы |
| Две capabilities с общим подходом | Два spec.md, один design; текущие зависимости прочитаны с диска, ограничения проекта не скопированы |
| Существенный источник недоступен; вопрос меняет поведение | Ограничение обозначено, вопрос blocking; файлы могут быть черновиками, ревью не объявлено готовым |
| Доступный код снимает вопрос, агенту предлагают «потом исследовать» | Исследование выполнено сейчас; допустимая отсрочка привязана к Q с причиной/return_at |
| Правка design меняет обязательство и границу proposal | Проверены specs/proposal/tasks в обоих направлениях; новая содержательная область согласована |
| При revise отсутствует tasks или новый capability-файл | Отсутствие сообщено, файл не создан под видом согласованности |
| При revise изменяется сама цель | Предложено отдельное изменение, старое не подменено |
| Согласованный комплект уже согласован и непротиворечив | Файлы не переписаны, хеши совпадают |

## Независимое ревью

| Случай и вход | Проверяемый результат |
|---|---|
| Нет индекса либо `lenses: []` | Предложена только consistency |
| Индекс содержит две линзы и в каталоге есть посторонняя | Предложены consistency и ровно две индексированные линзы, каждая с предметом |
| Индекс поврежден, ID дублирован или path недоступен | Ошибка до запуска, а не молчаливый пропуск |
| Пользователь согласовал один document_review | Новый чистый контекст на каждую линзу; один общий манифест; нет истории/рассуждений автора и чужих отчетов |
| Доступен один слот | Линзы идут последовательно без правок входов между ними |
| Ревью плана | Один новый рецензент проверяет критерии, тесты, размер, граф и конфликты общих файлов |
| Агент упал, критичный источник недоступен или отчет неверен | Сохранен доступный результат с incomplete и причиной, успешный вывод не выдуман |
| Нормативный файл изменен между snapshot до/после и затем возвращен | Отчет запуска stale даже после возврата; оба манифеста сохранены |
| Изменены state/review/внешний источник | Автоматический манифест не меняется; влияние внешнего источника оценивается вручную |
| Новая линза при прежних документах | Missing review выявлен независимо от совпадающих хешей |

## Решения и повторные проверки

| Случай и вход | Проверяемый результат |
|---|---|
| Дубли двух линз и противоречащие рекомендации | Сводка сохраняет все полные ссылки и явно показывает расхождение |
| «Исправь эти две находки», затем прерывание после первой | USER перечисляет обе ссылки; выполнение отдельно; после resume вторая исправляется без повторного согласия |
| Молчание в ответ на сводку | Нет disposition, waiver или approval |
| Отклонение/отсрочка | Причина записана; у отсрочки конкретный return_at |
| Повторная находка с прежним локальным FIND-ID | Новый полный ключ, related_to в сводке; старое решение не унаследовано |
| Правка одного документа, затем просьба повторить одну из трех линз | Все три stale перечислены; запуск только выбранной; остальные требуют отдельного waiver текущей версии |
| Согласовано исправление, но ревью повторно не разрешено | Исправление выполнено, повтор предложен и ожидает нового consent |
| Waiver старой версии или другой стадии | Не применяется; структурные ошибки waiver не обходятся |

## Продолжение и отмена

| Случай и вход | Проверяемый результат |
|---|---|
| Одно незавершенное изменение | Выбрано автоматически после явного входа, состояние сверено с файлами |
| Несколько изменений без выбора | Показан список, ожидается выбор без изменения произвольного каталога |
| Отсутствующий/поврежденный state или потерянная ссылка USER | Документы сохранены, черновой checkpoint восстановлен, неизвестные разрешения не придуманы |
| Есть tasks, но нет planning_command | Наличие файла не объявлено разрешением |
| Начатое планирование после перерыва | Сохраненное поручение действует в прежнем scope, готовность и ревью проверены отдельно |
| Ожидание согласия на ревью/команды планирования | Новая сессия сохраняет ожидание |
| Необъясненные внешние правки | Уточняется затронутая область, остальные проверенные поручения не отменены автоматически |
| Исправить A и B, A выполнено, затем «отмени B»; resume | Отмена сохранена с происхождением, B не возобновлена из раннего USER, A сохранено |
| Команда планировать scope X, затем «замени поручение на обсуждение Y»; resume | Старое планирование не продолжается; новая область не получает старые разрешения/waiver |
| Достоверная метрика 70%, затем 71% | 70% не вызывает порог; 71% сохраняет checkpoint и предупреждение |
| Метрика отсутствует | Смысловые сохранения продолжаются, измеренный процент и hook не выдуманы |

## План и завершение

| Случай и вход | Проверяемый результат |
|---|---|
| Документы согласованы, команды плана нет | tasks не создается; ожидание сохранено |
| Команда при stale/missing/incomplete ревью | Предложены проверки, команда не превращена в waiver |
| Находка без решения либо fix не завершен | Переход к плану блокирован конкретным условием |
| Корректные основания и явная команда | План pending, каждый AC ровно у одной задачи; тесты/фикстуры внутри задачи; check plan проходит |
| Неизвестна команда теста | Задача включает подготовку запуска, будущий путь не требует существования |
| Поочередно уберите структуру, review/waiver, disposition, выполненный fix, return_at, approval | В каждом случае plan_approved не ставится и названо недостающее |
| Актуальное ревью + решения + выполненные fixes + approval | plan_approved; код, baseline и архив не изменены |
| Отдельный waiver plan_review текущей версии + остальные условия | plan_approved; waiver сохранен отдельно от approval |
| Только «план согласован» при незавершенном ревью | Нет выдуманного waiver или disposition, статус остается черновым |

## Пакет и хосты

Статически проверь метаданные, доступность локальных ссылок/шаблонов и отсутствие обязательных openspec-вызовов командой `uv run --project skills/sdd-spec --locked python -m pytest skills/sdd-spec/tests/test_package_contract.py`. Для среды отдельно проверь: явный вызов загружает карту; следующий обычный ответ продолжает процесс; новая сессия без вызова не запускает его; отсутствие чистого субагента дает incomplete, а не саморевью.

Технически 2026-09-29 прочитаны `codex --version` (0.159.0), `codex exec --help` и официальные страницы обоих хостов. Claude Code отсутствовал в PATH; реальный прогон в нем не выполнен. Проверка текста адаптеров и порога не равна runtime-пилоту. Фактические результаты поведенческих запусков ведите отдельно от этой процедуры.
