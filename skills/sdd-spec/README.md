# SDD Spec

`sdd-spec` помогает превратить идею изменения в согласованный план разработки. Вместе с агентом вы уточняете задачу, описываете ожидаемое поведение и выбираете техническое решение. Затем независимые рецензенты проверяют документы, а вы решаете, что исправить и с чем согласиться.

В SDD (разработке по спецификациям) этот скилл отвечает за подготовку изменения. На выходе остаются требования с критериями приёмки, дизайн решения и план задач с проверками. Реализацию по этому плану выполняет [`sdd-apply`](../sdd-apply/SKILL.md), который вызывается отдельно.

## Основной сценарий

Начните с явного вызова: `$sdd-spec` в Codex или `/sdd-spec` в Claude Code. После этого можно продолжать обычным диалогом.

1. **Обсудить задачу.** Агент изучает проект, уточняет цель и границы изменения, разбирает риски. Существенные решения принимаете вы.
2. **Подготовить черновик.** В нём описаны цель изменения, требования с критериями приёмки и обязательный дизайн решения. Черновик можно сохранить с открытыми вопросами и продолжить обсуждение.
3. **Проверить документы.** Когда блокирующие вопросы закрыты, агент предлагает независимое ревью: проверку согласованности документов и дополнительные проверки, принятые в проекте. Вы разрешаете запуск, затем разбираете замечания: исправить, отклонить с причиной или отложить с условием возврата.
4. **Согласовать требования и дизайн.** Агент вносит выбранные исправления и проверяет, что ревью относится к текущей версии. После вашего согласования он ждёт отдельной команды составить план.
5. **Подготовить и согласовать план.** Агент разбивает работу на задачи, связывает их с критериями приёмки, добавляет проверки и зависимости. План проходит отдельное ревью и разбор замечаний. Ваше явное согласование завершает работу sdd-spec.

[![Основной сценарий sdd-spec с возвратами на исправление документов и плана](../../docs/diagrams/sdd-spec/spec-workflow.png)](../../docs/diagrams/sdd-spec/spec-workflow.html)

Документы и принятые решения сохраняются в каталоге изменения. После перерыва можно продолжить с того места, где остановились.

## Вариации

| Ситуация | Как пойдёт работа |
| --- | --- |
| Пока есть только идея | Можно ограничиться исследованием, сравнением подходов и обсуждением рисков. |
| Уже есть ТЗ | Начните с черновика по ТЗ. Агент сверит его с проектом и вынесет недостающие решения на обсуждение. |
| Изменение небольшое | Объём документов будет соразмерен задаче; дизайн, проверяемые требования и согласования сохраняются. |
| Требования изменились | Агент пересмотрит связанные документы и укажет, какие ревью и согласования устарели. |
| Решение трудно оценить по спецификациям | Закажите пояснение с диаграммами Archify. Его можно подготовить или обновить отдельно. |
| Нужен более естественный русский текст | Попросите отредактировать документы через `humanizer-ru`. Если текст изменится после ревью, агент заново проверит его актуальность. |
| Работа прервалась | Агент восстановит этап, открытые вопросы и действующие поручения, затем продолжит незавершённую работу. |

Пропустить ревью можно только по отдельному явному решению о конкретной проверке и текущей версии документов. Команда «составь план» сама по себе такого разрешения не даёт.

## Примеры промптов

В примерах используется Codex; для Claude Code замените `$sdd-spec` на `/sdd-spec`.

**Исследовать идею**

```text
$sdd-spec Хочу добавить экспорт заказов в CSV. Изучи текущую работу
с заказами, помоги определить границы первой версии и риски.
Пока ограничимся исследованием.
```

**Подготовить документы по готовому ТЗ**

```text
$sdd-spec Подготовь черновик изменения order-export по docs/export-brief.md.
Опиши требования, критерии приёмки и дизайн. Сохрани открытые вопросы
и обсуди со мной решения, которых не хватает в ТЗ.
```

**Пересмотреть существующее решение**

```text
$sdd-spec В order-export экспорт должен учитывать активные фильтры
списка заказов. Пересмотри связанные требования и дизайн.
Покажи, какие прежние проверки и согласования нужно повторить.
```

**Объяснить решение перед согласованием**

```text
$sdd-spec Поясни решение order-export для владельца продукта.
Нужен короткий текст и диаграммы Archify: путь пользователя,
подготовка CSV и обработка ошибок.
```

**Запустить предложенное ревью**

```text
Согласен на предложенный запуск ревью документов order-export
по всем перечисленным проверкам. После него покажи замечания
для моего решения.
```

**Перейти к планированию после разбора замечаний**

```text
Согласовываю текущие требования и дизайн order-export.
Составь план реализации: задачи, зависимости и проверки
критериев приёмки. Покажи, что можно выполнять параллельно.
```

**Продолжить после перерыва**

```text
$sdd-spec Продолжи order-export. Проверь сохранённые документы,
решения и актуальность ревью. Вернись к ближайшему открытому
вопросу или продолжи уже порученную работу.
```

**Отредактировать текст перед ревью**

```text
Прогони требования и дизайн order-export через humanizer-ru.
Сохрани смысл требований, критерии приёмки и принятые решения.
```
