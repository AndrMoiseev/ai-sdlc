# SDD Spec

`sdd-spec` помогает превратить идею изменения в согласованный план разработки. Вместе с агентом вы уточняете задачу, описываете ожидаемое поведение и выбираете техническое решение. По вашему желанию независимые рецензенты проверяют документы, а вы решаете, что исправить и с чем согласиться.

В SDD (разработке по спецификациям) этот скилл отвечает за подготовку изменения. На выходе остаются требования с критериями приёмки, дизайн решения и план задач с проверками. Реализацию по этому плану выполняет [`sdd-apply`](https://github.com/AndrMoiseev/ai-sdlc/blob/main/skills/sdd-apply/SKILL.md) по вашему явному поручению. Утверждение плана само по себе не запускает работу.

Документы готовит отдельный агент-архитектор. Он ведёт весь комплект, пояснения
и сводки замечаний, вносит согласованные исправления. Основной агент общается
с вами, передаёт архитектору ваши решения и сохраняет состояние работы.
При продолжении архитектор получает прежние документы и решения; повторять
обсуждение из-за смены его сессии не требуется.

## Основной сценарий

Начните с явного вызова: `$sdd-spec` в Codex или `/sdd-spec` в Claude Code. После этого можно продолжать обычным диалогом.

1. **Обсудить задачу.** Агент изучает проект и явно показывает существенные развилки с вариантами и последствиями. Можно обсудить несколько вопросов сразу или попросить задавать их по одному.
2. **Подготовить черновик.** Агент описывает цель, требования, критерии приёмки и дизайн. Открытые вопросы можно продолжить обсуждать или поручить агенту решить показанный список. Он сообщит свои решения и уточнит, нужно ли ревью. Новые вопросы требуют нового решения.
3. **Выбрать следующий шаг.** Когда вопросов нет, агент предлагает написать план или провести независимое ревью подготовленных документов. Спецификация отдельно не утверждается.
4. **Подготовить план.** По вашему поручению агент составляет задачи, проверки и зависимости. Спецификация, дизайн и план образуют единый комплект.
5. **Утвердить комплект.** Когда все вопросы закрыты, выберите ревью всего комплекта или утверждение без агентского ревью. Для начала реализации нужно явное поручение, например: «Комплект утверждён, выполняй план». Действующее разрешение повторно подтверждать не нужно.

Агент сохраняет завершённую часть работы коммитом Git. Перед продолжением он проверяет, что файлы не изменены и текущий коммит совпадает с принятой точкой. Если появились другие правки или коммиты, агент покажет их для вашего решения. Если вы примете текущее состояние, прежнее поручение продолжит действовать в согласованных границах. Новые задачи требуют отдельного поручения.

## Вариации

Исследование помогает выбрать направление и сравнить варианты. Каждое существенное
решение агент обозначает явно. Принятый отчёт не разрешает молча выбрать все его
рекомендации; вы можете выбрать варианты сами или делегировать показанный список.

Для поиска фактов агент может привлечь explorer: он вернёт выводы со ссылками
на исходники и укажет, что осталось непроверенным. Explorer также запускает
проверки структуры документов. Их успех означает, что комплект оформлен правильно;
содержание отдельно оценивают рецензенты, если вы поручили ревью.
Согласования остаются за вами. Результаты
исследования хранятся во временной папке; если она удалена, при продолжении
агент сообщит, какие доказательства потеряны.

| Ситуация | Как пойдёт работа |
| --- | --- |
| Пока есть только идея | Можно ограничиться исследованием, сравнением подходов и обсуждением рисков. |
| Уже есть ТЗ | Начните с черновика по ТЗ. Агент сверит его с проектом и вынесет недостающие решения на обсуждение. |
| Изменение небольшое | Объём документов будет соразмерен задаче; дизайн, проверяемые требования и согласования сохраняются. |
| Требования изменились | Агент пересмотрит связанные документы и покажет последствия для прежних ревью и области согласования. |
| Решение трудно оценить по спецификациям | Закажите пояснение с диаграммами Archify. Его можно подготовить или обновить отдельно. |
| Нужен более естественный русский текст | Попросите отредактировать документы через `humanizer-ru`. Если текст изменится после ревью, агент заново проверит его актуальность. |
| Работа прервалась | Агент восстановит этап, открытые вопросы и действующие поручения, затем продолжит незавершённую работу. |

Рекомендации можно проигнорировать без ответа, объяснений и дополнительных действий. Если вы хотите отклонить или отложить рекомендацию, причина и срок возврата необязательны. Прежнее решение сохраняется для повторной находки, если её смысл и обстоятельства не изменились. Реальные открытые вопросы агент показывает отдельно и не предлагает утверждение до их закрытия.

Каждое ревью охватывает все документы, подготовленные к этому моменту.
Consistency проверяет согласованность, simplicity ищет лишнюю сложность,
premortem разбирает, почему работа может не дать нужного результата. При наличии плана
отдельный рецензент plan проверяет задачи и зависимости. Агент добавляет проверки,
заданные в проекте; simplicity выполняется один раз для всего комплекта.
Каждый рецензент читает одну и ту же версию и возвращает собственный отчёт.
[Происхождение критериев простоты](references/simplicity-origin.md).

Вы можете запросить ревью ещё до закрытия вопросов. Агент передаст их рецензентам,
предварительно исправив структурные ошибки. Новые вопросы из ревью снова
возвращаются к вам; прежнее поручение решить вопросы на них не распространяется.

Часть инструкций адаптирована из OpenSpec; [источник и лицензия](references/openspec-origin.md) сохранены в пакете.

## Примеры промптов

В примерах используется Codex; для Claude Code замените `$sdd-spec` на `/sdd-spec`.

**Исследовать идею**

```text
$sdd-spec Хочу добавить экспорт заказов в CSV. Изучи текущую работу
с заказами, помоги определить границы первой версии и риски.
Пока ограничимся исследованием.
```

**Подготовить документы по готовому ТЗ**

```text
$sdd-spec Подготовь черновик изменения order-export по docs/export-brief.md.
Опиши требования, критерии приёмки и дизайн. Сохрани открытые вопросы
и обсуди со мной решения, которых не хватает в ТЗ.
```

**Пересмотреть существующее решение**

```text
$sdd-spec В order-export экспорт должен учитывать активные фильтры
списка заказов. Пересмотри связанные требования и дизайн.
Покажи последствия для прежних проверок и области согласования.
```

**Объяснить решение перед согласованием**

```text
$sdd-spec Поясни решение order-export для владельца продукта.
Нужен короткий текст и диаграммы Archify: путь пользователя,
подготовка CSV и обработка ошибок.
```

**Запустить предложенное ревью**

```text
Согласен на предложенный запуск ревью документов order-export
по всем перечисленным проверкам. После него покажи замечания
для моего решения.
```

**Перейти к планированию после разбора замечаний**

```text
Открытые вопросы order-export закрыты. Перейдём к плану.
Составь план реализации: задачи, зависимости и проверки
критериев приёмки. Покажи, что можно выполнять параллельно.
```

Для уже подготовленного пояснения или плана выберите нужное продолжение.

| Действие | Пример запроса | Ожидаемый результат |
| --- | --- | --- |
| Обновить пояснение | `$sdd-spec Обнови существующее пояснение order-export по текущим требованиям и дизайну. Исправь затронутые диаграммы и проверь остальные.` | Агент сверит источники и обновит пояснение в порученной области. |
| Доделать превью | `$sdd-spec Продолжи незавершённые превью order-export по sdd/changes/order-export/archify/preview-handoff.md. Сохрани готовые актуальные изображения.` | Агент выполнит оставшиеся проверки и заменит подготовленные заглушки. Если завершить их нельзя, укажет причину и оставшуюся работу. |
| Провести ревью всего комплекта | `Проведи независимое ревью всех текущих документов order-export, включая план.` | Общие рецензенты и отдельный рецензент плана вернут отчёты; агент покажет результат и новые вопросы. |
| Утвердить комплект и начать реализацию | `Утверждаю весь комплект order-export со спецификацией, дизайном и планом. Выполняй план.` | При закрытых вопросах и корректной структуре агент сохранит утверждение и перейдёт в sdd-apply. |
| Только утвердить комплект | `Утверждаю весь комплект order-export со спецификацией, дизайном и планом.` | Агент сохранит утверждение и будет ждать явного поручения на выполнение. |

**Продолжить после перерыва**

```text
$sdd-spec Продолжи order-export. Проверь сохранённые документы,
решения и актуальность ревью. Вернись к ближайшему открытому
вопросу или продолжи уже порученную работу.
```

**Отредактировать текст перед ревью**

```text
Прогони требования и дизайн order-export через humanizer-ru.
Сохрани смысл требований, критерии приёмки и принятые решения.
```

## Рефакторинг с сохранением поведения

В активном процессе можно менять внутреннее устройство, сохраняя внешний контракт.
Агент сообщит выбранный маршрут и его границы. При ясной цели отдельное подтверждение
маршрута не требуется; при конфликте с поведением понадобится ваш выбор.

Агент запишет результат в `sdd/refactoring/<id>/`: цель и границы в proposal,
критерии результата и сохранения поведения в design, по команде планирования также задачи. У каждой задачи есть свой проверяемый результат.
Несколько задач могут вместе достигать общей цели, которую отдельно проверяют в финале.

| Запрос | Ожидаемый результат |
| --- | --- |
| `$sdd-spec Подготовь рефакторинг product-id: выдели внутренний ProductId для core, orders и inventory. Сохрани форматы API и ошибки.` | Черновик цели и дизайна, источники сведений о текущем поведении и открытые вопросы. |
| `$sdd-spec Убери повторяющуюся обработку идентификаторов в этих модулях, сохранив поведение. Подготовь документы.` | Агент выберет маршрут по смыслу и сообщит его до работы. |
| `$sdd-spec Приведи идентификаторы в порядок; ещё не решил, сохранять число или перейти на UUID в API.` | Исследование доступных источников и вопрос о внешнем контракте до зависимых правок. |
| `Вопросы закрыты. Составь план refactoring/product-id: core вводит тип, orders и inventory переходят независимо.` | После проверки готовности документов появится план с локальными проверками и проверкой общей цели. |
| `$sdd-spec Продолжи sdd/refactoring/product-id по сохранённому поручению.` | Агент восстановит выбранный маршрут, решения и оставшуюся работу. |

Если исходных тестов или спецификации нет, агент укажет пробел и запланирует
проверку прежнего поведения до преобразования соответствующей части системы.
