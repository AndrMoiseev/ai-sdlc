# Полное восстановление контекста

Для сохранённых [поручений explorer](explorer.md) прочитай request/launch/result
по абсолютным ссылкам из state.md, сверь SHA-256 и текущий basis. До change
используй сохранённую хостом или пользователем точку продолжения. Отсутствие
ответа — incomplete; очистка временных файлов — unavailable. Краткий итог
не заменяет доказательства. Проверь живой контекст через хост перед продолжением.

Для refactoring восстанавливай proposal/design и существующий tasks без требования specs по [справочнику](refactoring.md). Сверь вид, полный корень, основание выбора и уведомление; одинаковые ID в двух корнях различаются. При смене маршрута сообщи новые границы до зависимой работы.

Прочитай [общую основу](../../sdd-shared/references/document-format.md) и
[формат обсуждения и восстановления](../../sdd-shared/references/document-format-discussion.md).
При наличии proposal/specs/design добавь [нормативный формат](../../sdd-shared/references/document-format-normative.md),
при наличии tasks — [задачи и проверки](../../sdd-shared/references/document-format-tasks.md),
при наличии отчётов, USER-записей или проверке разрешённого перехода —
[ревью и согласования](../../sdd-shared/references/document-format-review.md).
Сначала выполни Git-проверку входа по [resume](../flows/resume.md). Прочитай текущее состояние и основания действующих поручений; исторические версии всех документов повторно обходить не требуется.

1. Прочитай [правила обсуждения](discussion.md), state.yaml и state.md целиком, decisions.md и questions.md при наличии, затем все существующие proposal/specs/design/tasks, отчеты, сводку и USER-записи из review/decisions.md. Поддерживается только полная пара state.yaml и state.md без frontmatter и машинных записей в Markdown. Для v1 выполни явную миграцию по общему формату: старые решения служат контекстом, не новым принятием. Сверь происхождение существенных положений, открытые выборы, ссылки на коммиты, состав линз, выполненную работу и основания разрешений. State — точка продолжения, не источник истины о согласовании. Наличие tasks не доказывает ни planning_command, ни plan_approval.
2. Проверь сохранённый [премортем](premortem.md): прочитай краткий итог и документ по ссылке, сопоставь основания с текущими источниками. При актуальном разборе используй прежние ответы; при изменениях пересмотри затронутую часть. Отсутствующую запись, недоступный документ или источник обработай по правилам восстановления справочника.
3. При отсутствующем/поврежденном state сохрани документы и восстанови черновой checkpoint из файлов и доступных проверенных решений. Не повторяй уже подтвержденное исследование; занимайся пробелами. Потерянная ссылка USER или недоказанная область не дает разрешения: сообщи, что восстановлено и чего недостает, ожидай конкретного решения только для неподтвержденного перехода.
4. Различай согласование версии и разрешение работы. Проверь смысл и область document_approval и plan_approval; принятый переход не отменяет их автоматически из-за нового OID. state_acceptance не является поручением или одобрением плана. review_consent разрешает один запуск. finding_disposition и planning_command действуют на оставшуюся согласованную работу, пока пользователь не отменил/заменил поручение и область не расширена.
5. При частично выполненном поручении проверь исходный scope, ссылки находок, выполненную часть и происхождение изменений. Продолжи остаток без повторного согласия: ожидаемые правки не отменяют разрешение. Сохраненная команда планирования не обходит обязательную готовность документов; ревью остаётся опцией. Необъясненные внешние правки уточняй только в затронутой области; не отменяй все поручения и не расширяй их автоматически. Найди более поздние отмены/замены в решениях и checkpoint; старое поручение после них не возобновляй.
6. Если пояснение существует, прочитай его и archify/index.md; сравни нормативные пути исходного коммита с текущим принятым коммитом по [контракту пояснения](explanation.md). При несовпадении отметь пояснение устаревшим до сверки всего содержания. Отдельно проверь привязку результатов archify к текущему HTML. Если индекс отсутствует или повреждён, актуальность не подтверждена.
7. Восстанови выбор пояснения из читаемой части state: область, исходный коммит, источник поручения, отмены и выполненную часть. Отказ или уже сделанное предложение без ответа не вызывают повторного предложения той же версии. Действующее поручение продолжи через [explain](../flows/explain.md) без повторного разрешения в прежней области; наличие старого пояснения не разрешает новую область. Поздний явный запрос может заменить отказ. Проверки и готовность основного комплекта сохраняются отдельно.
8. Сообщи текущий этап, блокирующие/отложенные вопросы, changed_since_review, missing и incomplete проверки и следующий допустимый шаг. Если есть открытый существенный выбор, продолжи его обсуждение независимо от наличия готового черновика и phase; заданный вопрос без ответа сохраняй в ожидании. При явной паузе только сохрани очередь. Сохрани действующие поручения и ожидания review consent или planning command через смену сессии; открытый выбор не позволяет обойти условия перехода. Продолжение сессии само по себе не разрешение.

Если текущий план уже согласован, проверь актуальность plan_approval, последние ограничения пользователя и отдельные основания существенных выборов по discussion. Сохрани согласование версии, но не закрывай им неподтверждённые решения или старый пакетный Q. После проверки обязательных условий продолжи через sdd-apply с сохранённым ответом по общему контракту согласования; ожидание review_consent не требует дополнительного подтверждения.
