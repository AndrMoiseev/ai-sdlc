# Обсуждение и происхождение решений

Прочитай перед explore, draft, revise, plan и при resume. Спецификация, дизайн
и план составляют единый комплект. Черновик сохраняет достигнутое понимание;
сохранение файла само по себе не закрывает обсуждение.

Для записи вопросов и checkpoint используй [общую основу формата](../../sdd-shared/references/document-format.md)
и [формат обсуждения и восстановления](../../sdd-shared/references/document-format-discussion.md).

## Граница самостоятельности

Существенный выбор меняет цель, объём, наблюдаемое поведение, критерии готовности,
границы автономности или ключевой технический подход с заметными последствиями
для совместимости, данных, стоимости, безопасности или сопровождения.
Материальное требование вводит или меняет обязательство в одной из этих областей.
Проверь также требования и ограничения, предложенные самим агентом.

Для каждого существенного выбора нужно решение пользователя либо явное поручение
агенту решить именно этот вопрос из показанного списка. Исследование, рекомендация
рецензента, готовый design, молчание и согласование комплекта не заменяют такого
основания. «Предложи решение» разрешает подготовить предложение; «реши перечисленные
вопросы сам» разрешает принять решения в его области. Уже данный выбор используй
без повторного подтверждения.

Редактуру, структурные исправления и технические детали внутри принятого подхода
выполняй самостоятельно. Структурные ошибки исправляй до ревью без отдельного
разрешения. Фактический вопрос закрывай проверенным источником. Если исправление
требует существенного выбора, покажи его пользователю. Не выдавай выбор поведения
за техническую правку и не превращай каждое действие в запрос разрешения.

Рекомендация остаётся опцией: её можно проигнорировать без ответа, причины или
действия. Создавай Q только для реального пробела, требующего решения для текущей
работы. Предложение улучшения само по себе не делает комплект неготовым.

## Явные развилки

Покажи существенные вопросы в сообщении пользователю: предмет каждого выбора,
варианты, последствия и рекомендацию. Одной записи в questions.md недостаточно.
Можно показать несколько вопросов сразу; каждый независимый выбор должен иметь
собственный Q-ID и понятные варианты. Соблюдай просьбу пользователя задавать их
по одному. Общее «одобрить документы» не закрывает скрытые или неразобранные решения.

При открытых вопросах прямо сообщи, что они остались, и предложи продолжить
обсуждение либо поручить агенту решить показанный список. Агент не запрашивает
утверждение комплекта, пока вопросы открыты. Инициировать согласование в таком
состоянии может пользователь: покажи оставшиеся вопросы и получи ответы либо
ограниченное делегирование до фиксации утверждения. Ответ «утверждаю всё»
не закрывает вопросы, которые пользователь не видел.

## Делегирование текущего списка

Сохрани точный ответ пользователя, показанные Q-ID, область поручения и доступный
источник в decisions.md и читаемой части state.md. Поручение действует только на
этот список; новые вопросы, в том числе возникшие при ревью, требуют нового
решения пользователя. Смена сессии не отменяет оставшуюся порученную работу.

Для каждого делегированного вопроса запиши выбранный вариант, обоснование и то,
что решение принял агент по указанному поручению. Закрой Q ссылкой на эту запись.
Покажи принятые решения в сообщении. После их принятия уточни необходимость
независимого ревью; ранее явно выбранный пользователем вариант для этой области
учти без повторного вопроса. Разрешение решать вопросы не разрешает запуск ревью,
утверждение комплекта или выполнение плана.

## Проверка предпосылок

До подробной спецификации установи ожидаемый результат, получателя и условия
успеха по доступным документам, коду, тестам, diff и сохранённым ответам. Проверь
существенные предпосылки; различай факты, гипотезы и пробелы. Недоступный источник
оставляет ограничение. Найденный ответ используй без повторного вопроса.

Пробел, заставляющий угадывать цель, объём, поведение или ключевой подход, сохрани
отдельным Q и покажи пользователю; продолжай независимую часть. При достаточных
основаниях продолжай без интервью. Для опечатки достаточно проверки diff.
При изменении существенного основания пересмотри зависимые решения. При resume
используй актуальные сохранённые основания; новый сеанс не требует исследования
заново. Отсрочка открытого Q не закрывает его. Если пользователь исключил часть
из объёма, зафиксируй этот выбор и закрой соответствующий вопрос.

## Материалы изменения

| Файл | Назначение |
|---|---|
| decisions.md | Существенные предложения и решения, авторство, основания и делегирование |
| questions.md | Открытые и закрытые вопросы с Q-ID |
| state.yaml | Этап, ожидание, ссылки, ближайший Q-ID и статусы проверок |
| state.md | Выполненная часть, область поручения и следующий шаг |
| review/decisions.md | USER-записи утверждения комплекта и других явных поручений |

Создавай журнал при первом существенном предложении по [шаблону](../templates/discussion-decisions.md),
список вопросов при первом вопросе по [шаблону](../templates/questions.md).
Добавляй существующие файлы в state.yaml.document_links. Пустые документы для
простой правки не нужны. Журнал — обычный Markdown без новых машинных записей.

Отдельная запись журнала относится к одному выбору: устойчивый заголовок, предмет,
вариант, статус «предложено / принято / отклонено / заменено», автор предложения
и тот, кто принял решение. Для принятого выбора укажи точный ответ пользователя
с доступной датой или ссылкой либо поручение агенту и его решение. Предложения
помечай «решение не принято». Не выдумывай цитаты, даты и авторство.
Из существенного положения в proposal/specs/design/tasks дай ссылку на запись;
для предложения укажи открытый Q-ID, в том числе у зависимых REQ/AC.

В questions.md сохраняй все обнаруженные вопросы. В пояснении укажи причину,
варианты и затронутые документы. Существенный выбор остаётся blocking: true,
пока не получено решение; blocking: false не разрешает утверждение при открытом Q.
При закрытии сохраняй resolution: относительный путь с якорем к решению или
проверенному источнику. Проверь, что основание отвечает именно на этот вопрос;
факт не закрывает пользовательское предпочтение.

## Цикл и следующий шаг

1. Исследуй факты, выдели вопросы и сохрани основания уже принятых решений.
2. Покажи открытые вопросы и варианты пользователю. Получи ответы либо явное
   поручение решить текущий список. При ожидании ответа продолжай независимую
   работу, не повторяй вопрос и не принимай решение молча.
3. Закрой только решённые вопросы, обнови журнал и зависимые документы. После
   каждой порции черновика проверь основания существенных положений, включая
   пробелы, ещё не отражённые в документах. Новые вопросы снова покажи пользователю.
4. Когда открытых вопросов нет, предложи выбор: без плана — написать план или
   провести независимое ревью текущего комплекта; с планом — провести ревью или
   утвердить весь комплект без агентского ревью. Спецификация отдельно не утверждается.
5. Пользователь может запросить ревью с открытыми вопросами. Передай их рецензентам;
   сначала устрани структурные ошибки. Само ревью вопросы не закрывает. Новые
   существенные вопросы по его итогам возвращаются в шаг 2.

Сохраняй checkpoint после завершённой порции обсуждения. При явной паузе сохрани
очередь и остановись. Утверждение комплекта не запускает реализацию: требуется
явное поручение выполнить план по [общему контракту](../../sdd-shared/references/document-format-review.md).

## Продолжение

При resume сначала прочитай журнал и questions.md, сопоставь их с документами,
ответами и последними отменами. Проверь основания закрытых Q и остаток текущего
делегирования. При утрате основания сохрани историю и выясни только утраченный
выбор. Старое согласование не восстанавливает отсутствующий выбор или поручение.

Если старый Q объединяет независимые решения, сохрани его историю и раздели
актуальную запись на отдельные Q. Перенеси только подтверждённые ответы. Неизвестное
происхождение положения покажи отдельно. Неполный checkpoint не даёт готовности.
Новая воля пользователя действует сразу: обнови документы и состояние, не продолжай
отменённую работу из старой записи.
