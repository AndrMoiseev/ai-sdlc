# Ручная проверка в Codex

## Подключение

Скопируй папку `sdd-doc` целиком в
`<проект>/.agents/skills/sdd-doc`, включая `agents/openai.yaml`:
в нём `policy.allow_implicit_invocation: false` отключает автоматический выбор.
Открой проект в Codex и новый чат. Если скилл не появился в списке, перезапусти
Codex. Явный вызов — `$sdd-doc` вместе с задачей.
Основание настройки: [документация Codex](https://developers.openai.com/codex/skills).

Для ручной проверки нужны Codex и доступ к файлам проекта. Claude CLI,
Anthropic API key и скрипты skill-conductor для этих прогонов не требуются.
Для полного прохода редактуры нужны установленный `humanizer-ru` и возможность
запускать редактора и слепого проверяющего в отдельных свежих контекстах.

## Проверка на реальном проекте

В отдельной рабочей копии проекта выполни:

```text
$sdd-doc
Создай или обнови глоссарий проекта по кодовой базе; сверь с документацией.
```

Проверь фактическое чтение `SKILL.md`, `references/glossary.md` и
`references/editorial-pass.md` в действиях
агента, полученные файлы и diff. Оцени:

- Подтверждены ли определения конкретными источниками?
- Прочитан ли код каждого проверенного домена, включая понятия вне README?
- Есть ли отдельные таблицы по доменам с названием, описанием, допустимыми именами в коде и синонимами?
- Отделены ли конкурирующие и исторические имена от допустимых имён нового кода?
- Содержит ли сам глоссарий правило повторного использования терминов и ввода новых понятий только по спецификации?
- Добавлен ли указатель в существующие инструкции агентам либо явно предложен, если запись вне области задачи?
- Вынесены ли неоднозначности в открытые вопросы рядом с терминами?
- Разделены ли текущие значения, предложения и исторические сведения?
- Сохранены ли незатронутые определения и рабочие ссылки?
- Ограничены ли изменения документацией в рамках запроса?
- Прошёл ли каждый затронутый документ редактуру и слепую проверку до показа,
  включая указатели в README и AGENTS.md?
- Сохранены ли смысл, термины, кодовые имена и защищённые фрагменты после редактуры?

В новом чате повтори явный вызов на полученном результате с теми же источниками.
Сравни файлы до и после: содержательных изменений и дублей быть не должно.

## Воспроизводимые сценарии

Открой [evals.json](evals.json). Каждый `prompt` уже содержит явный вызов.

| ID | Что проверяет |
|---|---|
| 1 | Создание глоссария и различение действующего соглашения и предложения |
| 2 | Обновление, сохранение ссылок и терминов, противоречие с реализацией |
| 3 | Разные значения одного слова и неподтверждённый синоним |
| 4 | Нехватка оснований для определений при требовании законченного результата |
| 5 | Код как первичный источник, таблицы по доменам, конкурирующие имена |
| 6 | Давление срока и готовой документации при доступном коде |

Для каждого сценария используй отдельный временный проект и новый чат.
Подготовь файлы, приведённые в `prompt`, до запуска; в остальных случаях передай
материалы текстом. Сценарии описывают синтетические проекты: их исходные файлы
не следует записывать поверх документации реального проекта.
Для сценариев 5–6 скопируй содержимое `files/code-first/` в корень временного
проекта, сохранив README.md и src/model.ts; ожидаемые результаты агенту не передавай.

Отправь только `prompt`. Поля `expected_output` и `expectations` используй
для собственной оценки после выполнения. Для сценария 2 сохрани снимок
полученных файлов, открой новый чат и отправь `repeat_prompt`. Исходные файлы
заново не создавай: проверяется обновление уже полученного глоссария.

Для каждого критерия запиши «пройден / не пройден» и свидетельство: фрагмент
результата, ссылку на источник или diff. Сохрани запрос, ответ, изменённые файлы
и выбранную модель с настройками. Непроверенные критерии пометь отдельно.

## Необязательное сравнение без скилла

Чтобы оценить пользу инструкций, повтори сценарий на одинаковом начальном
состоянии в новом чате, убрав из запроса `$sdd-doc`. Для чистого
контроля используй копию без установленного скилла и не передавай его инструкции.
Оставь модель и настройки одинаковыми. Сравни результаты по тем же критериям.

Проверка автоматического выбора не входит в этот набор. Один ручной прогон
показывает конкретный результат; для оценки устойчивости повтори важные случаи
в нескольких новых чатах на одинаковом начальном состоянии.

## Сценарии редактуры

Для каждого случая подготовь отдельную рабочую копию вне каталогов скиллов.
Сохраняй там исходные и итоговые документы, задания субагентам, ответы и diff.
Проверяй фактические вызовы и содержимое заданий: заявление «редактура выполнена»
без выполнения этапов не засчитывается.

| Сценарий | Критерий |
|---|---|
| Создать русский глоссарий и обновить указатели README и AGENTS.md | Все три документа переданы редактору и отдельному слепому проверяющему; неизменённые файлы не переписаны |
| Поправить одно определение перед немедленной передачей пользователю, потребовав сэкономить время | Промежуточный статус и малая правка не отменяют редактуру; передача происходит после проверки смысла |
| Определение содержит «обязан», «не допускается», «может», число, `reservation_id`, ссылку и спорный синоним | Смысл, обязательность, неопределённость, точные имена и статус синонима сохранены; таблица не перестроена |
| Русский текст рядом с английским абзацем, кодом, цитатой пользователя и историческим отчётом | Редактируется только разрешённая русская проза; остальные фрагменты совпадают с оригиналом |
| Передать чистый русский текст без паттернов, затем запросить анализ без записи | Первый проход завершается без искусственных правок; анализ не запускает редактуру документов |
| Изменить полностью английский документ | Явное «неприменимо: нерусский текст», без вызова humanizer и заявления об успешной русской редактуре |
| Убрать доступ к humanizer или отдельным свежим контекстам | Результат остаётся черновиком с конкретной причиной незавершённости; саморедактура не заявлена заменой |
| Проверяющий продолжает находить подтверждённые дефекты после двух циклов исправлений | Цикл прекращён с указанием оставшихся проблем, без ложного успеха и рекурсивных вызовов |
| После успешного прохода автор добавляет одну фразу | Для актуальной версии выполнен новый проход; правки самого редактора не вызвали бесконечный перезапуск |

Для проверки изоляции убедись, что редактор не получил историю беседы, а слепой
проверяющий не получил оригинал, diff или находки редактора. Оба получили
ограничения технической документации. Основной агент сверил смысл и применил
патч; субагенты не писали в целевые файлы. Логи, временные файлы линтера и
прочие результаты остались вне каталогов скиллов.
