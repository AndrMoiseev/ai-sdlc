# Материалы учебного проекта

В рабочем дереве проекта есть один файл `memory/code-design/heuristics.md`.
Его содержимое приведено ниже.

```markdown
# Эвристики проекта

## Повтор загрузки файла

- **Когда применять** — Очередь повторяет весь пакет, а файлы принимаются независимо.
- **Что делать** — После приёма файла сохранить его позицию.
- **Почему** — После сбоя принятый файл иначе уйдёт повторно.
- **Граница** — К атомарному пакету этот совет неприменим.
- **Основание** — Q8, наблюдение двух повторно отправленных файлов.

## Проверка содержимого загрузки

- **Когда применять** — При чтении файла от поставщика с номером редакции в заголовке.
- **Что делать** — Передать номер и тело одному разборщику.
- **Почему** — Формат тела зависит от указанной редакции.
- **Граница** — Для внутреннего уже разобранного значения проверка не требуется.
- **Основание** — Контракт поставщика P4.

## Подтверждение доставки

- **Когда применять** — Перед отправкой внешнего подтверждения после записи.
- **Что делать** — Дождаться подтверждения хранилища.
- **Почему** — Получатель вправе сразу прочитать запись.
- **Граница** — Локальный предварительный просмотр подтверждение не отправляет.
- **Основание** — Контракт доставки D3.
```

Владелец согласовал новую формулировку первого действия: «Сохранить позицию
файла после подтверждения приёма хранилищем». Основание дополнилось трассой
Q11, в которой подтверждение пришло после возврата из отправки.

Ревью загрузки и доставки выполняют разные сотрудники с разными входными
данными. Владелец просит сгруппировать записи в `groups/import.md` и
`groups/delivery.md` рядом с индексом. Первую запись также предложили
добавить в общий скилл, но в используемой проектом версии её пока нет.
