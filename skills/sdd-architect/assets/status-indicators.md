# Справочник показателей статуса проекта

В [status.json](status.json) сохранены исходные значения, числители и знаменатели долей, границы аудита (`scope`) и действовавшие пороги (`profile.parameters`). «Неприменимо» означает, что для этой области величина не определена. Например, если в коде нет ветвей, у покрытия ветвей нет знаменателя.

## Область измерения и интегральные показатели

### kotlin-files

**Файлы Kotlin**

Число production-файлов `.kt` в области после исключений, включая файлы без зависимостей. Это число вершин графа. Если оно изменилось между аудитами, проверьте, изменился ли состав исходников. [Правила отбора][population]

### other-production-files

**Прочие production-файлы**

Число файлов в инвентаре production-исходников, оставшихся после вычитания Kotlin-файлов. Показывает, какая часть инвентаря осталась за пределами оценок D, L, U и Q. [Правила отбора][population]

### incoming-non-kotlin-edges

**Входящие связи Kotlin с прочим production-кодом**

Число различных направленных пар файлов, где потребитель написан на другом языке, а поставщик — на Kotlin. Чем выше число, тем больше прямых связей с потребителями за пределами графа Kotlin. [Правила построения графа][graph] · [jdeps][jdeps]

### outgoing-non-kotlin-edges

**Исходящие связи Kotlin с прочим production-кодом**

Число различных направленных пар, где Kotlin-файл зависит от production-файла на другом языке. Большое значение указывает, что часть зависимостей Kotlin-кода можно увидеть только при рассмотрении смешанного графа. [Правила построения графа][graph] · [jdeps][jdeps]

### tokens

**Токены**

Количество лексических единиц Kotlin-кода, например ключевых слов, имён и литералов. Пробелы, комментарии, директивы package и import исключены. Это объём кода, по которому нормируют дублирование и ряд других показателей. [Правила подсчёта токенов][population]

### d

**Структурная разделимость D**

Оценка Decoupling Level от 0 до 100 по иерархии групп файлов ArchDRH-Re. Чем выше D, тем лучше граф разделяется на группы с ограниченным кругом зависимых файлов. При снижении D посмотрите вклад групп в `structure.decoupling_level.groups`. Для модуля расчёт учитывает только внутренние связи. [Исходная метрика Decoupling Level][dl] · [Алгоритм профиля][graph]

### l

**Локальная поддерживаемость L**

Среднее геометрическое оценок когнитивной сложности и размеров контейнеров, `√(C_score × S_score)`. Чем ближе L к 100, тем меньший штраф дали эти два фактора. При снижении L сравните их по отдельности. [Формула профиля][local]

### u

**Оценка дублирования U**

Оценка от 0 до 100, равная `100 / (1 + d / duplication_reference)`, где d — доля повторяющихся токенов. При отсутствии точных повторов U равна 100, при доле повторов на уровне параметра `duplication_reference` — 50. При сравнении модулей учитывайте также межмодульные повторы. [Формула и критерий повтора][local]

### q

**Общий индекс качества Q**

Среднее геометрическое D, L и U, `∛(D × L × U)`. Низкое значение любой составляющей снижает индекс. Чтобы понять причину изменения Q, сравните три составляющие при одинаковом профиле. Для проекта Q рассчитывается заново по всем его файлам. Покрытие и история изменений в формулу не входят. [Формула индекса][local] · [Область расчёта][modules]

## Статистика scc

Строка «всего» описывает выбранную область целиком. Категории production, tests и other и строки языков дают два разреза одного итога. При сложении строк разных разрезов одни файлы будут учтены дважды. [Отбор и распределение файлов][modules]

### scc-files

**Файлы**

Число файлов, учтённых scc после исключений. По проекту сюда могут войти тесты, документация и файлы сборки. Этот счётчик позволяет оценить представленный объём репозитория по категориям и языкам. [scc][scc] · [Область статистики][modules]

### scc-lines

**Строки**

Общее число физических строк в учтённых файлах. Учитывает код, комментарии и пустые строки. Рост показывает увеличение объёма текста, причину можно найти по трём составляющим. [scc][scc]

### scc-code

**Код**

Число строк, которые scc отнёс к коду. Сравнивайте внутри одного языка и категории, поскольку переносы строк и стиль форматирования влияют на результат. [scc][scc]

### scc-comment

**Комментарии**

Число строк, которые scc классифицировал как комментарии. Счётчик помогает объяснить разницу между общим объёмом текста и строками кода. Содержательность комментариев требует отдельного чтения. [scc][scc]

### scc-blank

**Пустые строки**

Число строк, которые scc классифицировал как пустые. Изменение при прежнем числе строк кода может отражать переформатирование файлов. [scc][scc]

## Граф зависимостей Kotlin

Ребро направлено от файла-потребителя к файлу-поставщику. jdeps видит зависимости, сохранившиеся в байткоде. Рефлексия, внедрение зависимостей и встраивание функций ограничивают видимость графа. [jdeps][jdeps] · [Граф профиля][graph]

### pc

**Стоимость распространения зависимостей PC**

Доля достижимых упорядоченных пар среди всех N² пар файлов, включая путь каждого файла к себе. Чем больше PC, тем шире потенциальная область распространения изменений по связям графа. Даже у N изолированных файлов PC равна 1/N. [Расчёт PC][graph]

### cyclic-files

**Циклические файлы**

Количество файлов, входящих в сильно связную компоненту (SCC) из двух или более файлов. Между любыми двумя файлами такой компоненты есть путь в обе стороны. Рост числа показывает, что взаимные зависимости охватывают больше файлов. [Расчёт компонент][graph]

### cyclic-file-fraction

**Доля циклических файлов**

Количество циклических файлов, делённое на все Kotlin-файлы области. Например, 20% означает, что каждый пятый файл участвует хотя бы в одном цикле. [Расчёт доли][graph]

### largest-scc-size

**Крупнейшая SCC**

Число файлов в крупнейшей сильно связной компоненте. Значение 1 означает непустой граф без циклов между файлами, 0 — пустой граф. Большие значения помогают найти самую широкую группу взаимозависимых файлов. [Расчёт размера SCC][graph]

### edge-count

**Рёбра**

Количество различных прямых направленных зависимостей между файлами области. Связи классов одной и той же пары файлов одного направления считаются один раз, внутрифайловые зависимости исключены. Рост при прежнем составе файлов означает больше прямых связей. [Построение рёбер][graph]

## Когнитивная сложность, размеры и повторы

### cognitive-score

**Оценка когнитивной сложности C_score**

Для каждой функции берут относительное превышение порога когнитивной сложности, взвешивают по токенам тела и усредняют по токенам функций. Оценка равна 100, делённым на единицу плюс это среднее. Значение 100 означает, что ни одна функция с ненулевым весом не превысила порог. [Формула профиля][local] · [Когнитивная сложность в detekt][detekt]

### size-score

**Оценка размеров контейнеров S_score**

Для каждого токена берут наибольшее относительное превышение лимита среди содержащих его тела функции, класса или объекта и файла. Оценка равна `100 / (1 + среднее превышение по токенам)`. Низкое значение указывает на концентрацию кода в крупных контейнерах. [Формула и лимиты][local]

### function-count

**Функции**

Число именованных Kotlin-функций с телом, которые учитываются при расчёте L. Вложенная именованная функция входит в тело внешней и отдельно не считается. Число показывает, сколько функций представляют максимум и p95 сложности. [Правила отбора][local]

### function-tokens

**Токены функций**

Количество токенов в телах учтённых функций. Это суммарный вес при расчёте C_score. Чем объёмнее функция, тем больше её вклад при том же превышении порога. [Веса функций][local]

### outside-function-tokens

**Токены вне функций**

Разность между всеми токенами области и токенами тел учтённых функций. Большое значение означает, что C_score описывает лишь часть кода, например при большом числе объявлений свойств. [Популяция токенов][local]

### maximum-cognitive-complexity

**Максимальная когнитивная сложность**

Наибольшее значение когнитивной сложности среди учтённых функций. Показывает наиболее сложный для чтения поток управления по правилам detekt. Один выброс способен изменить максимум даже при стабильном p95. [Правила detekt][detekt] · [Отбор функций][local]

### weighted-p95-cognitive-complexity

**Взвешенный p95 когнитивной сложности**

Минимальное значение сложности, при котором функции с такой или меньшей сложностью охватывают не менее 95% токенов функций. Высокий p95 указывает, что существенный объём кода находится в сложных функциях. [Правило взвешивания][local] · [Когнитивная сложность][detekt]

### complex-tokens

**Токены сложных функций**

Число токенов в телах функций со сложностью строго выше порога `cognitive_complexity`. Учитывается всё тело такой функции. Счётчик показывает объём кода, для чтения которого приходится разбираться в сложном потоке управления. [Критерий сложности][local]

### complex-token-fraction

**Доля токенов сложных функций**

Число токенов сложных функций, делённое на токены **всех учтённых функций**. Например, 30% означает, что почти треть кода в телах функций находится выше порога по сложности своей функции. [Знаменатель доли][implementation]

### duplicate-tokens

**Повторяющиеся токены**

Число позиций токенов в точных повторах длиной от `clone_tokens`. Учитывается и первое вхождение, каждая позиция считается один раз. Изменение имён или литералов может скрыть похожий фрагмент. [Критерий повтора][local]

### duplicate-token-fraction

**Доля повторяющихся токенов**

Число повторяющихся позиций, делённое на все токены области. Рост доли при тех же настройках снижает U. Для модуля здесь учитываются совпадения внутри самого модуля. [Расчёт доли][local] · [Модульная область][modules]

## Покрытие и CRAP_exec

Покрытие берётся из объединённого отчёта JaCoCo по выбранным успешно прошедшим тестам. Для каждой области складываются счётчики. Проценты в таблице отражают выполнение кода, а качество проверок результата устанавливается чтением тестов. [Счётчики JaCoCo][jacoco] · [Методика профиля][coverage]

### branch-coverage

**Покрытие ветвей**

Число пройденных ветвей, делённое на все ветви учтённых методов JVM. Низкое значение указывает на исходы условий, которые тесты не исполняли. JaCoCo исключает обработчики исключений из счётчика ветвей. [Ветви JaCoCo][jacoco] · [Агрегация][coverage]

### instruction-coverage

**Покрытие инструкций**

Число выполненных инструкций байткода, делённое на общее число инструкций учтённых методов. Рост означает, что тесты исполнили бо́льшую долю скомпилированного кода. [Инструкции JaCoCo][jacoco]

### line-coverage

**Покрытие строк**

Доля строк с хотя бы одной выполненной инструкцией среди уникальных строк Kotlin, для которых JaCoCo привёл построчные данные. Строка может содержать непройденную ветвь. Сводка перечисляет файлы без построчных данных отдельно. Если таких файлов часть, процент относится к остальным файлам. Если это все файлы области, сводка показывает «Нет данных». [Строки JaCoCo][jacoco] · [Отбор строк][coverage]

### method-count

**Методы CRAP_exec**

Количество исполняемых методов JVM в расчёте CRAP_exec. Метод различают по классу, имени и JVM-дескриптору. Это размер выборки для суммы и p95. При сравнении с числом Kotlin-функций учитывайте преобразования компилятора. [Популяция методов][coverage] · [Методы JaCoCo][jacoco]

### total-crap

**Сумма CRAP_exec**

Для каждого метода берут его цикломатическую сложность v и прибавляют превышение e за неполное покрытие. Сумма CRAP_exec равна сумме этих `v + e`. Высокое значение может объясняться большим числом методов. Чтобы выделить вклад непокрытого кода, посмотрите сумму превышений. [Адаптация CRAP_exec][coverage] · [Исходная метрика CRAP][crap]

### total-excess

**Сумма превышений CRAP_exec**

Сумма `e = v² × (1 − c)³` по методам. Здесь c — меньшая из долей покрытия инструкций и ветвей метода, а для метода без ветвей — доля покрытия инструкций. Полностью покрытый метод даёт нулевое превышение. Особенно большой вклад дают сложные методы с низким покрытием. [Формула профиля][coverage] · [Сложность JaCoCo][jacoco]

### excess-density

**Превышение на 1000 токенов**

Сумма превышений CRAP_exec, умноженная на 1000 и делённая на все токены Kotlin в области. Показывает концентрацию превышения и позволяет сравнить модули разного объёма при одинаковом профиле. [Нормировка по объёму][coverage]

### e-crap

**Нормированное превышение E_CRAP**

Сумма превышений, делённая на сумму v² по методам, умноженная на 100. Ноль соответствует нулевому превышению, 100 — максимально возможному для этих методов при нулевом покрытии. Больший вес имеют методы с высокой сложностью. [Нормировка по сложности][coverage]

### p95-crap-exec

**p95 CRAP_exec**

95-й процентиль значений CRAP_exec по отдельным методам, каждый метод имеет один голос. Как минимум 95% методов имеют значение не выше указанного. Сравнение с крупнейшими превышениями в JSON помогает отличить несколько выбросов от более широкой проблемы. [Методный расчёт][coverage] · [Правило процентиля][implementation]

## История совместных изменений

Учитываются коммиты по первому родителю за окно `history_days`, с отслеживанием переименований и без merge-коммитов. Для пары файлов степень совместного изменения равна `2 × общие коммиты / (коммиты первого + коммиты второго)`. Пара попадает в расчёт, если достигнуты пороги числа общих коммитов, средней частоты и степени совместного изменения. [Отбор истории][coverage] · [Метод логической связанности Code Maat][maat]

### observations

**Наблюдения**

Число учтённых коммитов, затронувших хотя бы один Kotlin-файл области. Один коммит даёт одно наблюдение независимо от числа затронутых файлов. Это объём истории, на который опирается вывод о совместных изменениях. [Окно и отбор истории][coverage]

### excluded-large-commits

**Исключённые крупные коммиты**

Число коммитов за окно наблюдения, превысивших лимит `history_maximum_files` по production-файлам Kotlin. Фильтр действует на коммит целиком до отбора модуля, поэтому значение может повторяться по модулям. Большое число показывает, сколько массовых изменений исключено из частот. [Порядок фильтрации][implementation]

### history-status

**Статус истории**

`limited` означает, что наблюдений в области меньше `history_minimum_shared`. При достижении этого порога статус становится `known`. Нуль выявленных пар при `limited` говорит прежде всего о скудности истории. [Условие статуса][implementation]

### coupled-files

**Файлы с совместными изменениями**

Число различных файлов хотя бы с одним прошедшим пороги партнёром в области. Большое значение означает, что многие файлы регулярно менялись вместе. Причину можно выяснить по содержанию общих коммитов. [Отбор пар][coverage] · [Логическая связанность][maat]

### coupled-tokens

**Токены файлов с совместными изменениями**

Сумма текущих размеров этих файлов в токенах. Даже при нескольких партнёрах файл учитывается один раз и целиком. Показатель отвечает на вопрос, сколько кода находится в таких файлах, включая строки, которые могли не меняться. [Расчёт по файлам][implementation]

### coupled-token-fraction

**Доля токенов файлов с совместными изменениями**

Токены файлов с прошедшими отбор партнёрами, делённые на все токены области. Высокая доля при малом числе файлов указывает, что совместно менялись крупные файлы. [Расчёт доли][implementation]

## Границы архитектурных модулей

У каждого модуля свои D, PC, повторы и пары из истории. Следующие показатели возвращают в рассмотрение связи, видимые за его пределами. [Границы областей расчёта][modules]

### incoming-edges

**Входящие рёбра модуля**

Количество прямых зависимостей от файлов снаружи к файлам внутри модуля. Чем больше число, тем больше различных пар «внешний потребитель — внутренний поставщик» видно в байткоде. Один потребитель может образовать несколько таких пар. [Расчёт границ][implementation] · [jdeps][jdeps]

### outgoing-edges

**Исходящие рёбра модуля**

Количество прямых зависимостей от файлов модуля к файлам за его пределами. Показывает, сколько различных связей с поставщиками скрыто при расчёте по внутреннему графу. [Расчёт границ][implementation] · [jdeps][jdeps]

### project-cyclic-files

**Файлы модуля в циклах проекта**

Число файлов модуля, участвующих в циклах полного графа Kotlin. Если число больше локального числа циклических файлов, часть файлов оказывается в цикле только с участием других модулей. [Циклы и границы][modules]

### cross-module-coupled-tokens

**Токены файлов с межмодульными совместными изменениями**

Суммарный размер файлов модуля, у которых есть хотя бы один исторический партнёр из другого модуля. Большое значение означает, что изменения пересекали границу для файлов со значительным объёмом кода. Учитываются все токены такого файла один раз. [Отбор межмодульных пар][implementation] · [Логическая связанность][maat]

### cross-module-duplicate-tokens

**Токены в межмодульных повторах**

Число позиций токенов модуля, имеющих точное повторение в другом модуле по правилам `clone_tokens`. Считаются только совпавшие позиции. Если локальная U равна 100, положительное значение здесь показывает повторы, видимые лишь при сравнении модулей. [Критерий повтора][local] · [Межмодульный подсчёт][modules]
