# Аудит проекта

Проверяй среду, в которой агент будет выполнять команды этого проекта. Windows,
WSL, контейнер и удалённый сервер — разные среды: установка mise на хосте не
подтверждает её наличие внутри контейнера. Зафиксируй выбранную среду в отчёте.

## Требования к проекту

| ID | Обязательность | Критерий соответствия | Исправление |
| --- | --- | --- | --- |
| `mise` | Обязательное | Найден исполняемый файл mise; его `--version` завершился с кодом 0 и вернул версию | Найти существующую установку или установить mise для текущей ОС; повторить проверку |

Зависимости конкретной команды проверяются на этапе настройки сбора. Минимальная версия
пока не задана: работающую установку не обновляй ради «последней версии».
Наличие `mise.toml`, установленные через mise инструменты и активация оболочки
не входят в это первое требование. Не создавай пустой `mise.toml` и не запускай
`mise install`, `mise use`, `mise trust` или задачи проекта ради проверки наличия
самой утилиты. Это отдельные изменения зависимостей и доверия к конфигурации.

При добавлении требования укажи обязательность, наблюдаемый критерий, исправление
и повторную проверку; дополни `scripts/project_audit.py` и его тесты. Только
обязательные требования блокируют полный маршрут. Рекомендации показывай
отдельно и исправляй в пределах выбранных пользователем настроек.

## Проверка

1. Выполни `audit --project-root <project> --output <external-file.json>` по
   [API](api.md). Команда только проверяет требования; установка в неё не встроена.
   Она не читает назначения ролей и не требует каталога агентов Claude Code.
2. Покажи таблицу «требование / обязательность / наблюдение / соответствие /
   исправление». Для mise приведи путь, версию либо фактическую ошибку.
3. Выбери продолжение по результату:

| Статус mise | Продолжение |
| --- | --- |
| `satisfied` | Требование выполнено; повторная установка не нужна |
| `not_found` | Команда не найдена; сначала проверь известное место существующей установки |
| `failed` | Файл найден, но запуск не подтвердил версию; разбери stderr, код выхода или таймаут |

`not_found` по PATH ещё не доказывает отсутствие установки. Проверь сведения
установленного пакетного менеджера и стандартное место официального установщика:
`~/.local/bin/mise` на macOS/Linux, `~\.local\bin\mise.exe` на Windows. Используй
домашний каталог текущего пользователя из API среды. Если файл найден, повтори
аудит с `--mise-path <absolute-path>`; указывать можно и выбранный пользователем
путь. Запуск по абсолютному пути удовлетворяет требованию. Сохрани этот путь
для последующих команд; не утверждай, что PATH или новая сессия уже настроены.

При нескольких установках укажи, какой файл реально проверен. Не устанавливай
ещё одну копию для устранения ошибки PATH. При `failed` сначала отличи проблему
доступа/окружения от повреждённой установки. `mise doctor` используй для конкретной
диагностики, а не как дополнительное обязательное требование.

## Исправление

Маршрут «только аудит» заканчивается результатом проверки и предложенными
исправлениями: он не разрешает установку или изменение конфигурации. Полный setup
и просьба привести требования в соответствие включают необходимые исправления.
Перед исполнением покажи конкретную команду, источник и область изменений
(например, установка mise в пользовательский каталог). Используй уже данное
поручение; повторное согласие на то же действие не требуется. Новый существенный
выбор, выход за поручение или ограничение среды разрешай штатным способом хоста.

Выбери один способ установки по текущей ОС и существующей установке. Прочитай
актуальную [официальную инструкцию установки](https://mise.jdx.dev/installing-mise.html)
перед скачиванием: способы и требования платформ меняются. При отсутствии доступа
к документации сообщи об этом и используй только уже проверенный источник/способ;
не выдумывай ссылку на бинарник.

| Среда | Способ, подтверждённый документацией |
| --- | --- |
| macOS / Linux | Официальный установщик `https://mise.run` для `sh`; стандартный путь `~/.local/bin/mise` |
| Windows / PowerShell | Официальный установщик `https://mise.run/powershell`; стандартный путь `~\.local\bin\mise.exe` |
| Уже используется пакетный менеджер | Его способ из документации, например `brew install mise` или `winget install jdx.mise` |

Скачай установщик в отдельный внешний временный каталог, проверь успешность
скачивания и прочитай скрипт перед запуском через соответствующий интерпретатор.
Не подменяй проверку скачивания исполнением пустого/ошибочного ответа. Сохраняй
проверки целостности установщика и обычные разрешения среды. Для существующей
установки используй её способ обслуживания; восстановление не должно молча
заменять рабочую копию другим менеджером.

Если пакетный менеджер или установщик меняет пользовательский PATH, отметь это
в плане. Активацию оболочки и изменение shell profile выполняй только по отдельному
запросу: для данного требования достаточно рабочего исполняемого файла.

## Повторная проверка и завершение

После установки или исправления повтори `audit`, при необходимости с абсолютным
путём. Используй новый файл отчёта. Проверь `compliant` и каждое обязательное
требование; код 0 установщика и `ok: true` скрипта сами по себе не означают
соответствия. Учитывай, что текущий процесс может ещё не видеть обновлённый PATH.

При успехе сообщи подтверждённые путь и версию, выполненные изменения и переходи
к ролям, если выбран полный маршрут. Если пользователь отказался от установки,
доступ запрещён или исправление не удалось, сохрани отрицательный результат,
назови препятствие и конкретное следующее действие. Полный setup остановлен на
этом этапе; отдельную настройку ролей можно выполнить по новому явному уточнению.

Повторный запуск снова проверяет требования. При выполненном требовании он
оставляет установку и конфигурацию без изменений. Отчёт относится к текущей среде
и проверенному набору требований, а не ко всей будущей готовности проекта.

Источники проверены 2026-11-15: [установка](https://mise.jdx.dev/installing-mise.html),
[запуск без активации оболочки](https://mise.jdx.dev/getting-started.html).
