# Проектные задачи mise для Kotlin/JVM на Gradle

Настрой четыре задачи в проектной конфигурации mise. Сверь существующие задачи
mise с командами Gradle из сборки и CI. Используй формат конфигурации проекта,
его способ запуска Gradle и правила ktlint и detekt, выбранные на предыдущих шагах.
Если имя уже занято другой операцией, покажи расхождение и согласуй изменение.

Пример для одномодульного проекта с Gradle Wrapper и стандартными именами задач:

```toml
[tasks.format]
run = "./gradlew ktlintFormat"

[tasks.lint]
run = ["./gradlew ktlintCheck", "./gradlew detekt"]

[tasks.build]
depends = ["lint"]
run = "./gradlew clean build"

[tasks.test]
depends = ["lint"]
run = "./gradlew --no-build-cache clean test jacocoTestReport"
```

Подставь команду wrapper для платформы проекта и реальные пути задач. При
нескольких сборках охвати их все. В `lint` сначала выполни все проверки ktlint
и только после их успеха запускай detekt. Обе проверки должны возвращать
ненулевой код при нарушениях. Форматирование запускается отдельной командой.

Для `build` используй полный цикл сборки проекта после очистки. Для `test`
используй наборы тестов и проверенную задачу сводного отчёта из шага
[`jacoco`](jacoco.md). После очистки тесты должны выполниться заново, а сводный XML
должен охватывать все JVM-модули и использовать данные этого прогона.

Проверь команды через `mise run` из корня. Для `format` используй временную
копию текущего проекта с теми же настройками и исходником, требующим
автоисправления по выбранному правилу. Проверь результат исправления, если
такое правило включено. Для `lint` сверь порядок проверок. Для `build` и
`test` проверь зависимость от `lint` и успешный результат каждой команды.
По итогам `test` подтверди выполнение тестов и укажи пути к полученным
отчётам JaCoCo. При ошибке оставь шаг открытым.

Синтаксис задач и формирование покрытия описаны в документации
[mise](https://mise.jdx.dev/tasks/toml-tasks.html) и
[Gradle](https://docs.gradle.org/current/userguide/jacoco_plugin.html).
