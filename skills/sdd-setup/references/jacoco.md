# Покрытие всех JVM-модулей через JaCoCo

1. Составь перечень модулей по модели сборки и CI. Включи независимые и вложенные
   сборки проекта. Для каждого модуля установи каталоги скомпилированных
   производственных классов и задачи тестирования, включая интеграционные тесты.
   У модуля могут быть классы без собственных тестов или только тесты для других
   модулей. Для модулей без JVM-кода укажи причину неприменимости.
2. Подключи JaCoCo ко всем задачам, выполняющим JVM-тесты. Каждая задача пишет
   данные выполнения в свой файл. Настрой или используй существующую задачу
   сводного отчёта. В Gradle у `JacocoReport` задай `classDirectories` и
   `sourceDirectories` из производственных наборов всех модулей, а
   `executionData` — из всех участвующих задач тестирования. Обеспечь сборку
   классов даже в модуле без тестов. Свяжи построение отчёта с компиляцией и
   успешным выполнением тестов. Включи XML через `reports.xml.required.set(true)`.
   Если проект использует `jacoco-report-aggregation`, сверь граф зависимостей
   агрегатора и имена тестовых наборов с перечнем шага 1. Для самостоятельных
   сборок передай их классы и данные выполнения в тот же сводный отчёт.
3. Выполни чистый прогон штатных тестов с построением XML. Убедись, что
   задачи с тестами выполнились и передали данные этого прогона. При аудите
   только для чтения используй результаты CI для проверяемой ревизии.
4. Для каждого JVM-модуля сопоставь измеряемые производственные классы из его
   каталогов компиляции с элементами `class` в сводном XML. Включи классы,
   которые не вызвал ни один тест, с нулевым покрытием. Если класс вызван из
   теста соседнего модуля, его покрытие должно попасть в этот же отчёт.
   Для чисто тестового модуля проверь участие его данных выполнения. Для модуля
   без измеряемого байткода зафиксируй причину. Отсутствующий измеряемый класс,
   пропущенный набор тестов или старый XML оставляют шаг открытым.
5. Передай полный перечень JVM-модулей и результаты сверки в
   [`jvm-step jacoco`](api.md#jvm-step). Укажи пользователю проверенную команду
   и путь к сводному XML. Их используют шаги `collection` и `mise-tasks`.

Параметры отчёта и область агрегации описаны в документации Gradle.
[JaCoCo](https://docs.gradle.org/current/userguide/jacoco_plugin.html) ·
[Агрегация отчётов](https://docs.gradle.org/current/userguide/jacoco_report_aggregation_plugin.html)
