# Формат ревью и согласований

Читай вместе с [общей основой](document-format.md) перед ревью, рассмотрением
находок и проверкой актуальности или разрешений, включая resume и gate плана.

## Линзы, отчеты и сводка

Машинные виды записей — `sdd_record: finding` для находки и `sdd_record: user`
для пользовательского решения; их поля описаны ниже.

Индекс `sdd/arch-lenses/index.md`: frontmatter `schema_version: 1`, `lenses: [{id, title, path}]`. Пути относительно каталога индекса. Нет файла или lenses: [] — только consistency; поврежденный существующий индекс ошибочен. consistency и plan зарезервированы. Содержимое линзы: предмет, вопросы, ограничения, источники.

Отчет: `review/<run-id>/<lens-id>.md`; для плана lens-id=plan. Run-id — UTC-время с уникальным суффиксом. Дополнительный frontmatter: run_id, stage (document_review/plan_review), lens_id, result, started_at, finished_at, inputs, inputs_after, freshness, limitations. Все даты заключайте в кавычки. result: completed_no_findings/completed_with_findings/incomplete; limitations — список строк. Находка имеет source (текст), target: {path, element_id?}, severity: blocker/recommendation, problem/impact/suggestion (непустой текст). target.path относительно изменения.

Манифест — отсортированный список `{path, sha256}`; пути относительно изменения, хеши SHA-256 сырых байтов. Документная стадия включает proposal/design/все specs/**/spec.md; плановая добавляет tasks. State, decisions.md, questions.md, review, premortem.md, внешние источники и инструкции линз исключены. Снимок до/после и текущий должны совпасть; гонка внутри запуска оставляет отчет stale даже при возврате исходных байтов. Сохраненное freshness — историческое значение, при чтении вычислите актуальность вновь. Изменение общего комплекта устаревает для всех линз стадии; новый индекс может потребовать недостающую линзу независимо от хешей.

explanation.md, explanation/ и archify/ также исключены из нормативного манифеста,
включая index.md, candidate, HTML, снимки и промпт продолжения. Замена только
превью, заглушки или прозы пояснения сохраняет согласование неизменённого
основного комплекта. Новое обязательство из пояснения требует обычного revise
с пересчётом актуальности ревью и согласований нормативных документов.

Сводка `review/summary.md`: общий frontmatter document_type: summary плюс findings — список `{finding, related_to, duplicates}` с полными ключами. Для отсутствующих связей используйте []. Сохраняйте исходные отчеты; объединяйте дубли только в сводке, показывайте расхождения отдельно. related_to не переносит решения.

## Идентичность рефакторинга

Для `sdd/refactoring/<change_id>` общие документы state, questions, decisions,
review и summary содержат в frontmatter `work_kind: refactoring` и свой
`change_id`. Их назначение и остальные поля сохраняются. Отчёт связывается
с видом работы и ID вместе с манифестом. Documents включает proposal/design,
plan добавляет tasks; specs для этого вида не входят в снимок.

Каждая USER-запись рефакторинга также содержит `work_kind: refactoring` и
`change_id`: эти поля относятся к самой записи, а не только к файлу решений.
Совпадающие ID и хеши документов в другой работе не переносят разрешение.
Старые USER-записи обычных изменений без этих полей сохраняют прежний смысл
в `sdd/changes`; они не становятся разрешениями рефакторинга при копировании.

## USER-решения и область разрешения

`review/decisions.md` имеет document_type: decisions. USER-запись содержит kind, scope, response (реальный явный ответ), date (quoted ISO с timezone), inputs (манифест исходной версии). Необязательны message (ссылка при наличии), status (active/completed/cancelled), supersedes (список USER-ID).

| kind | scope сверх stage | Применимость |
|---|---|---|
| review_consent | run_id, lenses | Только указанный запуск |
| review_waiver | lenses | Точная версия, стадия и линзы |
| document_approval | — | Точная версия document_review |
| planning_command | work: ограниченный объем | document_review; поручение сохраняется при ожидаемых правках |
| plan_approval | — | Точная версия plan_review |
| finding_disposition | findings: полные ключи | Только перечисленные находки, без автоматического переноса |

У disposition дополнительно action: fix/reject/defer; reject/defer требуют reason, defer — return_at. Выполнение fix храните отдельно в completion: `[{finding, path}]`, path существующего измененного документа относительно изменения. Исторический response не переписывайте. Для отмены пометьте status: cancelled и сохраните свидетельство отмены в читаемом тексте/ссылке; для замены новая датированная запись указывает supersedes. Механика не доказывает авторство пользователя: при продолжении агент сверяет последнюю явную волю, объем и происхождение правок.

Согласование и waiver действуют только при совпадении версии. Поручение исправить или спланировать сохраняется при ожидаемых правках до завершения, отмены/замены или изменения объема. Необъясненные внешние правки требуют уточнить затронутую область. Разрешение работы не обходит отдельные условия готовности и не охватывает новые находки.
