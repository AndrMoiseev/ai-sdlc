# SDD Sync

Перенеси реализованные требования из изменения в текущие спецификации (baseline),
затем сохрани весь каталог изменения в архиве. Текущие спецификации описывают
действующее поведение; архив хранит историю решения и проверки.

## Порядок работы

1. Прочитай [условия запуска](references/runtime-setup.md) и
   [процесс переноса](references/workflow.md). Выбери изменение и проверь завершение.
2. Перед подготовкой правок прочитай [правила слияния](references/merge.md) и
   [формат текущих спецификаций](../sdd-shared/references/current-specifications.md).
   Сначала составь полный список правок всех capabilities.
3. Выполни выбранный режим по процессу переноса. Обычный вызов включает
   синхронизацию и архив. «Покажи, что изменится» означает только просмотр;
   «синхронизируй без архива» оставляет изменение активным.
4. Сообщи изменённые требования, результаты проверок и точный путь архива либо
   причину, по которой изменение осталось активным.

При конфликте сохрани изменение активным. Архивируй только после проверки всех
его спецификаций; частичный перенос не считается завершением. Уже порученный
перенос и архив не требуют повторного подтверждения каждого файла.

Работа ограничена спецификациями, отчётом переноса и перемещением выбранного
каталога изменения. Код, согласованный план, результаты исполнения и Git-историю
не меняй. Смысл операций основан на [OpenSpec](references/openspec-origin.md),
форматы и пути принадлежат SDD. Примеры запросов: [README](README.md).

При завершении через sdd-apply проверь отдельно финальные результаты запуска
explorer и заключения проверяющего по [процессу переноса](references/workflow.md#2-проверь-завершение).
Успешная команда без подтверждённых критериев не разрешает перенос.
