# Условия запуска

Работай с установленным комплектом `aisdlc-core`. Разрешай ссылки от расположения
этого скилла, а пути документов от явно выбранного корня проекта.

1. Проверь соседний `sdd-shared/api.json`: `api_version` должен быть целым числом 2.
   Нужны его `scripts/check.py`, lock-файл и справочники, указанные ниже. При
   неполной установке останови зависимую операцию и назови недостающий файл.
2. Прочитай [общий формат](../../sdd-shared/references/document-format.md),
   [нормативный формат](../../sdd-shared/references/document-format-normative.md)
   и [общие правила запуска](../../sdd-shared/references/runtime-setup.md).
   Команды Python запускай через `uv run --locked --script` с абсолютными путями.
   Новое окружение в проекте не требуется; кеш uv находится вне пакетов скиллов.
3. Найди `sdd/changes/` выбранного проекта. При его отсутствии сообщи, что
   переносить нечего. Не создавай проект как побочный эффект. Для `openspec/`
   используй установленный процесс OpenSpec, не переименовывай его в SDD.
4. Проверь доступ к активному изменению, текущим спецификациям и будущему архиву.
   Разрешённые цели лежат внутри проекта, вне `.git`, каталогов скиллов и иных
   изменений. Проверь реальные пути, включая symlink/junction. Выход за корень,
   неоднозначная цель или совместная запись другим процессом блокируют перенос.

Для изменения с `execution/state.json` нужен соседний `sdd-apply` и его
[контракт чтения](../../sdd-apply/references/api.md). Для принятой реализации,
выполненной вне sdd-apply, этот runtime не нужен. Не создавай фиктивное исполнение.

Превью ограничено чтением. В обычном режиме `sync.md` внутри изменения служит
сохраняемым отчётом операции. Черновые копии и резервные файлы размещай в отдельном
временном workspace вне исходных и установленных скиллов. Сохраняй их до проверки
переноса; при сбое сообщи их расположение. Не очищай чужие временные данные.
