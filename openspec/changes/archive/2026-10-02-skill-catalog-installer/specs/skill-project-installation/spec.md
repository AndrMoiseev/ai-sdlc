## Purpose

Установка переносит выбранный набор скиллов в проект для Codex и Claude Code, фиксирует его состав и позволяет обновлять его без потери локальных правок и посторонних файлов.

## ADDED Requirements

### Requirement: One-command project installation

The system SHALL предоставлять одну команду подключения набора `all` из публичного каталога в явно определённый проект при наличии документированных инструментов запуска. По умолчанию SHALL устанавливаться оба агента; пользователь SHALL иметь возможность выбрать `codex`, `claude-code` или оба. Пакеты SHALL копироваться целиком в `.agents/skills/<name>/` для Codex и `.claude/skills/<name>/` для Claude Code без обязательных симлинков и глобальной установки.

#### Scenario: Install for both agents
- **WHEN** пользователь подключает `all` в проект без выбора конкретного агента
- **THEN** каждый пакет набора появляется в обеих директориях вместе со своими скриптами, ресурсами, скрытыми файлами пакета и метаданными

#### Scenario: Install for one agent
- **WHEN** пользователь явно выбирает только Codex
- **THEN** система устанавливает набор только в `.agents/skills/` и записывает этот выбор в проектный манифест

### Requirement: Portable project manifest and lock

The system SHALL сохранять `skill-catalog.yaml` с источником каталога, выбранным набором и агентами, а `skill-catalog.lock.json` - с коммитом каталога, полным составом и зависимостями, точными источниками пакетов, контрольными суммами содержимого и относительными путями управляемых файлов по каждой цели установки. Формат файлов SHALL допускать хранение в Git и перенос проекта между машинами без абсолютных локальных путей, временных каталогов и секретов. Повторная установка неизменного состава SHALL NOT менять эти файлы по существу.

#### Scenario: Clone a configured project
- **WHEN** участник клонирует проект с манифестом, lock-файлом и установленными пакетами
- **THEN** пакеты уже находятся в директориях агентов и для доступа к их файлам не требуется повторная установка

#### Scenario: Receipt is malformed or incomplete
- **WHEN** lock-файл повреждён, имеет неподдерживаемую версию либо отсутствует при существующем проектном манифесте
- **THEN** система сообщает ошибку и не трактует проект как новую установку с последней версией каталога

### Requirement: Reproduce locked installation

The system SHALL при повторном `install` использовать lock-файл, не обновляя коммиты каталога и пакетов. Совпадающие установленные пакеты SHALL оставаться неизменными; полностью отсутствующие пакеты SHALL восстанавливаться из точных источников с проверкой контрольных сумм. При недоступном источнике или несовпадении суммы система SHALL завершаться с ошибкой без перехода на другую версию. Если все пакеты уже совпадают, проверка SHALL обходиться без сети. Изменение набора или агентов относительно lock-файла SHALL требовать явного `update`.

#### Scenario: Upstream advanced after installation
- **WHEN** upstream и основная ветка каталога изменились, но пользователь выполняет повторный `install`
- **THEN** установленный состав сохраняет зафиксированные версии

#### Scenario: Restore an absent package
- **WHEN** управляемый каталог пакета полностью отсутствует, а его точный источник доступен
- **THEN** система восстанавливает его в выбранных целях с содержимым, соответствующим lock-файлу

#### Scenario: Upstream is unavailable
- **WHEN** требуется скачать отсутствующий пакет, но зафиксированный источник недоступен
- **THEN** система сообщает ошибку, сохраняет существующее состояние и не скачивает latest вместо него

### Requirement: Explicit catalog update

The system SHALL обновлять состав только по явной команде `update`, разрешая основную ветку каталога в новый точный коммит. Новые записи `all` SHALL добавляться, изменившиеся пакеты SHALL заменяться, а исключённые из выбранного состава управляемые пакеты SHALL удаляться только при отсутствии локальных изменений. Источники сторонних пакетов SHALL определяться новыми записями каталога, без самостоятельного обновления до upstream latest. Новые манифест и lock-файл SHALL отражать только успешно применённое состояние.

#### Scenario: Catalog changes membership and a source pin
- **WHEN** обновление каталога добавило пакет, исключило другой и изменило SHA стороннего источника
- **THEN** `update` применяет эти изменения к выбранным целям и записывает новый состав, оставляя прочие установленные скиллы нетронутыми

#### Scenario: Local changes in a package scheduled for removal
- **WHEN** исключённый из набора управляемый пакет содержит локальную правку
- **THEN** обновление сообщает конфликт и сохраняет пакет вместе с прежним lock-файлом

### Requirement: Preserve local edits and unmanaged content

The system SHALL до записи сравнивать управляемые пакеты с предыдущими контрольными суммами. Добавленные, изменённые и удалённые внутри существующего пакета файлы SHALL считаться локальными изменениями. Любой такой конфликт SHALL останавливать операцию до изменения проекта с указанием путей; автоматическое слияние и принудительная перезапись не требуются. Система SHALL принимать существующий неуправляемый пакет под управление только при точном совпадении с устанавливаемым содержимым. Остальные скиллы, настройки, `AGENTS.md`, `CLAUDE.md` и рабочие документы проекта SHALL оставаться неизменными.

#### Scenario: Edit in only one agent copy
- **WHEN** копия для Codex соответствует lock-файлу, а в копии для Claude Code изменён файл
- **THEN** система сообщает конфликт Claude Code и не обновляет ни одну копию

#### Scenario: A local file was added or deleted
- **WHEN** внутри существующего управляемого пакета добавлен файл либо удалён один из зафиксированных файлов
- **THEN** система сообщает локальное изменение и не затирает его при установке или обновлении

#### Scenario: Existing manual installation matches
- **WHEN** неуправляемый каталог содержит в точности устанавливаемый пакет
- **THEN** система принимает его под управление без изменения содержимого и фиксирует файлы в lock-файле

#### Scenario: Existing manual installation differs
- **WHEN** одноимённая неуправляемая установка отличается хотя бы одним файлом
- **THEN** система сообщает конфликт, не перезаписывает пакет и не присваивает ему статус управляемого

### Requirement: Complete preparation before project changes

The system SHALL подготовить весь необходимый состав, проверить доступность файлов, корректность путей и конфликты до изменения управляемых директорий. Запись SHALL оставаться внутри выбранных директорий проекта. Система SHALL NOT запускать скрипты устанавливаемых скиллов. При обычной ошибке применения система SHALL восстановить предыдущее состояние; если восстановление невозможно, SHALL явно сообщить о незавершённой операции и сохранить данные для восстановления, не объявляя успех.

#### Scenario: One source fails in a multi-package installation
- **WHEN** один пакет подготовлен, а загрузка другого завершилась ошибкой
- **THEN** управляемые директории, манифест и lock-файл проекта остаются прежними

#### Scenario: Destination escapes the project
- **WHEN** имя, путь или существующая ссылка ведут за пределы разрешённой директории установки
- **THEN** система останавливается до записи вне проекта

#### Scenario: Applying staged files fails
- **WHEN** запись второго пакета завершается обрабатываемой ошибкой после изменения первого
- **THEN** система восстанавливает прежние пакеты и учётные файлы либо явно сообщает о невозможности завершить восстановление и сохраняет резервные данные

### Requirement: Read-only local status

The system SHALL предоставлять `status`, который без сети и изменения файлов показывает выбранный набор и агентов, зафиксированный коммит каталога, совпадающие, отсутствующие и локально изменённые управляемые пакеты. Система SHALL различать отсутствие установки и повреждённое описание установки. Статус SHALL NOT заявлять о наличии или отсутствии удалённых обновлений без обращения к источнику.

#### Scenario: Inspect a project offline
- **WHEN** пользователь выполняет `status` без сетевого доступа
- **THEN** система сообщает локальное состояние всех управляемых копий и не меняет проект

#### Scenario: Unconfigured project
- **WHEN** ни манифеста, ни lock-файла нет
- **THEN** `status` сообщает, что каталог к проекту не подключён
