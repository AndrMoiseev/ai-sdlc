## Purpose

Каталог описывает рекомендуемые скиллы, их происхождение, источники и зависимости, чтобы команды могли устанавливать согласованный набор в проекты из одного воспроизводимого состояния.

## ADDED Requirements

### Requirement: Explicit catalog of skill packages

The system SHALL читать версионируемый каталог с уникальным идентификатором каждого скилла, источником полного пакета и списком обязательных зависимостей. Запись SHALL указывать либо путь в репозитории каталога, либо публичный Git-репозиторий, полный SHA коммита и путь внутри него. Идентификатор SHALL совпадать с именем устанавливаемого скилла; неоднозначные имена и конфликты имён без учёта регистра SHALL считаться ошибкой.

#### Scenario: Mix local and third-party sources
- **WHEN** каталог содержит собственный пакет, локальную доработанную копию и внешний пакет с точным коммитом
- **THEN** система определяет независимый источник каждого пакета и не требует копировать внешний пакет в исходники каталога

#### Scenario: Invalid source or duplicate name
- **WHEN** запись внешнего пакета содержит только изменяемую ветку либо несколько записей претендуют на одно имя установки
- **THEN** система сообщает ошибку каталога до изменения проекта

### Requirement: Preserve provenance and unmodified upstream packages

The system SHALL сохранять в каталоге происхождение доработанных пакетов: URL upstream, исходный путь и известный базовый коммит. Если точная база исторической копии неизвестна, система SHALL допускать явное значение «неизвестно», не выдумывая SHA. Эти сведения SHALL отличаться от фактического источника установки. Сторонний пакет as is SHALL устанавливаться без переписывания инструкций, метаданных или имён; зависимости такого пакета SHALL допускаться в каталоге без правки upstream.

#### Scenario: Adapted package has separate identity
- **WHEN** локальный пакет `sdd-skill-conductor` содержит сведения об исходном стороннем пакете
- **THEN** устанавливается локальный `sdd-skill-conductor`, сведения об upstream описывают происхождение и не служат командой скачать оригинал вместо него

#### Scenario: External package has catalog-defined dependency
- **WHEN** для неизменённого стороннего скилла в каталоге указана обязательная зависимость
- **THEN** система добавляет зависимость в состав, сохраняя содержимое исходного пакета неизменным

### Requirement: Named bundles and automatic all bundle

The system SHALL поддерживать выбор набора по имени. Зарезервированный набор `all` SHALL включать все записи выбранного состояния каталога без отдельного перечисления. Другие именованные наборы SHALL задаваться явными списками идентификаторов; поставка первой версии SHALL включать только `all`. Неизвестный набор SHALL вызывать ошибку. Директории скиллов, не зарегистрированные в каталоге, SHALL NOT автоматически добавляться в наборы.

#### Scenario: Catalog entry added
- **WHEN** в следующем коммите каталога появилась новая запись
- **THEN** `all` для нового коммита включает её, а состав `all` из прежнего lock-файла остаётся прежним до явного обновления

#### Scenario: Installed package is not a recommendation
- **WHEN** в `.agents/skills/` репозитория каталога имеется пакет, отсутствующий в каталоге
- **THEN** пакет не включается в `all`

#### Scenario: Named subset with dependencies
- **WHEN** каталог содержит именованный набор из части скиллов
- **THEN** система выбирает только его записи и их обязательные зависимости

### Requirement: Resolve required skill dependencies

The system SHALL вычислять транзитивное замыкание обязательных зависимостей по идентификаторам каталога, устанавливая каждую запись один раз. Все зависимости SHALL присутствовать в том же состоянии каталога. Отсутствующие ссылки и циклы SHALL вызывать диагностическую ошибку до изменения проекта. Идентификатору SHALL соответствовать одна версия; разрешение диапазонов версий не требуется.

#### Scenario: Shared transitive dependency
- **WHEN** два скилла зависят от одного помощника, который зависит от ещё одного пакета
- **THEN** оба помощника входят в итоговый состав по одному разу

#### Scenario: Missing dependency or dependency cycle
- **WHEN** зависимость не зарегистрирована либо обнаружена цепочка, возвращающаяся к исходному скиллу
- **THEN** система сообщает отсутствующий идентификатор либо цепочку цикла и не устанавливает частичный состав

### Requirement: Main branch is the accepted source

The system SHALL при первоначальном подключении разрешать основную ветку репозитория каталога в один точный коммит и читать каталог и локальные пакеты из этого коммита. При восстановлении SHALL использовать зафиксированный коммит. Система SHALL считать записи основной ветки принятыми к использованию и SHALL NOT требовать статусы допуска, отдельный релиз или результаты поведенческих проверок и проверок совместимости с агентами. Проверки корректности данных и доступности файлов остаются обязательными.

#### Scenario: Main branch moves during installation
- **WHEN** основная ветка изменилась после выбора коммита первоначальной установки
- **THEN** все локальные пакеты и сам каталог устанавливаемого состава берутся из первоначально выбранного коммита

#### Scenario: Package has no certification metadata
- **WHEN** корректная запись основной ветки не содержит статуса готовности или матрицы совместимости
- **THEN** отсутствие таких метаданных не препятствует установке
