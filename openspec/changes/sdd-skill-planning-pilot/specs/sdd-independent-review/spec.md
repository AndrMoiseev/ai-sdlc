## Purpose

Обеспечивает независимые ревью, явные решения пользователя по находкам и контроль актуальности отчетов по документам изменения.

Статус: черновик. Блоки Scenario здесь оформляют критерии по формату текущего OpenSpec; будущий скилл не требует отдельной сущности сценария.

## ADDED Requirements

### Requirement: REQ-lens-selection

Ревью specs/design MUST включать встроенную линзу консистентности и полноты и дополнительные линзы только из sdd/arch-lenses/index.md.

#### Scenario: AC-default-lens
- **WHEN** индекс отсутствует или пуст
- **THEN** предлагается только встроенная линза

#### Scenario: AC-indexed-lenses
- **WHEN** индекс перечисляет дополнительные линзы
- **THEN** они включены в предложение ревью, посторонние файлы каталога не подключаются; неразрешенная ссылка является ошибкой

#### Scenario: AC-lens-skip
- **WHEN** агент считает обязательную линзу неприменимой
- **THEN** пропуск возможен только по явному решению пользователя

### Requirement: REQ-isolated-review

После согласия пользователя агент MUST запускать нового субагента с чистым контекстом на каждую линзу; для плана MUST использовать одного отдельного рецензента. Рецензенты MUST только читать материалы и возвращать отчеты.

#### Scenario: AC-clean-context
- **WHEN** начинается запуск
- **THEN** рецензент получает задание, документы и источники без переписки и рассуждений автора, не редактирует файлы; основной агент сохраняет отчет

#### Scenario: AC-plan-review-scope
- **WHEN** запускается рецензент плана
- **THEN** он проверяет полноту, зависимости, порядок, возможность параллельной работы, соответствие specs/design и тесты

#### Scenario: AC-missing-subagents
- **WHEN** среда не позволяет запустить независимого субагента
- **THEN** агент сообщает ограничение и не выдает самопроверку за независимое ревью

### Requirement: REQ-review-freshness

Отчет MUST фиксировать список и хеши proposal.md, specs/**/spec.md и design.md, а для плана также tasks.md. Хеши MUST проверяться до запуска и после получения отчетов.

#### Scenario: AC-changed-input
- **WHEN** вход изменился, удален или добавился документ комплекта
- **THEN** отчет сохранен, но не считается актуальным полным ревью; редакционные правки также учитываются

#### Scenario: AC-excluded-input
- **WHEN** изменился state.md, review/ либо внешний источник
- **THEN** автоматическое устаревание не происходит; версии исходников, проектной документации и инструкций линз не отслеживаются

#### Scenario: AC-added-lens
- **WHEN** индекс содержит новую обязательную линзу
- **THEN** покрытие ревью считается неполным независимо от хешей документов

#### Scenario: AC-all-lenses-stale
- **WHEN** изменился любой документ общего комплекта стадии
- **THEN** отчеты всех линз этой стадии устарели; агент перечисляет все устаревшие и недостающие ревью, независимо от тематической связи правки с линзой

#### Scenario: AC-partial-repeat
- **WHEN** пользователь выбирает повторный запуск только части устаревших или недостающих ревью
- **THEN** для продолжения без остальных требуется отдельное явное разрешение на их пропуск для текущей версии; частичный запуск сам по себе не является таким разрешением

### Requirement: REQ-review-history

Каждый запуск MUST иметь отдельный исходный отчет в review/ с ограничениями проверки и результатом: завершено без находок, завершено с находками или не завершено.

#### Scenario: AC-incomplete-review
- **WHEN** субагент завершился с ошибкой или недоступный источник не позволяет сделать вывод
- **THEN** отчет фиксирует незавершенность и причину; предлагается повторный запуск, продолжение без проверки требует решения пользователя

#### Scenario: AC-preserved-reports
- **WHEN** получен повторный отчет
- **THEN** старый отчет сохраняется, решения и результаты исправлений записываются отдельно со ссылками на находки

### Requirement: REQ-finding-decisions

Находка MUST иметь стабильный ID, источник, затронутый элемент, проблему, последствия, предложение исправления и оценку блокирования. Агент MUST сводить дубли и расхождения, сохраняя ссылки на первичные находки.

FIND-ID MUST быть уникален внутри исходного отчета. Полная ссылка MUST включать `<run-id>/<lens-id>/<FIND-ID>`. Повторное обнаружение MUST создавать новую запись; связь `related_to` в сводке MUST NOT автоматически переносить решение пользователя на новую находку.

#### Scenario: AC-finding-local-identity
- **WHEN** два рецензента или два запуска используют одинаковый смысловой FIND-ID
- **THEN** записи различаются полными ссылками, исходные отчеты не переименовываются; повтор ID внутри одного отчета является ошибкой

#### Scenario: AC-recurring-finding
- **WHEN** повторный запуск обнаружил ранее рассмотренную проблему
- **THEN** новая находка связывается с предыдущей через related_to в сводке; пользователь явно принимает решение по новой находке, а прежние ссылки и решения сохраняются

#### Scenario: AC-user-disposition
- **WHEN** пользователь рассматривает сводку
- **THEN** он выбирает исправить, отклонить с обоснованием или отложить с этапом возврата; решения могут относиться к группе; молчание не означает согласия

#### Scenario: AC-repeat-review
- **WHEN** согласованные исправления изменили проверяемые документы
- **THEN** агент показывает устаревшие проверки и предлагает повторное ревью, не запускает его без согласия
