## 2. Форматы каталога и вычисление состава

- [ ] 2.1 Описать и реализовать схему `catalog.yaml`: источники `catalog`/`git`, происхождение, полный SHA внешнего источника, имена, пути и обязательные зависимости. Проверка: тесты смешанных источников, неизвестной исторической базы upstream, повторных ключей, конфликтов имён, неподдерживаемой схемы и некорректных путей; отсутствие статусов допуска не является ошибкой.
- [ ] 2.2 Реализовать набор `all`, именованные списки и транзитивное замыкание. Проверка: тесты автоматического включения новой записи, исключения незарегистрированных директорий, неизвестного набора, общей зависимости, отсутствующей ссылки и цикла; результат стабильно отсортирован и не содержит дублей.
- [ ] 2.3 Реализовать разрешение основной ветки в единый снимок и получение Git-пакетов по SHA. Проверка: локальные Git-фикстуры с движущейся веткой подтверждают согласованность каталога и его пакетов; отдельный тест подтверждает, что внешняя версия берётся из записи каталога, а не из latest.

## 3. Пакеты и проектный учёт

- [ ] 3.1 Реализовать извлечение полного дерева пакета и детерминированный digest по исходным байтам. Проверка: tests/references/scripts/assets, скрытые файлы, лицензии и собственные lock-файлы сохраняются; неотслеживаемые кэши не попадают в пакет; симлинки/gitlinks и отсутствующий `SKILL.md` дают понятную ошибку; скрипты скилла не исполняются.
- [ ] 3.2 Реализовать чтение и запись `skill-catalog.yaml` и `skill-catalog.lock.json` с учётом обеих целей. Проверка: round-trip и перенос между разными абсолютными корнями сохраняют состав, суммы и относительные пути; повреждённый/неполный учёт не превращается в новую установку; одинаковые данные дают одинаковые файлы.
- [ ] 3.3 Реализовать сравнение установленного состояния с lock и построение общего плана изменений до записи. Проверка: обнаруживаются правка только одной копии, добавление/удаление файла, отсутствующий пакет, совпадающая и отличающаяся ручные установки; посторонние пакеты не включаются в план.

## 4. Применение изменений и команды CLI

- [ ] 4.1 Реализовать staging, проверку границ назначения, защиту от конкурентного применения и резервное восстановление затронутых файлов. Проверка: ошибка загрузки второго источника не меняет проект; внедрённая ошибка записи вызывает откат; невозможный откат оставляет понятную диагностику и резервные данные; путь через ссылку за пределы проекта не изменяется.
- [ ] 4.2 Реализовать первоначальный `install all` с `--catalog`, `--project`, выбором агентов и обеими целями по умолчанию. Проверка: команды в чистом проекте создают полный состав и согласованные учётные файлы; настройки агентов, `AGENTS.md`, `CLAUDE.md` и посторонние скиллы неизменны.
- [ ] 4.3 Реализовать повторный `install` по lock. Проверка: совпадающий проект остаётся побайтово неизменным и не требует сети; полностью отсутствующая копия восстанавливается по SHA; неверный digest, недоступный источник или локальная правка дают отказ без перехода на latest; изменение выбора требует `update`.
- [ ] 4.4 Реализовать явный `update`, включая добавление, замену, удаление управляемых пакетов и применение нового выбора набора/агентов. Проверка: тесты перехода между двумя коммитами каталога сохраняют сторонние установки и блокируют удаление изменённого пакета; неизменный внешний pin не обновляется самостоятельно.
- [ ] 4.5 Реализовать read-only `status`, справку и exit codes. Проверка: без сети различаются отсутствие подключения, совпадение, отсутствующие копии, локальные изменения, повреждённый lock и незавершённое применение; команда не записывает файлы и не заявляет об удалённых обновлениях.

## 6. Сквозная проверка и готовность к использованию

- [ ] 6.1 В отдельных временных проектах последовательно выполнить install, Git commit/clone, offline status/install, изменить каталог, выполнить update и восстановить отсутствующий пакет. Использовать собственный `sdd-doc`, доработанный `sdd-skill-conductor`, неизменённый публичный пакет с закреплённым SHA и явно тестовую зависимость. Проверка: зафиксированы URL/SHA источников; контрольные суммы, полный состав файлов, обе цели и lock совпадают с ожидаемыми снимками; правка одной копии блокирует обновление без изменения проекта. Это проверка установщика, а не поведения скиллов.
- [ ] 6.2 Прогнать пакетные тесты на Windows и доступной Unix-среде, включая пробелы/Unicode в путях, переводы строк и признак executable. Проверка: сохранены результаты и команды; недоступная среда явно обозначена как непроверенная, без объявления межплатформенной проверки завершённой.
- [ ] 6.3 Проверить готовность поставки: запуск одной командой через uv/uvx из checkout и Git-источника с подкаталогом, публичная доступность источников, в diff только предусмотренные файлы, нет кэшей и результатов тестов внутри устанавливаемых пакетов. Проверка: команда с закреплением версии CLI проверена в чистом окружении с документированными uv/Git; итоговый отчёт сопоставляет сценарии обеих спецификаций с тестами и фиксирует SHA и ограничения. Отдельно отметить, если удалённый запуск нового CLI требует последующего попадания его коммита в публичный репозиторий; никаких автоматических коммитов, push или публикации.
